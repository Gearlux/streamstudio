- **One ComfyUI Workflow Document PER GRAPH, And The Save Mirror Is PATH-KEYED (2026-08-31, user report: "echo sends me to the efficientvit graph … this is unacceptable"):** `open_graph.js` persists an opened graph file as `workflows/taidal/<workspace>/<stem>.json` — the earlier path collapsed to the workspace name alone, so EVERY graph of a workspace shared one document and opening a second graph re-used the first's canvas. The save mirror keeps a sessionStorage MAP (`taidal.graphFiles`: workflow document → graph file) and mirrors a `/userdata/workflows/…` POST ONLY when its route matches a mapped document, to THAT file — the earlier single remembered target would have mirrored WHICHEVER workflow saved (echo and efficientvit open together = one canvas silently written into the other's file). **The `<stem>.app.json` DERIVATIVE maps to the same file (2026-09-01):** a graph whose `extra` carries `linearMode: true` opens in ComfyUI's APP view (frontend ≥1.49 — the workflow presents as a FORM of the widgets `extra.linearData.inputs` names, `[[nodeId, widgetName], …]`, plus `outputs: [nodeId]`; a taidal template may SHIP that declaration so a parameter is tuned without ever seeing nodes — the signal workspace's sink template exposes its writer's `output_dir` this way), and an app-view save posts to `<stem>.app.json` — unmapped, the typed value never reached the graph file and the workspace ran with the stale one (measured live). Pins: `tests/test_open_graph_mirror.py`.
- **A Wired-`Any` Op Param NAMED After A Strict Slot Role Carries The ROLE Socket, And Its Wire Exports As A Whole-Node `!ref:` (2026-08-29):** comma socket types connect on set INTERSECTION, so an op's bare-`Any` `model` param typed with the generic value union (`RECORDSTREAM_SOURCE,RECORDSTREAM_OBJECT`) can never accept a model node's `RECORDSTREAM_OBJECT:model:torch,RECORDSTREAM_OBJECT:model` — disjoint sets, wire refused while drawing. `_build_op_node` therefore types a wired-`Any` param through `_STRICT_SLOT_ROLES` + `_object_socket` when its NAME is a slot role (`model`, `loss`, `sink`, …) and keeps `VALUE_INPUT_TYPE` otherwise (pinned both ways). On EXPORT, `_resolve_widget_link` hands the consumer a WHOLE-NODE `!ref:` for (a) a VALUE node's trailing `object` output — the live instance, so a `random=True` producer draws per call instead of folding to one frozen literal — and (b) an OBJECT node's `instance` output (slot 0) — a model into a predict op's `model` param hoists as an eager top-level `!class:` entry; the `lazy` output (slot 1) still drops with a note, because the hoist is eager and silently building what the author marked deferred would change when the cost is paid. The cone compiler's omission notes now surface in the whole-graph export's comment block (`_skipped_comment_block(fold_notes=…)`) — a canvas that LOOKS wired must not export an op silently missing a param. Pins: `tests/test_value_node_wiring.py`.
- **What it is:** a ComfyUI custom-node extension. Every node is AUTO-GENERATED at import from `@configurable` callables discovered through the `confluid.configurables` entry-point group — there is no bespoke server, frontend, or executor of our own.
- **Module map:** `cli.py` (ComfyUI clone / custom-node seed / launch), `custom_nodes.py` (the bundled node-URL declaration), `__init__.py` (one-shot discovery + the `/taidal/*` aiohttp routes + the default-node prune), `bridge.py` (the generator — introspection → node classes, `_map_type` / `_coerce_kwargs`, palette paths, socket vocabulary), `nodes.py` (hand-written adapter glue + the in-canvas viewers), `export.py` (canvas DAG → `flow:` graph compiler — the only export format), `graphio.py` (whole-graph `workflow.json` ↔ Confluid YAML, both directions), `config.default.yaml` (shipped palette keep-list), `web/*.js` (frontend extensions — dynamic sockets, pickers, viewers, menus).
- **Seven node shapes** (stamped as `TAIDAL_NODE_KIND`, one builder each): `source` / `op` / `model` / `value` / `object` / `runnable` / `generic`. `create_comfy_node` dispatches in the order runnable → model → op → source → object-or-sink → value → generic; the order is load-bearing (a model and an op both take a record, a sink and an object member share a builder). The `source` step accepts a class by TAG as well as by probe — `category="engine"` (`Stream` / `FlowGraph` / `JointStream`) builds a source node whatever its `__iter__` says (see the tag-beats-probe mandate below).
- **Socket vocabulary:** `RECORDSTREAM_SOURCE` (a `Stream`), `RECORDSTREAM_RECORD` (one record), `RECORDSTREAM_OP`, `RECORDSTREAM_OBJECT[:role]`, `RECORDSTREAM_RUNNABLE`, `RECORDSTREAM_ARRAY`, `RECORDSTREAM_VALUE`, `HF_DATASET`. ComfyUI matches sockets by string EQUALITY (with ONE extension both halves support: a comma-separated type is compatible when the two sets INTERSECT — `comfy_execution.validation.validate_node_input`, and litegraph's `isValidConnection` splits on `,` too), which is why the role is baked into the string. An object socket may additionally CLAIM an engine as a third segment inside such a union — `RECORDSTREAM_OBJECT:loss:torch,RECORDSTREAM_OBJECT:loss` — see the framework mandate below. Nothing else is narrowed.
- **A launcher names the canvas's FILE (user design 2026-08-24 — the push/auto-send designs are DELETED):** `web/open_graph.js` (`Taidal.OpenGraph`) reads `?taidal_graph=<server-side path>`: a `.json` path is a NATIVE workflow file — served raw by `GET /taidal/read_graph?path=` (404 when missing = not created yet), loaded onto the canvas unless the canvas already shows it, remembered (sessionStorage `taidal.sourceFile`), and every native workflow save (`POST /userdata/workflows/…`, observed by a SYNCHRONOUS pass-through wrap of `api.fetchApi` — an async wrap defers by a microtask and flips frontend races, measured) is MIRRORED verbatim into it via `POST /taidal/write_graph {path, workflow}`; a `.yaml` path converts through `/taidal/import_yaml` `{path}` as before. The TIMING rules in that file are all measured, and each one broke a live boot before it was learned — do not "simplify" them away: (a) `setup()` must NOT await the load (the app awaits every extension's `setup()` before its own initial load — awaiting there deadlocks the splash), so the work runs detached with a catch; (b) the reliable gate is OBSERVABLE STATE — wait until the app is interactive (app + graph + a mounted `canvas#graph-canvas`) and the graph fingerprint has been quiet for 1.5 s, then load and VERIFY the canvas holds the content, retrying only on mismatch (a late restore can replace one load). Pins: `tests/test_init_discovery.py::test_import_yaml_route_accepts_a_server_side_path` / `test_read_and_write_graph_routes_own_the_source_file`; the frontend half is exercised live (the viewer's *set source…* button).

- **`web/*.js` Is CODE And MUST Be In `package-data` (2026-08-24):** ComfyUI loads the frontend extension from the directory named by `WEB_DIRECTORY` in `streamstudio/__init__.py`, so every file under `streamstudio/web/` is shipped code, not a development asset. `web/` has NO `__init__.py`, so `packages.find` skips it and `[tool.setuptools.package-data]` is the ONLY thing that puts it in a wheel. The failure mode is silent and total, and it is invisible in development: an editable install reads the checkout directly, so the palette, the pickers and the viewers all work — while a BUILT wheel held 13 entries and none of the 30 JS files (measured 2026-08-24), installing a package that imports, registers every node, and has no UI. The same applies to `config.default.yaml` (the palette fallback `bridge` reads at runtime) and `py.typed`, which was declared for months without the file existing. Pins: `tests/test_packaging.py::test_every_web_asset_is_shipped` (stated as "every file under `web/` is covered by a pattern", so adding a `.css` or an icon beside the scripts fails there instead of shipping a half-populated directory) and `::test_the_declared_package_data_files_exist`. **The sdist needs `MANIFEST.in` for anything nothing else references** — setuptools builds it from what is DECLARED (`readme` -> README.md, `license-files` -> LICENSE, `packages.find` + `package-data` -> the package), so `CHANGELOG.md` was silently absent from both projects' sdists until 2026-08-25. Pin: `tests/test_packaging.py::test_the_changelog_is_shipped_in_the_sdist`.
- **Anything Imported At MODULE Scope Is A DECLARED Dependency (2026-08-24):** `nodes.py` imports `torch` and `numpy` at module scope and `__init__.py` imports `nodes`, so both are hard requirements of `import streamstudio` — yet neither was declared, and the workspace has both installed for other reasons, so every local check passed while `pip install streamstudio` produced a package that raised `ModuleNotFoundError: No module named 'torch'` on import (measured in a clean venv). A GUARDED import is the opposite case and stays undeclared on purpose: every `waivefront` use in this package sits inside `try/except ImportError` with a working fallback, which is what makes the domain node set a PLUGIN rather than a requirement. The rule is therefore mechanical, not a judgement call — a top-level `import X` outside a `try:` / `if TYPE_CHECKING:` / function body means `X` belongs in `[project] dependencies`. Pin: `tests/test_packaging.py::test_module_scope_imports_are_declared_dependencies` (walks the package with `ast`, counting only direct children of the module body).
- **No Requirement May Carry A URL (2026-08-24):** PyPI validates every `Requires-Dist` and REFUSES any whose requirement has a URL — `warehouse/forklift/metadata.py`: "Can't have direct dependency: {req}". Extras are validated identically, so an extra nobody installs still blocks the whole upload, and the rejection arrives only AFTER the artifact is built, checked and sent. A domain extra used to restate `torchsig @ git+https://github.com/TorchDSP/torchsig.git` (to satisfy uv's transitive-URL rule) and that alone made this package unpublishable. An unpublished dependency therefore cannot be reached by an extra at all: name it plainly and say in the README where to get it. Pin: `tests/test_packaging.py::test_no_requirement_is_a_direct_url`.
- **An Extra May Exist Undocumented — Never Print An Install Command That Cannot Succeed (2026-08-26):** the `[waivefront]` extra STAYS in `pyproject.toml`. It is the honest declaration of an optional dependency, it costs nothing where the package is already present, and an extra a project does NOT declare is silently ignored by installers anyway (measured: `Would make no changes`) — so declaring it is not what breaks. What breaks is ADVERTISING it: the distribution is on no index, so the README's fenced, copyable `pip install --pre "streamstudio[waivefront]"` resolved to *"your requirements are unsatisfiable"* and installed NOTHING, streamstudio included (measured 2026-08-26 during the 0.1.0a1 release check). A reader who runs a documented command and gets a hard resolver error blames their own environment. So the README states the NEED generically — install the domain package by whatever means you have, the palette is built from what the environment holds — and prints no command for it. Prose may name the extra; a fenced install line may not. Pin: `tests/test_packaging.py::test_the_readme_does_not_advertise_an_unresolvable_extra`.
- **The Extra Is Why CI Needs Credentials (2026-08-26, know the cost):** the CI generator walks EVERY extras group to build its internal-dependency clone list, so `[waivefront]` pulls waivefront AND its transitive closure (`annotaide`, `matrainer`, `torpaido`) into the generated `ci.yml` as `git+https://github.com/Gearlux/...` pre-installs, each guarded by a `create-github-app-token` step. Keeping the extra therefore means the workflow REQUIRES `GEARLUX_APP_ID` / `GEARLUX_APP_PRIVATE_KEY` — with no secrets set, every run dies at *"Input required and not supplied: app-id"* before a single test. That is a deliberate trade, not an oversight: the fix is to add the secrets, never to drop the extra to dodge them. Do not "simplify" CI by deleting the extra.
- **The Package Speaks Its OWN Name, And Scanning Is DEBUG (2026-08-26):** the module-scan line was `logger.info("ComfyStream: Scanning module … for nodes...")` — wrong on both counts. `ComfyStream` predates BOTH renames (`fluxstudio` -> `streamstudio` above), and it survived in 31 places: the four `bridge.py` scan/skip lines and one `console.log` in every one of the 27 `web/*.js` extensions, so it greeted the user on import AND in the browser console. The LEVEL was a mandate violation — a per-entry-point scan line is per-iteration diagnostics, which the workspace reserves `trace`/`debug` for. Measured on a clean install: `import streamstudio` printed 26 lines, 24 of them the scan line; now 2. It was not only noise — the first log call is what makes loggair create its file sink, so importing the package (or running `streamstudio --help`) wrote a `logs/` directory into the current folder. Pins: `tests/test_packaging.py::test_no_superseded_project_name_in_shipped_code`, `tests/test_init_discovery.py::test_module_scan_is_logged_at_debug_not_info`.
- **The CLI Is a liquifai App — `streamstudio.cli:app`, `strict_flags=True` (2026-08-26, migrated FROM argparse):** the argparse CLI defined every flag on the TOP-LEVEL parser only, so each subparser was empty: `streamstudio restart -h` printed nothing but `-h`, and `streamstudio restart --port 9000` was REFUSED (*unrecognized arguments*) while `streamstudio --port 9000 restart` worked. Per-command help now comes from the command function's own docstring + signature, so it cannot go stale, and a flag is accepted on either side of the command name. **What the migration COST, all user-visible — do not "restore" any of it:** (a) a boolean pair is liquifai's polarity suffix, `--install-` / `--install+`, NOT `--no-install` — the workspace ruling is one spelling per intent, and `--x-` already expresses false; (b) a repeatable flag is a LIST literal, `--custom-node=[urlA,urlB]`, not a repeated flag; (c) a short is DECLARED, not an alias list — `run`/`restart` carry `short={"p": "port", "b": "background"}` and the export/import commands `{"o": "output"}`, so `-b` and `-p` work while the old `--bg` does not (a stale one fails loudly rather than launching in the foreground); `-c`/`-s`/`-d`/`-h` are liquifai globals and MUST NOT be claimed here; (d) **`--config` was RENAMED to `--palette-config`** — liquifai reserves `--config` for the app's own configuration file, so the palette keep-list flag had to move or be swallowed (`STREAMSTUDIO_CONFIG` is unchanged); `import`'s positional was renamed `document` for the same reason. **Two traps this migration hit, both fixed IN liquifai** (see its AGENTS): `-h` was not a declared help spelling, so it fell through as an unrecognised token and `streamstudio restart -h` RESTARTED the server; and a flag naming no parameter was silently ignored. `strict_flags=True` is set here precisely because every command takes PLAIN values — there is no config document to fall through to, so a flag that reaches nothing reached nothing at all. **`argcomplete` is GONE** (dependency and hook): completion now comes from the `liquifai.apps` entry point (`streamstudio = "streamstudio.cli:app"`) — registration moves to that family in `aisland/setup.sh`. **`default_comfy_dir()` is a FUNCTION, not a constant:** a signature default is evaluated at IMPORT, which froze the path against `Path.home()`; argparse built its parser inside `main()` and never had the problem. Commands default it to `None` and resolve in the body. liquifai binds CLI values VERBATIM as strings, so the command body coerces (`Path(...)`, `int(...)`) — and `_as_list` normalises a repeatable option, because splatting the single-value string form iterates it CHARACTER BY CHARACTER. Pins: `tests/test_cli.py`, `tests/test_cli_port.py`, `tests/test_cli_restart.py`.
- **Reuse RecordStream + Waivefront Surfaces:** StreamStudio is the GUI layer over RecordStream pipelines — it auto-generates ComfyUI nodes from callables already exposed by RecordStream / Waivefront (and HuggingFace `datasets`). Every node it surfaces MUST come from existing passive discovery — NEVER hand-define a StreamStudio-only node, op, or visualizer. If an op or visualization is missing, add it to recordstream / waivefront, not here. RF-domain ops stay in waivefront behind the optional `[waivefront]` extra so the core install stays lean — they appear in StreamStudio when that package is INSTALLED, by any means, because discovery reads the environment (the extra is declared but NOT documented as an install command — see "An Extra May Exist Undocumented" below).
- **ComfyUI Extension, Not a Standalone Server:** StreamStudio is a ComfyUI custom node, not its own web service. The CLI (`streamstudio.cli:main`) clones ComfyUI to `~/.streamstudio/ComfyUI` on first run, symlinks this package into `ComfyUI/custom_nodes/streamstudio`, and launches `python main.py` under the active interpreter (so ComfyUI runs in the same `.venv` whose metadata discovery reads). Do NOT reintroduce a bespoke FastAPI server, React/xyflow frontend, or in-house executor — extend behaviour through ComfyUI nodes and the `web/` extension directory instead. There is no FastAPI server, `SteppingExecutor`, in-house Confluid-YAML graph serialization, type→visualizer registry, or React frontend; any `streamstudio/api/`, `frontend/dist/`, or `frontend/node_modules/` left on disk are orphans, not live surface.
- **Launcher Seeds Custom Nodes (entry-point-declared incl. bundled ComfyUI-Manager; extras via flag/env; idempotent; never blocks launch):** On EVERY `run` (not just the first clone), `cli._install_custom_nodes` clones custom-node repos into `ComfyUI/custom_nodes/` and pip-installs each repo's `requirements.txt` into the ACTIVE interpreter (the same env ComfyUI runs in). URLs come from THREE tiers, deduped in order **declared → env → flags**: (1) the **`streamstudio.custom_nodes` entry-point group** (`cli.CUSTOM_NODES_ENTRY_POINT_GROUP`, read by `_declared_custom_nodes`) — ANY installed package declares "generally available" nodes by pointing an entry point at a git-URL `str` or iterable of them; **streamstudio's own declaration is `streamstudio/custom_nodes.py:CUSTOM_NODE_URLS`** (wired in `pyproject.toml`), which bundles **ComfyUI-Manager** (`COMFYUI_MANAGER_URL`, canonical `Comfy-Org/ComfyUI-Manager`, re-exported by `cli`). To bundle another node with streamstudio, append to that tuple — tuple edits need NO reinstall (loaded at launch), but adding/renaming an entry point DOES (installed `*.dist-info` metadata — same staleness gotcha as `confluid.configurables`; pinned by `test_streamstudio_declares_manager_via_entry_point`, which fails on a stale editable). A broken declaration (load error / wrong type / non-str item) logs an actionable `warning` and is skipped. `--declared-nodes-` skips the whole tier; `--manager-` filters ONLY the manager URL and ONLY from the declared tier (an explicit env/flag request for it is the stronger signal and still installs). (2) the `STREAMSTUDIO_CUSTOM_NODES` env var (comma-separated git URLs, blanks dropped via `_env_custom_nodes`); (3) the repeatable `--custom-node <git-url>` flag. ComfyUI-Manager is the sanctioned in-GUI way to install/update/remove further nodes, which is why the launcher only SEEDS: a repo whose target directory (`custom_nodes/<url-basename-minus-.git>`, via `_custom_node_dir_name`) already exists is SKIPPED (`debug` log) — never re-cloned, never `git pull`-ed (updates are ComfyUI-Manager's job; don't add auto-update logic here). A clone or pip failure of ONE node logs an actionable `warning` and CONTINUES (both the loop and the launch) — a broken/unreachable custom node must never block the studio; only the ComfyUI clone itself stays fatal (`check=True` uncaught). **ComfyUI's OWN `requirements.txt` is synced on EVERY run too (2026-08-22)** — `pip install -r` right after the clone-or-reuse step (a no-op when satisfied): an existing checkout drifts (ComfyUI-Manager updates it in place; a newer `main.py` imported `comfy_aimdo`, which the venv never received, and ComfyUI died at startup — measured through the annotation workspace's launch button), so "installed once at clone time" was a bug; `--install-` (`BooleanOptionalAction`, default on) skips it for an air-gapped run. Pins: `test_main_syncs_requirements_for_an_existing_checkout`, `test_main_no_install_skips_the_sync`, `test_main_installs_exactly_once_after_a_clone`. Keep these semantics when touching `_run`: the custom-node install runs AFTER the clone-or-reuse + requirements sync and BEFORE the streamstudio symlink, and `--manager`/`--declared-nodes`/`--custom-node` follow the established launcher-flag pattern (top-level argparse flags, like `--default-nodes`). Tests pin the tier hermetically: an autouse fixture fakes `cli.entry_points` to streamstudio's own declaration so ambient venv packages can't leak into call-count assertions. Pins: `tests/test_cli.py` custom-node + entry-point blocks (`test_main_installs_comfyui_manager_by_default`, `test_custom_node_flag_and_env_combine`, `test_streamstudio_declares_manager_via_entry_point`, `test_declared_custom_nodes_*`, `test_main_no_declared_nodes_skips_package_declared_tier`, `test_no_manager_filters_declared_tier_only`, dedup / skip / clone-failure / pip-failure tests).
- **Compiling A Subgraph To An Op Is A COMMAND, Never Automatic (user instruction 2026-08-26, WITHDRAWING the automatic version — do not reinstate it):** the first cut ran on `nodeCreated` / `afterConfigureGraph` / a per-subgraph `onNodeAdded`, so every conversion edited the canvas unasked. Python annotations carry no range info, so widgets are unbounded by design — an op that needs validation does it in its constructor; NEVER reintroduce conditional bounds keyed off the *default's* sign (the original bug: only a negative DEFAULT widened `min`, so `noise_power_db: float = 0.0` could not accept -120). **A REAL range is declared upstream with a PEP-593 mark** — `Annotated[float, Interval(ge=…, le=…)]` (`annotated_types`, pydantic's own vocabulary, a declared direct dep): `_interval_bounds` reads `Interval`/`Ge`/`Le`/`Gt`/`Lt` (unwrapping `Optional`) and narrows the widget `min`/`max` in `_widget_for` AND on both `__lo`/`__hi` endpoints of a marked `Tuple` range; partial marks (`Ge` only) narrow one side. `_map_type` UNWRAPS `Annotated` before its string heuristics (the repr of `Interval` contains the substring `int` and would mis-classify). A nullable `Optional[Annotated[float, Interval]] = None` keeps the blank-STRING convention (the mark then feeds only the navigaitor schema, which `confluid.to_pydantic` carries for free). Marks are UX/schema metadata — the constructor stays the validation authority; declare them on the op signature in recordstream/waivefront (see waivefront.torchsig's `DbPower`/`DbSnr`/`Probability`/`WattRange`/`DbRange` aliases), NEVER hand-set per-node bounds in the bridge. - **`Optional[X] = None` Params Must Coerce to the CONSTRUCTOR Default, Never a Forced Widget Value (the "StreamStudio Trainer ≠ the YAML Trainer" footgun):** ComfyUI widgets can't be `None`, so a param that defaults to `None` (the library resolves it to ITS own default — Lightning's `precision`→32-bit, `enable_progress_bar`/`enable_checkpointing`→True) MUST render a "blank = use default" widget that `_coerce_kwargs` turns into omit/None — NOT a forced concrete widget value that silently overrides the constructor. The widget per type: a nullable **numeric** (`Optional[int/float]=None`) → blank `STRING` (`""`→None, filled→cast); a nullable **bool** (`Optional[bool]=None`) → a 3-state combo `["", "true", "false"]` defaulting blank (`""`→None, `true`/`false`→bool — NOT a checkbox forced to `False`); a nullable **`Literal`** (`Optional[Literal[...]]=None`) → the Literal combo with a leading blank entry (see the Literal mandate below); a nullable **str** → `STRING` `""`→None. The bridge already does this for numerics/Literals/str; bool was the gap (a `False` checkbox disabled the progress bar / checkpointing on an imported eval). A param with a **concrete** default keeps it (a real `bool=False` stays a checkbox; `int=1000` keeps 1000). The symptom of getting this wrong: the same config runs under `matrainer` (flow omits the param → library default) but fails or behaves differently in StreamStudio (the widget injected a wrong value — e.g. `precision=64`→float64-on-MPS crash, or `enable_progress_bar=False`). **CONNECTABLE nullable numerics:** the blank-`STRING` widget for an `Optional[int/float]=None` param ALSO carries `taidal_widget="NULLABLE_NUMERIC"` + `taidal_numeric="FLOAT"|"INT"`, and **`web/nullable_numeric_socket.js`** retypes the socket ComfyUI's "Convert to input" creates from STRING to that numeric type — so a numeric output (a Math result, another op's `@output`) can wire INTO the param (the export compilers then turn that wire into a `ConfigureOp` — see the canvas-compiler mandate). The widget STAYS blank-STRING, so the `""`→None / stamped-metadata-fallback semantics are unchanged; only the *converted* socket's type is fixed (a no-op when the node has no such param / on a different ComfyUI build). **The JS retype only makes the wire DRAW — the BACKEND `INPUT_TYPES` is still STRING, so ComfyUI's `validate_inputs` would reject the FLOAT/INT→STRING link at Queue ("Return type mismatch between linked nodes" — it surfaced only when the wired node entered an executed output's validation cone, e.g. a *Preview as text*, not a sibling *Preview Image*).** So `_node_class` ALSO gives any node with a NULLABLE_NUMERIC param a `VALIDATE_INPUTS(cls, input_types)` classmethod (`bridge._validate_inputs_with_nullable_numerics`): declaring an `input_types` param makes ComfyUI SKIP its built-in type check and defer to us, and we ACCEPT a FLOAT/INT wire into a NULLABLE_NUMERIC param while reusing ComfyUI's OWN `validate_node_input` (lazy-imported from `comfy_execution.validation`) for every other socket — no divergence, no loss of the type net. At execution the float arrives and `_coerce_kwargs` passes it through. BOTH halves (JS draw + VALIDATE_INPUTS accept) are required. The str-capable `Optional[Union[float,int,str]]=None` params (`Threshold.low_level` — 2026-07-26) map to STRING above and are NOT tagged — they keep the `'{meta}'` expression path. - **Closed `Literal[...]` → Combo Dropdown (enumerate from the annotation, never restate):** A constructor param typed as a closed `typing.Literal[...]` (the workspace's preferred way to type a fixed, short value set — see the root "Prefer Closed `Literal`s" mandate; e.g. waivefront's `Colormap`) renders as a ComfyUI **combo** whose options ARE the literal's members. `_widget_for` (via `_literal_options`, which also unwraps `Optional[Literal[...]]`) returns `(options_list, {"default": …})` — ComfyUI's enumeration form, where the *list itself* is the "type". This is resolved BEFORE the name-based PATH / scalar heuristics (an explicit enum is the stronger signal), and `_coerce_kwargs` passes a Literal value through verbatim (never the STRING list/int heuristics — a member containing `int`/`list`/`float` must not be cast/split). The default is the param default when it is a member, else the first option. **EXCEPTION — an `Optional[Literal[...]]` that defaults to `None`** (e.g. `pytorch_lightning.Trainer.precision`, `Optional[Literal[64,32,16]…]=None`): the combo can't BE `None`, so `_widget_for` does NOT force the first member — it prepends a blank `""` "(use default)" entry and selects it, and `_coerce_kwargs` OMITS a blank-valued Optional Literal so the constructor's own default applies. Without this, the combo would silently inject the first member (`precision=64` → the model is cast to **float64**, which crashes on MPS: "Cannot convert a MPS Tensor to float64") instead of letting Lightning pick its 32-bit default — the canonical "StreamStudio Trainer differs from the YAML/flow Trainer" footgun. (A param with a concrete in-set default keeps that default; a required Literal with no default still uses the first member.) - **Node Discovery Is a POSITIVE Category Allowlist (`_NODE_CATEGORIES = {op, model, source, engine, sink, value}`):** `register_module_nodes` registers a discovered class as a node ONLY if `getattr(cls, "__confluid_category__", None) in _NODE_CATEGORIES`. These are category-less or deliberately non-canvas-tagged; they're admitted by interface/role/lazy-mark, not by `_NODE_CATEGORIES`.
- **Runnable Nodes — trainers / evaluators / processors RUN on execute (members are wired sockets):** A class implementing the **run interface** (`_is_runnable`: a no-arg `run(self)`) becomes a node via `_build_runnable_node`. It enumerates the runnable's FULL configurable surface from `to_pydantic(cls)` (ctor params AND `__init__`-body slots — the confluid `_post_init_field_specs` scan; read-only properties are skipped) and renders each member as: a **`RECORDSTREAM_SOURCE`** socket (dataset/source members — `_DATASET_MEMBER_PARAMS = {train_set, val_set, test_set, dataset, stream}` + the `source` param; `stream` covers `DatasetProcessor`'s `Stream` input), a **`RECORDSTREAM_OBJECT`** socket (any other non-scalar member — model / loss / optimizer / loaders / lightning / metrics / **sink** — via `_is_scalar_anno`; a model/loss/metric/**sink** member is ROLE-QUALIFIED & TASK-AGNOSTIC per the role-socket mandate below — ANY trainer's `model` slot is `RECORDSTREAM_OBJECT:model`, and `DatasetProcessor.sink` is `RECORDSTREAM_OBJECT:sink`), or a **widget** (scalars: `num_classes` / `max_epochs` / `experiment_name` …, through the shared `_build_config_inputs`; ComfyUI's "convert to input" covers the rare wire). A member that is a ctor param with NO default is a REQUIRED socket (`model` / `train_set`); everything else is OPTIONAL — unwired ⇒ the runnable keeps its baked default ("true optional"). **The node RUNS on execute — it IS the terminal `OUTPUT_NODE` (there is NO separate Run node; the build/run split was collapsed).** `execute` builds the runnable (ctor params → `__init__`, body slots via post-construction `setattr` of the wired members), then calls `streamstudio.nodes.run_runnable` (lazy-imported to dodge the `bridge`↔`nodes` import cycle — it restores autograd, handles interrupts, live-streams stdout) and returns `{"ui": {"text": [log]}, "result": (runnable, *live_outputs)}`. OUTPUTS: slot 0 is the (post-run) runnable on a **`RECORDSTREAM_RUNNABLE`** wire (`kind="runnable"`), then EVERY declared `@output` as a typed socket carrying its LIVE value (see the all-outputs mandate below). A scalar body slot MUST be annotated (`self.x: bool = …`) or it reads as `Any` → an OBJECT socket; real trainers annotate their slots. Member detection is by ANNOTATION/name (never per-class). - **Runnable Nodes Are DUAL-MODE — terminal runner OR built instance for a workflow combinator (`RECORDSTREAM_RUNNABLE` input sockets):** A workflow COMBINATOR (`matrainer.workflow` `Sequence` / `Conditional` / `Switch`) is itself a runnable that HOLDS other runnables, so `_build_runnable_node` renders its runnable-typed members as **`RECORDSTREAM_RUNNABLE` INPUT sockets** (the runnable analogue of an op's `RECORDSTREAM_OP` slot / "Extract as Op"): a SINGLE-runnable member (`_RUNNABLE_PARAMS = {if_true, if_false, default}`) → one socket; a runnable-LIST member (`_RUNNABLE_LIST_PARAMS = {steps}`) → a dynamic `<name>_N` family (seed `steps_0`, grown by **`web/runnable_list.js`**, collected by `_collect_indexed`). Detected by NAME (like `_OP_LIST_PARAMS` / `_SINGLE_OP_PARAMS`), placed BEFORE the dataset/scalar/object checks in `socket_members`, and excluded from the `_build_config_inputs` widget pass. **Because runnable nodes RUN on execute (terminal `OUTPUT_NODE`), a node feeding a combinator's slot would otherwise run TWICE.** So a runnable node is DUAL-MODE, switched by `_runnable_consumed_as_instance(prompt, unique_id)` (reads the hidden **`PROMPT`** — added to the runnable node's `hidden` alongside `UNIQUE_ID` — and returns True iff this node's slot-0 `RECORDSTREAM_RUNNABLE` output is wired into ANOTHER node's `RECORDSTREAM_RUNNABLE` input, resolving a dynamic `<prefix>_N` slot back to its `<prefix>_0` seed type): **consumed ⇒ build the runnable and hand over the constructed-but-UN-RUN instance** (no `run_runnable`, `@output`s emit `None`) so the combinator runs the SELECTED branch; **not consumed ⇒ terminal, run on execute** (the unchanged default — a missing/None prompt is treated as terminal, so older ComfyUI and streamstudio's own tests are unaffected). The combinator (also an `OUTPUT_NODE`, downstream) collects the wired branch instances (single members pass through; lists via `_collect_indexed`) into its ctor and `run_runnable`s ITSELF — restoring autograd (combinators declare `__needs_autograd__` since they may wrap a trainer) and forwarding its progress callback to the running branch (`matrainer.workflow` owns both — see its AGENTS). - **Object Member Nodes Have TWO Outputs (`instance` + `class`):** A runnable's member classes become `RECORDSTREAM_OBJECT` producers via `_build_object_node` (`kind="object"`): config widgets → **two** `RECORDSTREAM_OBJECT` outputs, `instance` (the flowed, live object built right here via `confluid.flow`) and **`class`** (the configured-but-deferred class — a `PartialClass` value; the port is named `class` as the user-facing "the configured class, not yet built", NOT `lazy`). A runnable slot accepts either (`flow` is idempotent on a live instance): wire **`instance`** for a fully-configured standalone object; wire **`class`** when a value is only known at `run()` (`torch.optim.*.params` / `DataLoader.dataset`, or a model's dataset-derived `num_classes`) so the runnable flows it with the runtime kwarg. (graphio's whole-graph export keys eager `!class:Foo()` / deferred `!lazy:Foo` off the WIRED output slot — `instance`=slot 0, `class`=slot 1 — NOT the port label.) A member is detected as `role∈{model,loss,metric,logger}` OR confluid **`lazy`** (`marks(cls).lazy`, set by `@configurable(lazy=True)` / `register(..., lazy=True)`). A `lazy` member SKIPS the runtime-injected required params (`torch.optim.*.params`, `DataLoader.dataset`) so only the configurable knobs (lr / batch_size) are widgets; because those params are missing by design, its `instance` output is `None` (logged at `debug`, NOT a warning — that's expected) and only `class` is usable. Task `role="dataset"` classes are routed to `_build_source_node` (datasets are Sources, not objects). The select runtime members (`torch.optim.Adam`/`AdamW`/`SGD`, `DataLoader`, `pytorch_lightning.Trainer`) are `register(..., lazy=True, group=…)`-ed in **`matrainer.lightning.configurables`** (entry-pointed; re-exported via `__all__`) — **deliberately with NO `category`** (only a presentation-only `group`), so they're StreamStudio object nodes via the `lazy` mark WITHOUT leaking into navigaitor's category-driven form-spec slot pickers (which would then offer the raw `params`-taking optimizer instead of navigaitor's curated infra config). - **Object Sockets Are ROLE-QUALIFIED & TASK-AGNOSTIC; the Retag Node Is the Escape Hatch:** ComfyUI connects sockets only on string EQUALITY, so object-member sockets are **role-qualified** — `RECORDSTREAM_OBJECT:<role>` (`bridge._object_socket`), where `<role>` ∈ `{model, loss, metric, sink}` (the value-set `bridge._QUALIFIED_OBJECT_ROLES`). **TASK is deliberately NOT on the socket** — a classification model and a segmentation model both produce `RECORDSTREAM_OBJECT:model` and dock into ANY trainer's `model` slot. Task survives only as GUIDANCE (navigaitor slot ranking + the palette folder/label). The role still guards KIND: a loss (`RECORDSTREAM_OBJECT:loss`) can't dock into a model slot. An object node's output role comes from `bridge._object_socket_for_class` = the explicit `@configurable(role=…)` tag, ELSE inferred from the Python type (`_role_for_class` — a duck-typed MRO scan: `Metric→metric`, `Optimizer→optimizer`, `DataLoader→loader`, `Logger→logger`; model vs loss are BOTH `nn.Module` so only the tag disambiguates them). A runnable's object SLOT role comes from `bridge._STRICT_SLOT_ROLES` (`model→model` / `loss_fn→loss` / `*metrics→metric` / `sink→sink`, mirroring navigaitor's `PARAM_NAME_TO_ROLE` — streamstudio MUST NOT import navigaitor; the convention is small and replicated) and a trainer `@output` (`trained_model`) via the keyword-scanning `_infer_member_role`. A `category="sink"` class has no `role=` tag, so `_role_for_class` maps it to a synthetic `"sink"` role (checked FIRST) so its object output qualifies symmetrically with the `DatasetProcessor.sink` slot. The object-NODE output side and the runnable-SLOT input side MUST agree on which roles qualify (both gated on `_QUALIFIED_OBJECT_ROLES`) — a one-sided qualifier silently refuses an otherwise-valid wire (the original "can't connect a logger" footgun). **Scope:** model/loss/metric/sink object members. Datasets (and `DatasetProcessor.stream`) stay generic `RECORDSTREAM_SOURCE`. **Role-less members (optimizer / loader / lightning / logger) stay bare `RECORDSTREAM_OBJECT`** — no kind to enforce; they interchange among themselves (acceptable). The role qualifier is now joined by an ENGINE claim — see the framework mandate above; `loss` was added to `_STRICT_SLOT_ROLES` alongside `loss_fn` in the same change, because the Keras classifier names its slot `loss` and without it that slot rendered BARE while every Keras loss node output `…:loss`, so no Keras loss could be wired into it at all. The **Retag node** (`nodes.py:RetagObjectNode`, `Taidal_Retag`) is the deliberate, visible bypass: a wildcard (`AnyType("*")`) input accepts any object; the `target_role` combo (from the registry's `list_roles()`) re-stamps `__confluid_role__` PER-INSTANCE (never the class) and `web/retag.js` retypes the OUTPUT socket to the chosen `RECORDSTREAM_OBJECT:<role>` (or `*` for `(keep)`); `target_task` re-stamps only the guidance tag (no socket effect). graphio whole-graph export does NOT round-trip Retag nodes (no `TAIDAL_CALLABLE_PATH`, like the other canvas-only adapters — skipped-with-comment per the export-skip mandate; the flow export still raises `UnsupportedTopologyError` on them); it's a canvas convenience, hand-written YAML controls types directly. `_is_socket_type`/`_base_socket_type` (base-aware) keep graphio's socket-vs-widget split working under the qualified strings. - **Object Sockets Also CLAIM Their ENGINE — exclusion requires TWO claims (2026-07-31):** an object socket carries the class's `framework` as a THIRD segment, inside a comma UNION that also lists the bare role: `RECORDSTREAM_OBJECT:loss:torch,RECORDSTREAM_OBJECT:loss` (`bridge._object_socket(role, framework)`). - **`run_runnable` Restores Autograd for `TorchRunner`s (ComfyUI runs under `inference_mode`):** `streamstudio.nodes.run_runnable(runnable, unique_id)` is the shared runner each generated runnable node's `execute` calls (the node IS the `OUTPUT_NODE`). ComfyUI evaluates the whole graph under `torch.inference_mode()` (`execution.py`), which is fatal for **gradient-based training**: model params (model nodes are lazy → the backbone is built *inside* `run()`), forward activations, and the loss all become inference tensors with no autograd graph, so `loss.backward()` dies with *"element 0 of tensors does not require grad and does not have a grad_fn"*. So `run_runnable` re-enables normal autograd (`with torch.inference_mode(False), torch.enable_grad():`) ONLY for a runnable that declares itself a **`matrainer.TorchRunner`** (duck-typed `__needs_autograd__` flag — no hard `recordstream` import). Inference-only runnables (`LightningEvaluator`, `DatasetProcessor`) leave the flag unset and run as-is under ComfyUI's inference mode. This is why model nodes being **lazy** matters: the backbone is constructed inside the grad-restored `run()`, not earlier in the object node's `execute` (which still runs under `inference_mode`). - **`run_runnable` Is Interruptible (worker thread + injected `KeyboardInterrupt`):** ComfyUI only polls its interrupt flag BETWEEN nodes, but `run_runnable` wraps ONE blocking `.run()` call that can run for minutes/hours — so the interrupt button would otherwise be ignored until the sweep finished. It therefore executes the runnable on a **daemon worker thread** and polls `_processing_interrupted()` (a lazy, guarded `comfy.model_management.processing_interrupted()` — `False` when comfy is absent, so streamstudio's own tests/dev runs are unaffected) from the calling thread every 0.1 s; when the flag goes high it injects a `KeyboardInterrupt` into the worker via CPython's `PyThreadState_SetAsyncExc` (`_raise_interrupt_in_thread`) and re-raises ComfyUI's `InterruptProcessingException` for a clean stop (no traceback, UI reset). PyTorch Lightning catches `KeyboardInterrupt` for a graceful shutdown; `DatasetProcessor` / Stream iteration loops simply unwind. **Grad/inference mode is thread-local**, so the worker does NOT inherit the `torch.inference_mode()` ComfyUI wraps graph execution in — `run()` captures `torch.is_inference_mode_enabled()` on the calling thread and the worker re-establishes the correct context itself (grad-restored for `__needs_autograd__` runnables, `inference_mode()` re-entered for inference-only runnables). The injection lands at a Python statement boundary (between batches / records), so a single long-running C kernel is not interruptible — an accepted limitation. This keeps ALL ComfyUI/interrupt knowledge in streamstudio; matrainer/recordstream are untouched (per matrainer's `TorchRunner` mandate). Pins: `tests/test_nodes.py::test_run_runnable_interrupt_*`, `test_run_runnable_grad_context_is_active_inside_worker_thread`.

- **Container Values Round-Trip On The Wire — Input Side Too (`_coerce_kwargs` JSON-decode):** A container `@output` (a `Tuple`/`Dict`) rides a `STRING` socket json.dumps-encoded (the `@output` mandate above). The INPUT-side complement lives in `_coerce_kwargs`: a STRING value arriving on a `Dict[...]`-annotated param is `json.loads`-decoded back to a dict — and, when that fails, RETRIED with `ast.literal_eval` so a hand-typed Python dict LITERAL works too (`{0:'BG',1:'5GNR'}` — int keys + single quotes — is natural to type for a `Dict[int, str]` like `raidar.YoloSink.class_names` but is INVALID JSON; `ast.literal_eval` is safe, literals only; a value that is neither stays raw) — and a `Tuple[str, ...]`-annotated param (NOT a range `Tuple[float,float]`/`Tuple[int,int]`, which use `__lo`/`__hi` widgets, nor a variable-length `Tuple[int,...]`, which stays a RANGE pair — hence the `not int/not float` guard) is decoded from a JSON `[...]` array, a Python TUPLE LITERAL (`(`-prefixed → `ast.literal_eval`), OR a hand-typed comma string into a tuple. **The tuple-literal branch is LOAD-BEARING, not cosmetic:** the widget DEFAULT of an empty `Tuple[str, ...]` param renders as the repr `"()"`, and a comma-split of `"()"` yields `("()",)` — a one-element tuple of the literal string `()`, which is **TRUTHY**. That silently broke the `ImpairmentsChain` tx/rx config: the chain resolves `self.tx_disabled or metadata["impairments_tx_disabled"]`, so a `tx_disabled` left at its `()` default coerced to `("()",)` OVERRODE the metadata config stamped by `ImpairmentsTxConfig`/`ImpairmentsRxConfig` — the whole config mechanism did nothing. `ast.literal_eval("()")` → `()` (falsy → reads the metadata); it also makes the docstring-documented `("IQImbalanceOp", "QuantizeOp")` form round-trip (a non-literal `(`-string falls through to the comma-split). This is what lets a value node's `disabled`/`probability_overrides` output wire into another node's `Tuple`/`Dict` input (e.g. `ImpairmentsChain.tx_disabled`) and round-trip as a real container, not the literal JSON string. **A COMPOUND container — a LIST whose elements are themselves tuples/pairs (or a Union of those), e.g. a bridged Config op's `keys: str | list[str | tuple[str, str]]` rename map (a bare key = src==dst, a `(src, dst)` pair renames)** — is the generic case the flat `Tuple`/`List` branches CAN'T reconstruct (a list OF tuples). It gets its OWN branch, gated on the annotation SHAPE — **`"list" AND "tuple"` in the annotation, no `int`/`float`** (disjoint from a flat `Tuple[str, ...]`, which has "tuple" but no "list", and a flat `List[str]`, which has "list" but no "tuple") — placed BEFORE the flat-`Tuple` branch. It accepts EITHER a Python/JSON literal (`[("a","b"), "c"]` / `[["a","b"], "c"]` — `ast.literal_eval` first, then `json.loads`; a JSON inner list is normalised back to a `tuple` so a pair stays a pair) OR a friendly comma list with `src:dst` renames (`"snr_db, noise_power_db:nf"` → `["snr_db", ("noise_power_db", "nf")]` — split on `,`, then each item on `:`; a bare item stays a string, an item with `:` becomes a pair; also the fallback for a malformed literal). This is the GENERIC mechanism for any list-of-pairs/compound param — keyed off the annotation shape, NEVER a class name; do NOT refactor an upstream class into two comma-list params to dodge it (the decoder is shared by node `execute` AND both exporters via `_coerce_kwargs`, so one fix makes the param configurable on-canvas AND round-trip to YAML). The decode branches sit BEFORE the `List`/`Sequence` comma-split (kept for flat `List[str]` params) and after the Literal/blank handling. - **Source vs Dataset (a `source` is a canvas node; a task `dataset` is not):** A `category="source"` is a task-agnostic Record producer (`HuggingFaceSource`, `RFUAVSource`, `SigMFSource`) — the head of a RecordStream pipeline, and exactly what a canvas needs to Walk/Extract/visualize. - **Item Types Are SOCKET Types, and the `<Item> Type` Family Is GENERATED (user design 2026-08-26):** every registered `recordstream` item type gets a socket `RECORDSTREAM_ITEM_<NAME>` (`bridge.item_socket_type`, derived — never a listed table), an output on *Extract from Record* carrying the item VERBATIM (`item_<name>`, distinct from the `IMAGE`/`MASK` natives, which are normalized/colormapped for viewers), and a generated passthrough node `<Item> Type` that takes the item on its own socket and re-emits it. ComfyUI connects on socket-type EQUALITY, which is the whole point: a graph that wires an entry through `Image Type` STATES that the entry is an Image, a boundary fed by it inherits the type, and a wrong wire is refused while you draw rather than at run time. **The family is built AFTER node discovery** (`nodes.build_item_type_nodes()`, called from `__init__` once the entry-point scan has run) — item types are registered BY that scan, so building at import time carried only the record engine's five and silently missed every domain one (a signal package's `Signal`/`Spectrogram`/`Regions`/…).
