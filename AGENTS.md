# FluxStudio Mandates

- **Reuse SampleFlux + Waivefront Surfaces:** FluxStudio is the GUI layer over SampleFlux pipelines — it auto-generates ComfyUI nodes from callables already exposed by SampleFlux / Waivefront (and HuggingFace `datasets`). Every node it surfaces MUST come from existing passive discovery — NEVER hand-define a FluxStudio-only node, op, or visualizer. If an op or visualization is missing, add it to sampleflux / waivefront, not here. RF-domain ops stay in waivefront behind the optional `[waivefront]` extra so the core install stays lean — they appear in FluxStudio only when that extra is installed.
- **ComfyUI Extension, Not a Standalone Server:** FluxStudio is a ComfyUI custom node, not its own web service. The CLI (`fluxstudio.cli:main`) clones ComfyUI to `~/.fluxstudio/ComfyUI` on first run, symlinks this package into `ComfyUI/custom_nodes/fluxstudio`, and launches `python main.py` under the active interpreter (so ComfyUI runs in the same `.venv` whose metadata discovery reads). Do NOT reintroduce a bespoke FastAPI server, React/xyflow frontend, or in-house executor — extend behaviour through ComfyUI nodes and the `web/` extension directory instead. The old FastAPI server (`/api/{ops,visualizers,graph,run,...}`), `SteppingExecutor`, Confluid-YAML graph serialization, type→visualizer registry, and React frontend were removed in the v0.2.0 refactor; any `fluxstudio/api/`, `frontend/dist/`, or `frontend/node_modules/` left on disk are orphans, not live surface.
- **Launcher Seeds Custom Nodes (entry-point-declared incl. bundled ComfyUI-Manager; extras via flag/env; idempotent; never blocks launch):** On EVERY `run` (not just the first clone), `cli._install_custom_nodes` clones custom-node repos into `ComfyUI/custom_nodes/` and pip-installs each repo's `requirements.txt` into the ACTIVE interpreter (the same env ComfyUI runs in). URLs come from THREE tiers, deduped in order **declared → env → flags**: (1) the **`fluxstudio.custom_nodes` entry-point group** (`cli.CUSTOM_NODES_ENTRY_POINT_GROUP`, read by `_declared_custom_nodes`) — ANY installed package declares "generally available" nodes by pointing an entry point at a git-URL `str` or iterable of them; **fluxstudio's own declaration is `fluxstudio/custom_nodes.py:CUSTOM_NODE_URLS`** (wired in `pyproject.toml`), which bundles **ComfyUI-Manager** (`COMFYUI_MANAGER_URL`, canonical `Comfy-Org/ComfyUI-Manager`, re-exported by `cli`). To bundle another node with fluxstudio, append to that tuple — tuple edits need NO reinstall (loaded at launch), but adding/renaming an entry point DOES (installed `*.dist-info` metadata — same staleness gotcha as `confluid.configurables`; pinned by `test_fluxstudio_declares_manager_via_entry_point`, which fails on a stale editable). A broken declaration (load error / wrong type / non-str item) logs an actionable `warning` and is skipped. `--no-declared-nodes` skips the whole tier; `--no-manager` filters ONLY the manager URL and ONLY from the declared tier (an explicit env/flag request for it is the stronger signal and still installs). (2) the `FLUXSTUDIO_CUSTOM_NODES` env var (comma-separated git URLs, blanks dropped via `_env_custom_nodes`); (3) the repeatable `--custom-node <git-url>` flag. ComfyUI-Manager is the sanctioned in-GUI way to install/update/remove further nodes, which is why the launcher only SEEDS: a repo whose target directory (`custom_nodes/<url-basename-minus-.git>`, via `_custom_node_dir_name`) already exists is SKIPPED (`debug` log) — never re-cloned, never `git pull`-ed (updates are ComfyUI-Manager's job; don't add auto-update logic here). A clone or pip failure of ONE node logs an actionable `warning` and CONTINUES (both the loop and the launch) — a broken/unreachable custom node must never block the studio; only the ComfyUI clone itself stays fatal (`check=True` uncaught). Keep these semantics when touching `_run`: the install runs AFTER the clone-or-reuse step and BEFORE the fluxstudio symlink, and `--manager`/`--declared-nodes`/`--custom-node` follow the established launcher-flag pattern (top-level argparse flags, like `--default-nodes`). Tests pin the tier hermetically: an autouse fixture fakes `cli.entry_points` to fluxstudio's own declaration so ambient venv packages can't leak into call-count assertions. Pins: `tests/test_cli.py` custom-node + entry-point blocks (`test_main_installs_comfyui_manager_by_default`, `test_custom_node_flag_and_env_combine`, `test_fluxstudio_declares_manager_via_entry_point`, `test_declared_custom_nodes_*`, `test_main_no_declared_nodes_skips_package_declared_tier`, `test_no_manager_filters_declared_tier_only`, dedup / skip / clone-failure / pip-failure tests).
- **Console Coloring Defaults OFF — TWO `force_no_color()` calls required:** `fluxstudio/__init__.py` calls `loggair.force_no_color()` **twice**: (1) near the TOP, after `import loggair` but before the `fluxstudio.*` submodule imports, so not-yet-configured loggair picks up `NO_COLOR=1` at first `get_logger()`; (2) **again immediately after `_discover_and_register_nodes()`**, because some scanned packages (e.g. `waivefront-helios` / `keysight.ai`) call `logger.remove()` + `logger.add(colorize=True)` at their own import time, undoing the first call — the second `force_no_color()` triggers `reconfigure()` which strips those stray handlers and re-adds loggair's sinks colorless. Both calls are required; removing either breaks the invariant. The first call MUST precede the submodule imports (they legitimately follow a statement; the E402 is silenced via flake8 `per-file-ignores` in TWO configs — `fluxstudio/setup.cfg` keys it as `fluxstudio/__init__.py: E402` for `cd fluxstudio` runs, and the workspace-root `.flake8` keys it as `fluxstudio/fluxstudio/__init__.py: E402` for flake8 invoked from the workspace root; keep BOTH — don't "fix" the E402 by moving the call down, and don't drop either ignore). `NO_COLOR` is the only color env var (no bespoke `LOGGAIR_COLORIZE`); to re-allow colors pre-set `NO_COLOR=` (empty). Pin: `tests/test_loggair_colorize_default.py` (asserts colorless even when loggair was pre-configured WITH colors, AND after helios-style third-party handlers are added).
- **Entry-Point-Driven Node Discovery:** Nodes are discovered EXCLUSIVELY via the `confluid.configurables` entry-point group. `_discover_and_register_nodes()` (`fluxstudio/__init__.py`) enumerates that group and forwards each module to `register_module_nodes` (`fluxstudio/bridge.py`); each module is scanned by `sampleflux.discovery.scan_module` and wrapped into a ComfyUI node class by `create_comfy_node`, keyed by `_node_key` as `Taidal_<package>_<category>[_<group>]_<callable>` (globally unique — see the unique-key mandate below) and displayed under a `Taidal/<Package>/<Category>[/<group>]` palette path (see the palette-path mandate below). A package's ops therefore appear ONLY if its declared entry points are present in the INSTALLED `*.dist-info` metadata.
- **Entry Points Live in Installed Metadata — Reinstall After Changing Them:** Because discovery reads `importlib.metadata.entry_points(...)`, editable installs FREEZE the entry-point metadata at install time. After adding or changing a `[project.entry-points."confluid.configurables"]` declaration in ANY workspace package, you MUST reinstall that editable (`aisland setup`, or plain `uv pip install -e ./<pkg>` in dependency order) or the nodes silently vanish from FluxStudio with no error — discovery just yields fewer entries. NEVER use `--reinstall` / `--force-reinstall` to force it: that re-resolves internal deps (confluid, loggair, …) from PyPI, where they don't exist, and fails. The canonical symptom of stale metadata is an empty or near-empty `Taidal/…` palette even though the source is current; confirm with `python -c "import importlib.metadata as m; print(len(list(m.entry_points(group='confluid.configurables'))))"`.
- **Discovery Degrades Gracefully (debug, not warning):** A module that fails to import or scan during discovery MUST be skipped at `logger.debug` level so one package's missing optional dependency never empties the whole node palette. Do NOT promote these skips to `warning`/`info`.
- **Type → ComfyUI Widget Mapping:** Node inputs and outputs are derived from each callable's signature by `_map_type` in `fluxstudio/bridge.py` — int/float/str/bool (incl. `Optional`/`Union` of these, unwrapped via string scan so numerics still get real INT/FLOAT/BOOLEAN widgets rather than a STRING the constructor chokes on) map to ComfyUI scalar widgets; `sampleflux.sample.Sample` maps to the `SAMPLEFLUX_SAMPLE` socket; `datasets.Dataset` to `HF_DATASET`; path-like params (`pathlib.Path`, or names containing path/dir/root/folder) to a directory-picker widget backed by `web/directory_chooser.js` and the `/taidal/choose_directory` ComfyUI route. New supported types MUST extend `TYPE_MAP` / `_map_type` rather than special-casing individual nodes. **A `Union` with a list arm AND a bare `str`/`int` arm rides a STRING widget but must NOT be comma-split by `_coerce_kwargs` (the "default Trainer graph won't even build" footgun):** `_map_type` already returns `STRING` for `list[int] | str | int` (the int+str rule), and the widget default is rendered VERBATIM (`devices`→`"auto"`). But `_coerce_kwargs`'s `List`/`Sequence` comma-split fires on ANY annotation whose string contains `"list"` — so it silently turned the STRING default `"auto"` into `["auto"]`, a "sequence of str" Lightning rejects (`pytorch_lightning.Trainer.devices`, the canonical case — a freshly-created Trainer node failed to build its live `instance` AND failed at run with *"Device IDs … you passed a sequence of str"*). The split is now GUARDED by `_has_bare_scalar_union_arm` (inspect the Union ARGS for a top-level `str`/`int` member — `str(List[str])` itself contains the substring `"str"`, so a string scan is wrong): such a param passes the STRING through verbatim (the library parses `"auto"` / the comma-string `"1,2,3"` itself), while a pure `List[str]` / `Optional[List[str]]` (no bare scalar arm) still comma-splits. This is the coercion-side complement to the `_map_type` int+str→STRING rule. Pins: `tests/test_bridge.py::test_has_bare_scalar_union_arm_detects_str_int_arms` / `::test_coerce_kwargs_union_with_str_arm_passes_string_through_not_split` / `::test_real_lightning_trainer_devices_default_builds`.
- **`_map_type` Classifies STRUCTURALLY, Never by Substring Scan (resolve → `typing` introspection):** Type→widget mapping inspects the RESOLVED type via `get_origin`/`get_args`/identity — NOT `"int" in str(annotation)`. A stringized / forward-ref annotation (`from __future__ import annotations`) is resolved FIRST: `_build_config_inputs` calls `_resolved_param_hints` (`get_type_hints(owner, include_extras=True)`) against the owner's namespace and `param.replace(annotation=…)`s the real type before any classification; `_map_type`'s own `_resolve_annotation` is the best-effort fallback for a direct string (evals it in a typing-only `_ANNOTATION_NS`). Classification order: `Sample`/`datasets.Dataset`/`pathlib.Path` by `_type_mentions` (identity in the type tree — catches `Optional[Sample]`/`Iterator[Sample]`) → the path-NAME affordance (the ONE deliberate name-based rule: a param named `*dir*`/`*path*`/`*root*`/`*folder*` → directory picker, a UX choice not a type inference) → `_range_tuple_type` → `_is_nonrange_container` → a structural scalar-`Union`-arm analysis (`bool`/`int`+`str`→STRING/`int`/`float`, each arm `_strip_annotated`-unwrapped so `Optional[Annotated[float, Interval]]`→FLOAT). The **RANGE pair** (`__lo`/`__hi`) is ONLY a top-level **2-element** (`Tuple[int,int]`/`Tuple[float,float]`) or **variadic** (`Tuple[int,...]`) numeric tuple — never a `List` OF tuples (`OverlayBoxes.boxes`) nor a fixed != 2 tuple (a 3-tuple `Color`); the old `"tuple" in str(anno)` scan wrongly ranged all of them (`boxes__lo`/`boxes__hi`). `_is_nonrange_container`/`_has_container_origin` route a NON-range container to STRING (standard container origins `list`/`tuple`/`set`/`frozenset`/`dict` + abc `Sequence`/`Set`/`Mapping`, NOT every `Iterable` — so `datasets.Dataset` falls through to `HF_DATASET`; `str`/`bytes` are scalars), BEFORE the scalar branches so a container whose ELEMENT is numeric (`List[int]`, `Dict[str,float]`) doesn't collapse to one scalar widget. **Coercion complement (`_coerce_kwargs`):** a non-range numeric tuple (`Color`, a STRING widget) decodes `"(255,0,0)"`/`"255,0,0"`/`"[255,0,0]"` → `(255,0,0)` via `_fixed_numeric_tuple_cast` (fixed numeric tuple, arity != 2, no `Ellipsis` — `Max.axis: int|Tuple[int,...]` stays a nullable INT, not `(0,)`) BEFORE the bare-`int` cast that would `int("(255,0,0)")`-crash; the `List` branch ast/json-parses a `[...]` literal (the `[]` default + box lists) before comma-splitting. **Add a type mapping by extending these STRUCTURAL helpers, NEVER a substring check.** Pins: `tests/test_bridge.py::test_map_type_range_only_for_two_element_or_variadic_numeric_tuple` / `::test_map_type_non_range_container_is_string_not_scalar` / `::test_coerce_kwargs_decodes_fixed_numeric_tuple` / `::test_coerce_kwargs_list_branch_parses_literal_then_comma_splits` / `::test_optional_int_or_variadic_tuple_is_nullable_numeric_not_range` / `::test_optional_interval_marked_param_stays_nullable_string_and_coerces`.
- **A Type That Can't Be a Widget Rides a Wired `SAMPLEFLUX_VALUE` Socket + the Value Node (`_needs_value_socket`):** Some types can't be sensibly typed into one widget — a **nested container** (a container whose element is itself a container: `OverlayBoxes.boxes: List[Tuple[int,int,int,int]]`, a `List[List[...]]`, a `Dict[str, List[...]]`). `_build_config_inputs` detects them STRUCTURALLY (`_needs_value_socket` → `_is_nested_container`: a container origin with a container ELEMENT — `Dict` nests on its VALUE) and renders the param as an **OPTIONAL `SAMPLEFLUX_VALUE` input socket** (`bridge.VALUE_TYPE`) instead of a STRING widget — unwired keeps the constructor default (`boxes=[]`); the wired Python value passes through `_coerce_kwargs` unchanged (it is not a string). A FLAT container (`List[str]`/`List[int]` comma-typed) or a fixed numeric tuple (`Color` typed `255,0,0`) STAYS a widget — the boundary is "element is itself a container". The producer is the hand-written **Value** node (`nodes.ValueNode`, `Taidal_Value`): a multiline STRING `value` widget parsed by `parse_value_literal` (`ast.literal_eval` then `json.loads`; empty → `None`) into a real Python object on a `SAMPLEFLUX_VALUE` output — type `[(20,10,80,50),(200,100,300,150)]` and wire it in. It is GLUE (a literal parser, like `MathNode`), so it lives in `nodes.py`. **Export:** a `Taidal_Value` wire FOLDS inline as its parsed literal — `export._resolve_widget_link` handles `_VALUE_NODE_CLASS_TYPE` (like a primitive; lazy-imports `parse_value_literal` to keep export↔nodes acyclic). YAML has no tuple type, so a `(…)` box round-trips as a `[list]` (functionally identical — a box unpacks the same). v1 limit: the graphio whole-graph export + the YAML→workflow IMPORT don't yet reconstruct a Value node (tracked in TASKS) — the ops-export persists it. Pins: `tests/test_bridge.py::test_needs_value_socket_only_for_nested_containers` / `::test_is_nested_container_shape_rule` / `::test_nested_container_param_is_value_socket_not_widget`, `tests/test_nodes.py::test_value_node_parses_literals_and_is_registered`, `tests/test_export.py::test_value_node_folds_literal_into_consumer_kwarg` / `::test_value_node_round_trips_through_export_ops_yaml`.
- **Numeric Widgets ALWAYS Carry Full-Range `min`/`max` (frontend clamps to `[0, 2048]` otherwise):** When a node spec omits `min`/`max`, the ComfyUI frontend defaults them to `min ?? 0` and `max ?? 2048` — silently making negative values UNENTERABLE (every dB knob: `noise_power_db = -120`, gain offsets, SNR floors) and blocking large ones (`sample_rate = 1e7`, frequencies in Hz, `propagation_speed ≈ 3e8`). `DEFAULT_WIDGET_CONFIG` therefore bakes explicit wide bounds into EVERY `INT` (`±2**53`) and `FLOAT` (`±1e308`) widget, and the `RANGE_FLOAT`/`RANGE_INT` `__lo`/`__hi` pair inherits them. Python annotations carry no range info, so widgets are unbounded by design — an op that needs validation does it in its constructor; NEVER reintroduce conditional bounds keyed off the *default's* sign (the original bug: only a negative DEFAULT widened `min`, so `noise_power_db: float = 0.0` could not accept -120). **A REAL range is declared upstream with a PEP-593 mark** — `Annotated[float, Interval(ge=…, le=…)]` (`annotated_types`, pydantic's own vocabulary, a declared direct dep): `_interval_bounds` reads `Interval`/`Ge`/`Le`/`Gt`/`Lt` (unwrapping `Optional`) and narrows the widget `min`/`max` in `_widget_for` AND on both `__lo`/`__hi` endpoints of a marked `Tuple` range; partial marks (`Ge` only) narrow one side. `_map_type` UNWRAPS `Annotated` before its string heuristics (the repr of `Interval` contains the substring `int` and would mis-classify). A nullable `Optional[Annotated[float, Interval]] = None` keeps the blank-STRING convention (the mark then feeds only the navigaitor schema, which `confluid.to_pydantic` carries for free). Marks are UX/schema metadata — the constructor stays the validation authority; declare them on the op signature in sampleflux/waivefront (see waivefront.torchsig's `DbPower`/`DbSnr`/`Probability`/`WattRange`/`DbRange` aliases), NEVER hand-set per-node bounds in the bridge. Pins: `tests/test_bridge.py::test_numeric_widgets_always_carry_full_range_bounds` / `::test_range_widgets_carry_full_range_bounds` / `::test_interval_bounds_extraction` / `::test_interval_marked_widgets_get_bounds` / `::test_interval_marked_tuple_range_bounds_both_endpoints` / `::test_map_type_unwraps_annotated`.
- **`Optional[X] = None` Params Must Coerce to the CONSTRUCTOR Default, Never a Forced Widget Value (the "FluxStudio Trainer ≠ the YAML Trainer" footgun):** ComfyUI widgets can't be `None`, so a param that defaults to `None` (the library resolves it to ITS own default — Lightning's `precision`→32-bit, `enable_progress_bar`/`enable_checkpointing`→True) MUST render a "blank = use default" widget that `_coerce_kwargs` turns into omit/None — NOT a forced concrete widget value that silently overrides the constructor. The widget per type: a nullable **numeric** (`Optional[int/float]=None`) → blank `STRING` (`""`→None, filled→cast); a nullable **bool** (`Optional[bool]=None`) → a 3-state combo `["", "true", "false"]` defaulting blank (`""`→None, `true`/`false`→bool — NOT a checkbox forced to `False`); a nullable **`Literal`** (`Optional[Literal[...]]=None`) → the Literal combo with a leading blank entry (see the Literal mandate below); a nullable **str** → `STRING` `""`→None. The bridge already does this for numerics/Literals/str; bool was the gap (a `False` checkbox disabled the progress bar / checkpointing on an imported eval). A param with a **concrete** default keeps it (a real `bool=False` stays a checkbox; `int=1000` keeps 1000). The symptom of getting this wrong: the same config runs under `marainer` (flow omits the param → library default) but fails or behaves differently in FluxStudio (the widget injected a wrong value — e.g. `precision=64`→float64-on-MPS crash, or `enable_progress_bar=False`). **CONNECTABLE nullable numerics:** the blank-`STRING` widget for an `Optional[int/float]=None` param ALSO carries `taidal_widget="NULLABLE_NUMERIC"` + `taidal_numeric="FLOAT"|"INT"`, and **`web/nullable_numeric_socket.js`** retypes the socket ComfyUI's "Convert to input" creates from STRING to that numeric type — so a numeric output (a Math result, another op's `@output`) can wire INTO the param (the export compilers then turn that wire into a `ConfigureOp` — see the ops-export mandate). The widget STAYS blank-STRING, so the `""`→None / stamped-metadata-fallback semantics are unchanged; only the *converted* socket's type is fixed (a no-op when the node has no such param / on a different ComfyUI build). **The JS retype only makes the wire DRAW — the BACKEND `INPUT_TYPES` is still STRING, so ComfyUI's `validate_inputs` would reject the FLOAT/INT→STRING link at Queue ("Return type mismatch between linked nodes" — it surfaced only when the wired node entered an executed output's validation cone, e.g. a *Preview as text*, not a sibling *Preview Image*).** So `_node_class` ALSO gives any node with a NULLABLE_NUMERIC param a `VALIDATE_INPUTS(cls, input_types)` classmethod (`bridge._validate_inputs_with_nullable_numerics`): declaring an `input_types` param makes ComfyUI SKIP its built-in type check and defer to us, and we ACCEPT a FLOAT/INT wire into a NULLABLE_NUMERIC param while reusing ComfyUI's OWN `validate_node_input` (lazy-imported from `comfy_execution.validation`) for every other socket — no divergence, no loss of the type net. At execution the float arrives and `_coerce_kwargs` passes it through. BOTH halves (JS draw + VALIDATE_INPUTS accept) are required. The str-capable `Optional[Union[float,int,str]]=None` params (`ThresholdOp.low_level`) map to STRING above and are NOT tagged — they keep the `'{meta}'` expression path. Pins: `tests/test_bridge.py::test_optional_bool_none_default_is_tristate_combo` / `::test_real_lightning_trainer_enable_flags_default_blank` / `::test_optional_literal_none_default_offers_blank_use_default` / `::test_nullable_numeric_becomes_blank_string_widget` / `::test_nullable_numeric_validate_inputs_accepts_numeric_wire` / `::test_node_without_nullable_numeric_has_no_validate_inputs`.
- **Closed `Literal[...]` → Combo Dropdown (enumerate from the annotation, never restate):** A constructor param typed as a closed `typing.Literal[...]` (the workspace's preferred way to type a fixed, short value set — see the root "Prefer Closed `Literal`s" mandate; e.g. waivefront's `Colormap`) renders as a ComfyUI **combo** whose options ARE the literal's members. `_widget_for` (via `_literal_options`, which also unwraps `Optional[Literal[...]]`) returns `(options_list, {"default": …})` — ComfyUI's enumeration form, where the *list itself* is the "type". This is resolved BEFORE the name-based PATH / scalar heuristics (an explicit enum is the stronger signal), and `_coerce_kwargs` passes a Literal value through verbatim (never the STRING list/int heuristics — a member containing `int`/`list`/`float` must not be cast/split). The default is the param default when it is a member, else the first option. **EXCEPTION — an `Optional[Literal[...]]` that defaults to `None`** (e.g. `pytorch_lightning.Trainer.precision`, `Optional[Literal[64,32,16]…]=None`): the combo can't BE `None`, so `_widget_for` does NOT force the first member — it prepends a blank `""` "(use default)" entry and selects it, and `_coerce_kwargs` OMITS a blank-valued Optional Literal so the constructor's own default applies. Without this, the combo would silently inject the first member (`precision=64` → the model is cast to **float64**, which crashes on MPS: "Cannot convert a MPS Tensor to float64") instead of letting Lightning pick its 32-bit default — the canonical "FluxStudio Trainer differs from the YAML/flow Trainer" footgun. (A param with a concrete in-set default keeps that default; a required Literal with no default still uses the first member.) Pins: `tests/test_bridge.py::test_optional_literal_none_default_offers_blank_use_default` / `::test_real_lightning_trainer_precision_defaults_to_blank`. The SAME annotation drives navigaitor's form-spec (pydantic renders `Literal` as a JSON-Schema `enum` automatically) — one `Literal` upstream, both GUIs get a picker. To add a choice, edit the upstream `Literal` (e.g. `waivefront.visualizers.Colormap`), NEVER hard-code a parallel option list in the bridge or a node.
- **HuggingFace Dataset-ID Field (free text + cached picker, NOT a directory):** The dataset-identifier param of a HuggingFace dataset source is a *name* (a Hub repo id like `kitofrank/RFUAV`, or optionally a local imagefolder path) — NOT a filesystem directory, even though `sampleflux.sources.HuggingFaceSource` names it `path`. `_widget_for` (gated by `_is_hf_dataset_id_param`) emits it as a free-text `STRING` tagged `taidal_widget="HF_DATASET_ID"` instead of the directory picker. `web/hf_dataset_chooser.js` adds an OPTIONAL combo populated from `GET /taidal/hf_datasets` (→ `list_cached_hf_datasets()` → `huggingface_hub.scan_cache_dir()`, dataset repos only); selecting an entry fills the text field, which stays editable for any Hub id. The gate is the `HuggingFace`-class-name convention (matches `HuggingFaceSource`, sonair's `HuggingFaceClassificationDataset`, and any future `HuggingFace*`), the `repo_id`/`path` param names — NOT a per-node special-case; a plain `path` on a non-HF source still gets the directory picker. Note `taidal_widget="HF_DATASET_ID"` (a STRING-field hint) is distinct from the `HF_DATASET` socket *type* used for `datasets.Dataset` wires.
- **HuggingFace Feature-Selector Fields (free text + column picker, populated from the SELECTED dataset):** A HuggingFace source's `input_feature` / `target_feature` (which dataset *column* maps onto `Sample.input` / `.target`) are free-text `STRING`s — but typed blind they're a frequent source of zero-yield bugs, so `_widget_for` (gated by `_is_hf_feature_param`, params `_HF_FEATURE_PARAMS = {input_feature, target_feature}`) tags them `taidal_widget="HF_FEATURE"` and `web/hf_feature_chooser.js` adds an OPTIONAL "columns" combo. It is the cached-dataset picker ONE LEVEL DOWN: the columns are fetched from `GET /taidal/hf_dataset_features?path=…&name=…&split=…` (→ `list_hf_dataset_features()` → `datasets.load_dataset_builder().info.features`, falling back to streaming one example; degrades to `[]` on ANY failure — convenience over a free-text field, must never break the editor) keyed off the node's CURRENT dataset-id (`HF_DATASET_ID`) field, so the column list always reflects the chosen dataset. The combo refreshes when the dataset id / `name` / `split` widget changes — including when the cached-dataset picker fills the id field (it now fires that widget's `callback` after setting it, so dependents react to the programmatic change). Same `HuggingFace*` class-name gate as the dataset-id field — NOT a per-node special-case; a like-named param on a non-HF class is unaffected. Column order is preserved (input vs target read more naturally than alphabetical). Scope is the two scalar feature params; `metadata_features` (a list) is deliberately left as the comma-separated STRING (a multi-select / opt-in `"*"`=the-rest is a planned follow-up).
- **HuggingFace Split Field (free text + split picker; NOT the `DatasetSplit.split` Literal):** A HuggingFace source's `split` stays a free-text `STRING` — HF accepts slice syntax (`train[:90%]` / `train+test`) a closed dropdown can't express — so `_widget_for` (gated by `_is_hf_split_param`, param `_HF_SPLIT_PARAM = "split"`) tags it `taidal_widget="HF_SPLIT"` and `web/hf_split_chooser.js` adds an OPTIONAL "splits" combo fetched from `GET /taidal/hf_dataset_splits?path=…&name=…` (→ `list_hf_dataset_splits()` → `datasets.get_dataset_split_names`, metadata-only; `[]` on ANY failure) keyed off the node's current `HF_DATASET_ID` field; refreshes on dataset id / `name` change (incl. the cached-dataset pick cascade). Don't merge the two.

- **Node Discovery Is a POSITIVE Category Allowlist (`_NODE_CATEGORIES = {op, model, source, engine, sink, value}`):** `register_module_nodes` registers a discovered class as a node ONLY if `getattr(cls, "__confluid_category__", None) in _NODE_CATEGORIES`. So the palette is *exactly* the deliberately-tagged ops/models/sources/engines/sinks/value-producers. **`category="model"`** is the inference node type (see the *Model Nodes* mandate); **`category="value"`** admits a value producer tagged honestly (a `@configurable(category="value")` class with a no-arg `__call__` — e.g. the helios `MelodyDataset`; `create_comfy_node` still builds it via `_build_value_node`). These are category-less or deliberately non-canvas-tagged; they're admitted by interface/role/lazy-mark, not by `_NODE_CATEGORIES`.
- **Runnable Nodes — trainers / evaluators / processors RUN on execute (members are wired sockets):** A class implementing the **run interface** (`_is_runnable`: a no-arg `run(self)`) becomes a node via `_build_runnable_node`. It enumerates the runnable's FULL configurable surface from `to_pydantic(cls)` (ctor params AND `__init__`-body slots — the confluid `_post_init_field_specs` scan; `@ignore_config` members are skipped) and renders each member as: a **`SAMPLEFLUX_SOURCE`** socket (dataset/source members — `_DATASET_MEMBER_PARAMS = {train_set, val_set, test_set, dataset, flux}` + the `source` param; `flux` covers `DatasetProcessor`'s `Flux` input), a **`SAMPLEFLUX_OBJECT`** socket (any other non-scalar member — model / loss / optimizer / loaders / lightning / metrics / **sink** — via `_is_scalar_anno`; a model/loss/metric/**sink** member is ROLE-QUALIFIED & TASK-AGNOSTIC per the role-socket mandate below — ANY trainer's `model` slot is `SAMPLEFLUX_OBJECT:model`, and `DatasetProcessor.sink` is `SAMPLEFLUX_OBJECT:sink`), or a **widget** (scalars: `num_classes` / `max_epochs` / `experiment_name` …, through the shared `_build_config_inputs`; ComfyUI's "convert to input" covers the rare wire). A member that is a ctor param with NO default is a REQUIRED socket (`model` / `train_set`); everything else is OPTIONAL — unwired ⇒ the runnable keeps its baked default ("true optional"). **The node RUNS on execute — it IS the terminal `OUTPUT_NODE` (there is NO separate Run node; the build/run split was collapsed).** `execute` builds the runnable (ctor params → `__init__`, body slots via post-construction `setattr` of the wired members), then calls `fluxstudio.nodes.run_runnable` (lazy-imported to dodge the `bridge`↔`nodes` import cycle — it restores autograd, handles interrupts, live-streams stdout) and returns `{"ui": {"text": [log]}, "result": (runnable, *live_outputs)}`. OUTPUTS: slot 0 is the (post-run) runnable on a **`SAMPLEFLUX_RUNNABLE`** wire (`kind="runnable"`), then EVERY declared `@output` as a typed socket carrying its LIVE value (see the all-outputs mandate below). A scalar body slot MUST be annotated (`self.x: bool = …`) or it reads as `Any` → an OBJECT socket; real trainers annotate their slots. Member detection is by ANNOTATION/name (never per-class). Pins: `tests/test_bridge.py::test_build_runnable_node_member_sockets_and_widgets` / `::test_runnable_node_execute_builds_post_sets_and_runs`.
- **Runnable Nodes Are DUAL-MODE — terminal runner OR built instance for a workflow combinator (`SAMPLEFLUX_RUNNABLE` input sockets):** A workflow COMBINATOR (`marainer.workflow` `Sequence` / `Conditional` / `Switch`) is itself a runnable that HOLDS other runnables, so `_build_runnable_node` renders its runnable-typed members as **`SAMPLEFLUX_RUNNABLE` INPUT sockets** (the runnable analogue of an op's `SAMPLEFLUX_OP` slot / "Extract as Op"): a SINGLE-runnable member (`_RUNNABLE_PARAMS = {if_true, if_false, default}`) → one socket; a runnable-LIST member (`_RUNNABLE_LIST_PARAMS = {steps}`) → a dynamic `<name>_N` family (seed `steps_0`, grown by **`web/runnable_list.js`**, collected by `_collect_indexed`). Detected by NAME (like `_OP_LIST_PARAMS` / `_SINGLE_OP_PARAMS`), placed BEFORE the dataset/scalar/object checks in `socket_members`, and excluded from the `_build_config_inputs` widget pass. **Because runnable nodes RUN on execute (terminal `OUTPUT_NODE`), a node feeding a combinator's slot would otherwise run TWICE.** So a runnable node is DUAL-MODE, switched by `_runnable_consumed_as_instance(prompt, unique_id)` (reads the hidden **`PROMPT`** — added to the runnable node's `hidden` alongside `UNIQUE_ID` — and returns True iff this node's slot-0 `SAMPLEFLUX_RUNNABLE` output is wired into ANOTHER node's `SAMPLEFLUX_RUNNABLE` input, resolving a dynamic `<prefix>_N` slot back to its `<prefix>_0` seed type): **consumed ⇒ build the runnable and hand over the constructed-but-UN-RUN instance** (no `run_runnable`, `@output`s emit `None`) so the combinator runs the SELECTED branch; **not consumed ⇒ terminal, run on execute** (the unchanged default — a missing/None prompt is treated as terminal, so older ComfyUI and fluxstudio's own tests are unaffected). The combinator (also an `OUTPUT_NODE`, downstream) collects the wired branch instances (single members pass through; lists via `_collect_indexed`) into its ctor and `run_runnable`s ITSELF — restoring autograd (combinators declare `__torch_runner__` since they may wrap a trainer) and forwarding its progress callback to the running branch (`marainer.workflow` owns both — see its AGENTS). Nesting works (a `Conditional` consumed by a `Sequence` is itself built-not-run). Detection is NAME/PROMPT-based, never per-class. Pins: `tests/test_runnable_workflow.py` (runnable sockets single + `steps_0` seed, scalar stays a widget, `prompt` hidden, execute collection + terminal-vs-dual-mode, `_runnable_consumed_as_instance` true/false/no-prompt/dynamic-slot/non-slot0).
- **Object Member Nodes Have TWO Outputs (`instance` + `class`):** A runnable's member classes become `SAMPLEFLUX_OBJECT` producers via `_build_object_node` (`kind="object"`): config widgets → **two** `SAMPLEFLUX_OBJECT` outputs, `instance` (the flowed, live object built right here via `confluid.flow`) and **`class`** (the configured-but-deferred class — a `LazyClass` value; the port is named `class` as the user-facing "the configured class, not yet built", NOT `lazy`). A runnable slot accepts either (`flow` is idempotent on a live instance): wire **`instance`** for a fully-configured standalone object; wire **`class`** when a value is only known at `run()` (`torch.optim.*.params` / `DataLoader.dataset`, or a model's dataset-derived `num_classes`) so the runnable flows it with the runtime kwarg. (graphio's whole-graph export keys eager `!class:Foo()` / deferred `!lazy:Foo` off the WIRED output slot — `instance`=slot 0, `class`=slot 1 — NOT the port label.) A member is detected as `role∈{model,loss,metric,logger}` OR confluid **`lazy`** (`__confluid_lazy__`, set by `@configurable(lazy=True)` / `register(..., lazy=True)`). A `lazy` member SKIPS the runtime-injected required params (`torch.optim.*.params`, `DataLoader.dataset`) so only the configurable knobs (lr / batch_size) are widgets; because those params are missing by design, its `instance` output is `None` (logged at `debug`, NOT a warning — that's expected) and only `class` is usable. For a non-deferred member whose live build simply **fails** on an incomplete/invalid config (e.g. a model node left without `num_classes`), `instance` is `None` and `_build_object_node` emits an **actionable `warning`** ("could not build a live instance …") — ComfyUI tolerates the `None` socket; downstream nodes that need the instance fail legibly on use. Task `role="dataset"` classes are routed to `_build_source_node` (datasets are Sources, not objects). The select runtime members (`torch.optim.Adam`/`AdamW`/`SGD`, `DataLoader`, `pytorch_lightning.Trainer`) are `register(..., lazy=True, group=…)`-ed in **`marainer.configurables`** (entry-pointed; re-exported via `__all__`) — **deliberately with NO `category`** (only a presentation-only `group`), so they're FluxStudio object nodes via the `lazy` mark WITHOUT leaking into navigaitor's category-driven form-spec slot pickers (which would then offer the raw `params`-taking optimizer instead of navigaitor's curated infra config). Register the class upstream + mark it `lazy`, NEVER hand-build a member node here. **A member target may be a CLASS or a plain builder/factory FUNCTION** — the gate is "callable + marked", NOT "class + marked" (`_is_object_member_class` checks `callable(obj)`, never `inspect.isclass`; the `register_module_nodes` second pass likewise admits a re-exported registered *function*). Canonical case: `raidar.configurables` `register`s torchvision's detection builder FUNCTIONS (`fasterrcnn_*` / `retinanet_*` / `fcos_*` / `ssd*`) with `task="detection", role="model", lazy=True`, so each becomes a `SAMPLEFLUX_OBJECT:model` object node whose widgets are introspected from the FUNCTION's own signature (`num_classes` / `weights_backbone` / …) — wiring straight into a detection trainer's `model` slot with no Retag. `_build_object_node` already uses `inspect.signature(cls)` + `LazyClass(cls, …)` + `flow`, all callable-safe; the `class` output is a `LazyClass(builder, …)`. (Relies on confluid's callable-aware `to_pydantic` / `flow` / `resolve_class` — confluid AGENTS "A Target May Be ANY Callable".) NOTE: object nodes have TWO outputs — index 0 is `instance`, index 1 is `class` (the `LazyClass`). Both outputs carry the ROLE-QUALIFIED & TASK-AGNOSTIC socket (`_object_socket_for_class(cls)` → `SAMPLEFLUX_OBJECT:model`) per the role-socket mandate below. Pins: `tests/test_bridge.py` (object node dual output / deferred / build-warning; `::test_object_member_predicate_accepts_marked_function` / `::test_object_node_from_builder_function`).
- **Object Sockets Are ROLE-QUALIFIED & TASK-AGNOSTIC; the Retag Node Is the Escape Hatch:** ComfyUI connects sockets only on string EQUALITY, so object-member sockets are **role-qualified** — `SAMPLEFLUX_OBJECT:<role>` (`bridge._object_socket`), where `<role>` ∈ `{model, loss, metric, sink}` (the value-set `bridge._QUALIFIED_OBJECT_ROLES`). **TASK is deliberately NOT on the socket** — a classification model and a segmentation model both produce `SAMPLEFLUX_OBJECT:model` and dock into ANY trainer's `model` slot. Task survives only as GUIDANCE (navigaitor slot ranking + the palette folder/label). The role still guards KIND: a loss (`SAMPLEFLUX_OBJECT:loss`) can't dock into a model slot. An object node's output role comes from `bridge._object_socket_for_class` = the explicit `@configurable(role=…)` tag, ELSE inferred from the Python type (`_role_for_class` — a duck-typed MRO scan: `Metric→metric`, `Optimizer→optimizer`, `DataLoader→loader`, `Logger→logger`; model vs loss are BOTH `nn.Module` so only the tag disambiguates them). A runnable's object SLOT role comes from `bridge._STRICT_SLOT_ROLES` (`model→model` / `loss_fn→loss` / `*metrics→metric` / `sink→sink`, mirroring navigaitor's `PARAM_NAME_TO_ROLE` — fluxstudio MUST NOT import navigaitor; the convention is small and replicated) and a trainer `@output` (`trained_model`) via the keyword-scanning `_infer_member_role`. A `category="sink"` class has no `role=` tag, so `_role_for_class` maps it to a synthetic `"sink"` role (checked FIRST) so its object output qualifies symmetrically with the `DatasetProcessor.sink` slot. The object-NODE output side and the runnable-SLOT input side MUST agree on which roles qualify (both gated on `_QUALIFIED_OBJECT_ROLES`) — a one-sided qualifier silently refuses an otherwise-valid wire (the original "can't connect a logger" footgun). **Scope:** model/loss/metric/sink object members. Datasets (and `DatasetProcessor.flux`) stay generic `SAMPLEFLUX_SOURCE`. **Role-less members (optimizer / loader / lightning / logger) stay bare `SAMPLEFLUX_OBJECT`** — no kind to enforce; they interchange among themselves (acceptable). The **Retag node** (`nodes.py:RetagObjectNode`, `Taidal_Retag`) is the deliberate, visible bypass: a wildcard (`AnyType("*")`) input accepts any object; the `target_role` combo (from the registry's `list_roles()`) re-stamps `__confluid_role__` PER-INSTANCE (never the class) and `web/retag.js` retypes the OUTPUT socket to the chosen `SAMPLEFLUX_OBJECT:<role>` (or `*` for `(keep)`); `target_task` re-stamps only the guidance tag (no socket effect). graphio whole-graph export does NOT round-trip Retag nodes (no `TAIDAL_CALLABLE_PATH`, like the other canvas-only adapters — skipped-with-comment per the export-skip mandate; ops-export still raises `UnsupportedTopologyError` on them); it's a canvas convenience, hand-written YAML controls types directly. `_is_socket_type`/`_base_socket_type` (base-aware) keep graphio's socket-vs-widget split working under the qualified strings. Pins: `tests/test_bridge.py::test_object_node_output_socket_is_role_qualified` / `::test_strict_sockets_reject_cross_role` / `::test_role_for_class_*`, `tests/test_nodes.py::test_retag_*`.
- **Object Nodes Wire Object-Typed Ctor Params as INPUT Sockets (the `logger`/`callbacks` fix):** An object node's constructor param that accepts an OBJECT — a non-scalar **class** arm with **no `str`/`int`/`float` config arm** (a `bool` toggle arm or `None` does NOT disqualify) — renders as a wired **`SAMPLEFLUX_OBJECT`** INPUT socket instead of a widget, so a producer node docks into it. Detection is by annotation SHAPE (`bridge._is_wireable_object_param`, applied in `_build_object_node`), NEVER a per-class list: on a `pytorch_lightning.Trainer` it sockets `logger` / `callbacks` / `plugins` while leaving `accelerator` / `strategy` / `devices` / `precision` / `profiler` as STRING/INT widgets (they have a `str`/`int` config arm you TYPE). This fixes the bug where `logger: Union[Logger, Iterable[Logger], bool]` collapsed to a **BOOLEAN widget** (`_map_type` string-scans and hits `"bool"`) so a logger node couldn't connect. The socket is **bare `OBJECT_TYPE`** (role-less, matching the logger/callback producer nodes' bare `SAMPLEFLUX_OBJECT` output). **A param that also admits a LIST of objects (`_admits_object_list` — a `list`/`Iterable`/`Sequence` arm of an object class, e.g. `logger: Union[Logger, Iterable[Logger], bool]` / `callbacks: Union[List[Callback], Callback, None]`) gets a DYNAMIC `<name>_N` socket FAMILY** (seed `<name>_0`; `web/object_list.js` grows `<name>_1`, `<name>_2`, … as you wire — the object analogue of `op_N`/`source_N`), collected index-ordered into a list by `bridge._collect_indexed` in `execute` (empty ⇒ omitted ⇒ ctor default). A single-object param (no list arm) gets ONE socket — required when the param has no default, else optional. `execute` splits wired object kwargs (passed through as-is, `flow()`-ed first if still a `Fluid` so the producer's `instance` OR `class` output both work) from widget kwargs (still `_coerce_kwargs`-ed). Wire the producer's `instance` output. `web/optional_inputs.js`'s `(optional)` marker skips ANY `<name>_<digit>` slot (the list families have their own add-more UX). This is the INPUT-side complement to the role-qualified OUTPUT mandate above. Pins: `tests/test_bridge.py::test_is_wireable_object_param_shape_rule` / `::test_admits_object_list_shape_rule` / `::test_object_node_object_param_is_a_socket_not_a_widget` / `::test_object_node_list_param_seeds_indexed_socket` / `::test_object_node_collects_indexed_objects_into_list` / `::test_real_lightning_trainer_logger_is_a_dynamic_list_socket`.
- **`run_runnable` Restores Autograd for `TorchRunner`s (ComfyUI runs under `inference_mode`):** `fluxstudio.nodes.run_runnable(runnable, unique_id)` is the shared runner each generated runnable node's `execute` calls (the node IS the `OUTPUT_NODE`). ComfyUI evaluates the whole graph under `torch.inference_mode()` (`execution.py`), which is fatal for **gradient-based training**: model params (model nodes are lazy → the backbone is built *inside* `run()`), forward activations, and the loss all become inference tensors with no autograd graph, so `loss.backward()` dies with *"element 0 of tensors does not require grad and does not have a grad_fn"*. So `run_runnable` re-enables normal autograd (`with torch.inference_mode(False), torch.enable_grad():`) ONLY for a runnable that declares itself a **`marainer.TorchRunner`** (duck-typed `__torch_runner__` flag — no hard `marainer` import). Inference-only runnables (`LightningEvaluator`, `DatasetProcessor`) leave the flag unset and run as-is under ComfyUI's inference mode. This is why model nodes being **lazy** matters: the backbone is constructed inside the grad-restored `run()`, not earlier in the object node's `execute` (which still runs under `inference_mode`). Pins: `tests/test_nodes.py::test_run_runnable_*`.
- **`run_runnable` Is Interruptible (worker thread + injected `KeyboardInterrupt`):** ComfyUI only polls its interrupt flag BETWEEN nodes, but `run_runnable` wraps ONE blocking `.run()` call that can run for minutes/hours — so the interrupt button would otherwise be ignored until the sweep finished. It therefore executes the runnable on a **daemon worker thread** and polls `_processing_interrupted()` (a lazy, guarded `comfy.model_management.processing_interrupted()` — `False` when comfy is absent, so fluxstudio's own tests/dev runs are unaffected) from the calling thread every 0.1 s; when the flag goes high it injects a `KeyboardInterrupt` into the worker via CPython's `PyThreadState_SetAsyncExc` (`_raise_interrupt_in_thread`) and re-raises ComfyUI's `InterruptProcessingException` for a clean stop (no traceback, UI reset). PyTorch Lightning catches `KeyboardInterrupt` for a graceful shutdown; `DatasetProcessor` / Flux iteration loops simply unwind. **Grad/inference mode is thread-local**, so the worker does NOT inherit the `torch.inference_mode()` ComfyUI wraps graph execution in — `run()` captures `torch.is_inference_mode_enabled()` on the calling thread and the worker re-establishes the correct context itself (grad-restored for `__torch_runner__`s, `inference_mode()` re-entered for inference-only runnables). The injection lands at a Python statement boundary (between batches / samples), so a single long-running C kernel is not interruptible — an accepted limitation. This keeps ALL ComfyUI/interrupt knowledge in fluxstudio; marainer/sampleflux are untouched (per marainer's `TorchRunner` mandate). Pins: `tests/test_nodes.py::test_run_runnable_interrupt_*`, `test_run_runnable_grad_context_is_active_inside_worker_thread`.
- **A Runnable Node's Output Is LIVE-Streamed Into a Collapsible Widget (`web/run_output.js`):** The runner's stdout/stderr (training progress, metrics, loggair lines) is captured by `_TeeStream` (mirrored to the live console; delegates `isatty`/`fileno`/`encoding` so a real tqdm/Lightning bar still renders there) and shown in a read-only, **collapsible** multiline widget on the node. It streams **DURING** the run: the worker-join poll loop (the same 0.1 s loop that checks the interrupt flag) pushes the latest `_collapse_carriage_returns`-collapsed, `_strip_ansi`-cleaned, `_MAX_OUTPUT_CHARS`-tail-capped snapshot — but only when it CHANGED — via `_send_run_output` → ComfyUI's `server.PromptServer.instance.send_sync("taidal.run_output", {node, text})` websocket event. **ANSI stripping (`_strip_ansi`, `_snapshot` only):** a Rich/Lightning bar emits CSI control codes — color, dim/underline (`\x1b[2m`/`\x1b[2;4m`), erase-line (`\x1b[2K`), cursor moves — that a plain text widget can't render and that show up as literal `[2K`/`[0m` garbage (NO_COLOR strips *color* SGR but not dim/underline/erase). `_snapshot` strips the lot for the WIDGET copy ONLY; the `_TeeStream` console mirror keeps them so the bar still animates in the terminal. - **Container Values Round-Trip On The Wire — Input Side Too (`_coerce_kwargs` JSON-decode):** A container `@output` (a `Tuple`/`Dict`) rides a `STRING` socket json.dumps-encoded (the `@output` mandate above). The INPUT-side complement lives in `_coerce_kwargs`: a STRING value arriving on a `Dict[...]`-annotated param is `json.loads`-decoded back to a dict — and, when that fails, RETRIED with `ast.literal_eval` so a hand-typed Python dict LITERAL works too (`{0:'BG',1:'5GNR'}` — int keys + single quotes — is natural to type for a `Dict[int, str]` like `raidar.YoloSink.class_names` but is INVALID JSON; `ast.literal_eval` is safe, literals only; a value that is neither stays raw) — and a `Tuple[str, ...]`-annotated param (NOT a range `Tuple[float,float]`/`Tuple[int,int]`, which use `__lo`/`__hi` widgets, nor a variable-length `Tuple[int,...]`, which stays a RANGE pair — hence the `not int/not float` guard) is decoded from a JSON `[...]` array, a Python TUPLE LITERAL (`(`-prefixed → `ast.literal_eval`), OR a hand-typed comma string into a tuple. **The tuple-literal branch is LOAD-BEARING, not cosmetic:** the widget DEFAULT of an empty `Tuple[str, ...]` param renders as the repr `"()"`, and a comma-split of `"()"` yields `("()",)` — a one-element tuple of the literal string `()`, which is **TRUTHY**. That silently broke the helios `ImpairmentsChain` tx/rx config: the chain resolves `self.tx_disabled or metadata["impairments_tx_disabled"]`, so a `tx_disabled` left at its `()` default coerced to `("()",)` OVERRODE the metadata config stamped by `ImpairmentsTxConfig`/`ImpairmentsRxConfig` — the whole config mechanism did nothing. `ast.literal_eval("()")` → `()` (falsy → reads the metadata); it also makes the docstring-documented `("IQImbalanceOp", "QuantizeOp")` form round-trip (a non-literal `(`-string falls through to the comma-split). This is what lets a value node's `disabled`/`probability_overrides` output wire into another node's `Tuple`/`Dict` input (e.g. `ImpairmentsChain.tx_disabled`) and round-trip as a real container, not the literal JSON string. **A COMPOUND container — a LIST whose elements are themselves tuples/pairs (or a Union of those), e.g. the helios `Config.keys: str | list[str | tuple[str, str]]` rename map (a bare key = src==dst, a `(src, dst)` pair renames)** — is the generic case the flat `Tuple`/`List` branches CAN'T reconstruct (a list OF tuples). It gets its OWN branch, gated on the annotation SHAPE — **`"list" AND "tuple"` in the annotation, no `int`/`float`** (disjoint from a flat `Tuple[str, ...]`, which has "tuple" but no "list", and a flat `List[str]`, which has "list" but no "tuple") — placed BEFORE the flat-`Tuple` branch. It accepts EITHER a Python/JSON literal (`[("a","b"), "c"]` / `[["a","b"], "c"]` — `ast.literal_eval` first, then `json.loads`; a JSON inner list is normalised back to a `tuple` so a pair stays a pair) OR a friendly comma list with `src:dst` renames (`"snr_db, noise_power_db:nf"` → `["snr_db", ("noise_power_db", "nf")]` — split on `,`, then each item on `:`; a bare item stays a string, an item with `:` becomes a pair; also the fallback for a malformed literal). This is the GENERIC mechanism for any list-of-pairs/compound param — keyed off the annotation shape, NEVER a class name; do NOT refactor an upstream class into two comma-list params to dodge it (the decoder is shared by node `execute` AND both exporters via `_coerce_kwargs`, so one fix makes the param configurable on-canvas AND round-trip to YAML). The decode branches sit BEFORE the `List`/`Sequence` comma-split (kept for flat `List[str]` params) and after the Literal/blank handling. - **Empty Canvas Instead of ComfyUI's SD Sample (`web/empty_default_graph.js`):** ComfyUI ships a built-in `defaultGraph` (CheckpointLoader → CLIP → KSampler → VAE → Save Image) that it loads as the initial canvas AND re-loads whenever the LAST workflow tab is closed (frontend `workflowService.closeWorkflow` → `loadDefaultWorkflow` → `app.loadGraphData(defaultGraph)`). Those Stable-Diffusion nodes are unrelated to FluxStudio's Taidal pipeline nodes, so this web extension substitutes ComfyUI's own `blankGraph` (an empty canvas). The frontend exposes both on `window.comfyAPI.defaultGraph` (a self-described *internal* shim — so the extension is defensive: optional chaining, a hardcoded blank-graph fallback, idempotency guards). TWO complementary hooks (internals aren't a stable public API): (1) wrap `app.loadGraphData` to swap the default-graph object for a fresh blank one at call time — catches first-launch AND the all-tabs-closed reload with no timing race; (2) blank the shared `defaultGraph` object IN PLACE (poll until its possibly-lazy chunk is present, ~5s cap) — `loadDefaultWorkflow` captured that exact object reference at module-eval time, so emptying its contents neutralizes the reload even if (1)'s `app` ref isn't the one the workflow service calls. Substitution is gated on object IDENTITY (`graphData === defaultGraph`), so a real user workflow loads untouched. JS web extensions aren't in CI; verified by `node --check` + a node harness simulating `window.comfyAPI.defaultGraph` + a fake `app` (immediate, lazy-chunk, and untouched-user-workflow paths). This is GUI/launch UX (the one sanctioned class of canvas-only adapter glue), not a node/op.
- **Registration Key Is Globally Unique (`_node_key`), NOT Just the Class Name:** ComfyUI identifies a node TYPE by its key in `NODE_CLASS_MAPPINGS` — its display `CATEGORY` folder does NOT make it unique. A plain `Taidal_<ClassName>` collides whenever two modules expose a same-named class (the canonical case: `sampleflux.ops.numpy:RescaleOp` AND `sampleflux.ops.torch:RescaleOp`, likewise `StandardizeOp`) — the second registration silently overwrites the first and one node disappears from the palette. `register_module_nodes` therefore keys via `_node_key` = `Taidal_<package>_<category>[_<group-segments>]_<callable>` (e.g. `Taidal_sampleflux_op_numpy_RescaleOp` vs `Taidal_sampleflux_op_torch_RescaleOp`). The key is built from RAW identifiers (top-level package, lowercase category, literal group) NOT the display-cased `[PKG]` tag, so it stays stable regardless of how the tag is derived; the DISPLAY name stays the verbatim class name (so both still read "RescaleOp" in their folders). The hand-written adapter nodes in `nodes.py` keep their own literal keys (`Taidal_WalkDataset` / `Taidal_ExtractSample`). NOTE: this changes saved-workflow `class_type` strings for auto-discovered nodes — an older workflow referencing `Taidal_RescaleOp` must be re-pointed at the qualified key.
- **Widget Tooltips Come From the Docstring `Args:` (never hand-written here):** `_build_config_inputs` sets each widget's `tooltip` from the callable's docstring `Args:` block via `confluid.parse_param_docs` — the SAME per-parameter help navigaitor surfaces as pydantic `Field(description=...)` in its form-spec. Document a constructor parameter ONCE in the upstream class's `Args:` and it appears as a hover tooltip here AND in the navigaitor editor. An undocumented param simply gets no tooltip — the fix is to add the `Args:` entry in sampleflux/waivefront, NEVER to hand-write a tooltip in the bridge.
- **Typed Node Classification (Source / Op / Generic):** `create_comfy_node` classifies each discovered callable so a pipeline wires by TYPE, not opaque STRING: a `Sample`-yielding source class (`__getitem__`/`__iter__` → `Sample`) becomes a `-> SAMPLEFLUX_SOURCE` node (constructor config as widgets, output a `Flux`); a `@configurable` op class with `__call__(self, sample: Sample) -> Optional[Sample]` becomes a **dual-mode** op node (config widgets + an OPTIONAL `sample` socket → a `sample` applied-output AND an `op` `SAMPLEFLUX_OP` output — see *Ops Are Dual-Mode* below); everything else stays a generic scalar/STRING node. `SAMPLEFLUX_SOURCE` / `SAMPLEFLUX_SAMPLE` / `SAMPLEFLUX_OP` are FluxStudio socket type strings carrying the live `Flux` / `Sample` / op objects. When you add a new SampleFlux/Waivefront source or op that should chain, make sure its `__getitem__`/`__iter__`/`__call__` is annotated with `Sample` so the classifier picks the right shape — do NOT add per-node special-cases to the bridge.
- **Ops Are Dual-Mode (apply via `SAMPLEFLUX_SAMPLE` AND expose via `SAMPLEFLUX_OP`):** `_build_op_node` builds every op node with an OPTIONAL `sample` input and TWO outputs — `sample` (the op applied to the input, for linear chaining) and `op` (the constructed op as a `SAMPLEFLUX_OP` value). Wire `sample → sample` to chain inline (today's UX); leave `sample` unconnected and take the `op` output to use the node as an op-VALUE. `execute` constructs the op once and returns `(op(sample) if sample is not None else None, op)`. A **higher-order op** — one whose constructor has an op-list param (`_op_list_params` → `{param: socket-prefix}`: the name-set `ops`/`transforms` (list-annotated → `Enable`/`Parallel`/`TransformChain`/`HeliosComposeOp`) UNION the waivefront-helios bridge's `__taidal_op_list_params__` stamp — a `List[Transform]` slot under its own helios name, e.g. `HeliosIfOp.true_transforms`/`false_transforms`) — does NOT render that param as a STRING widget; instead each op-list family gets dynamic `SAMPLEFLUX_OP` inputs (`<prefix>_0`, `<prefix>_1`, … grown by `web/op_list.js`, now generalised to discover ANY `<prefix>_N` family of `SAMPLEFLUX_OP` type, like `web/object_list.js`). The prefix is `op` for the name-set params (existing `op_N` graphs/exports unchanged) and the PARAM NAME for stamped helios lists, so ONE node carries SEVERAL independent families. `execute` collects each (`_collect_indexed`, index-ordered, drops empties) into its kwarg before constructing. Detect op-list params by the `ops`/`transforms` naming + `List` annotation OR the helios `__taidal_op_list_params__` stamp — NEVER per-class in the bridge (the stamp is the type-precise authority, computed by waivefront-helios from the helios `Transform` annotations). **SINGLE-op params get ONE socket EACH (possibly several per node):** `_single_op_params` = the name-set `op`/`target` (`_SINGLE_OP_PARAMS`, non-scalar annotation) UNION the helios `__taidal_op_params__` stamp (a single `Transform` slot under its own helios name). Each renders as one optional `SAMPLEFLUX_OP` input instead of a STRING widget — `RandomApply.op`, `ConfigureOp.target` (sampleflux's helios-Configure port: compute ops via `op_N` + the op to configure via `target` + `param`), AND a bridged helios composite's slots: `HeliosConfigureOp` sockets BOTH `compute` and `target`, plus `HeliosConfigOp.delegate` / `HeliosApplyToTargetOp.transform`. (The old single-name `_single_op_param` exposed only the FIRST — why `compute` rendered as an inert STRING widget while `target` connected.) `execute` pops each wired value and setattr's it post-construction (the confluid paradigm). Pins: `tests/test_bridge.py::test_single_op_param_renders_op_socket` / `::test_stamped_single_op_params_each_get_a_socket` / `::test_stamped_op_list_params_seed_distinct_families_and_collect` / `::test_configure_op_node_executes_with_wired_target_and_compute`. NOTE this keeps `bridge.export`'s `TAIDAL_NODE_KIND`/`TAIDAL_CALLABLE_PATH` + the `sample`-link chain intact. **Op-VALUE wires DO export** (single-op + op-list, incl. the stamped helios slots): `export.py`/`graphio.py` recognise them class-aware (`export._is_op_value_key`/`_op_list_socket_param` introspect the op class via `bridge._single_op_params`/`_op_list_params`) — single ops embed as nested `!class:` instances (`_resolve_widget_link`, key-agnostic), each op-list family embeds into its OWN kwarg (`_embed_op_values` groups by param), and the whole-graph `graphio` naming guard treats stamped op-list bases like `ops` (the confluid-broadcast collision guard). - **Adapter Nodes Are Glue, Rendering Lives in Waivefront/SampleFlux (custom VIEWER nodes ARE sanctioned):** The statically-defined nodes in `fluxstudio/nodes.py` — `WalkDatasetNode` (`SAMPLEFLUX_SOURCE` + auto-incrementing `index` via ComfyUI's `control_after_generate` → the `Sample` at `source[index]`) and `SampleExtractorNode` (a `SAMPLEFLUX_SAMPLE` + `field` selector → typed `IMAGE`/`MASK`/`STRING`/`INT`/`FLOAT`/`SAMPLEFLUX_ARRAY` sockets — the `array` output carries the RAW field value on demand, tensor/ndarray passed through unchanged, PIL→ndarray, for the Array/Tensor Histogram viewer or any array consumer) — are ComfyUI orchestration/adapter glue, NOT SampleFlux data ops, so they may live here. `SampleExtractorNode` is NOT an `OUTPUT_NODE`: it unpacks a Sample field onto typed sockets so you can wire NATIVE ComfyUI viewers (Preview Image, text/number displays) when they are present. **Custom in-canvas VIEWER / `OUTPUT_NODE` nodes that render on their own surface (via a `web/` extension) ARE sanctioned** — e.g. `ArrayHistogramViewerNode` (the *Array / Tensor Histogram* mandate below). This intentionally RELAXES the earlier "never re-add a bespoke in-canvas viewer (the removed `SampleViewerNode`)" rule: under `--no-default-nodes` ComfyUI's native viewers are pruned, so a custom viewer node is the only way to view samples at all, and we plan a family of such viewer nodes; an interactive view (a histogram, a hover-readout) has no native equivalent regardless. **The ONE hard constraint that REMAINS:** the rendering / analysis MATH MUST live in sampleflux/waivefront (`sampleflux.ops.image.value_to_image` / `array_histogram` / …, re-exported from `waivefront.visualizers` — `sample_to_image` a thin wrapper), NEVER hand-rolled in fluxstudio; the node only bridges ComfyUI's protocols (a `(H,W,3) uint8` array → the `IMAGE` tensor protocol `[1,H,W,3]` float, a 2-D field → the `MASK` protocol `[1,H,W]`, or a base64 PNG → a `web/` canvas) and ships that sampleflux/waivefront output to the frontend. The relevant socket is chosen from the sample's features via `Sample.describe()` (ComfyUI can't retype a socket per run, so all plausible types are surfaced — see *Typed Sample extraction* below). This is the sanctioned class of "FluxStudio-only nodes": adapters that translate ComfyUI's execution model AND viewer nodes that DISPLAY sampleflux/waivefront-rendered output are allowed; data ops and the rendering math itself are not.
- **Array / Tensor Histogram Viewer (`ArrayHistogramViewerNode`, key `Taidal_ArrayHistogram`) — the reference custom in-canvas viewer node (more planned):** A FluxStudio analogue of *ComfyUI-Olm-Histogram* for SampleFlux data, and the template for the family of custom viewer nodes sanctioned by the *Adapter Nodes Are Glue* mandate above. It is an `OUTPUT_NODE` that takes an array/tensor on the `SAMPLEFLUX_ARRAY` socket (`bridge.ARRAY_TYPE` — fed by **Extract from Sample**'s `array` output) OR a native `IMAGE` (frame-0 of the batch, histogrammed in its `[0,1]` range), plus `bins`/`channel`/`colormap`/`max_size` widgets, and renders ON THE NODE: a histogram of the value distribution, the array as a colormapped image, and a HOVER readout (move the cursor over the image to read the value + source coordinate). It passes the array through its `array` output so it can also sit inline. **Why it stays glue (the hard constraint that survives the relaxed viewer rule):** ALL computation lives in sampleflux — `sampleflux.ops.image.array_histogram` / `select_channel` / `value_to_image` (`channel < 0` = mean view / natural RGB; `0..N` selects a channel) — the node only base64-encodes that output into a JSON payload and ships it via `{"ui": {"taidal_array_histogram": [payload]}}` to `web/array_histogram.js` (`onExecuted` receives the payload, re-delivered on workflow re-open). It works regardless of `--no-default-nodes` (unlike Extract→Preview Image), which is precisely why custom viewer nodes matter — when the native viewers are pruned this IS the viewer. **RENDERS ON THE LITEGRAPH NODE CANVAS, NOT a DOM widget (the pattern for ALL Taidal viewer nodes):** `web/array_histogram.js` draws the image/histogram/text/crosshair in `nodeType.prototype.onDrawForeground(ctx)` (the node's own 2D context), sizes the node via a `computeSize` override that returns a SMALL minimum so the node resizes FREELY in both axes (no snap-back), draws the image FIT-IN-BOX (scaled to fill the node's spare area — width AND height — aspect-preserved + centered, so growing either axis enlarges the image) with the stats line WORD-WRAPPED to as many lines as the width needs (the wrapped line count feeds both `computeSize` and the layout so the reserved height matches), and handles hover/clicks through litegraph's native `node.onMouseMove`/`onMouseDown`/`onMouseLeave` (which receive NODE-LOCAL coords; the layout rects are stashed on the node each draw so the handlers hit-test the same geometry; the log/lin toggle is a canvas-drawn button hit-tested in `onMouseDown`, not a widget). Do NOT use `addDOMWidget` for these viewers: ComfyUI's DOM-widget parent is shrink-to-fit, which broke width sizing (CSS `%` → the image's natural width), node resize, AND pointer routing (the element captured / dropped mouse events) — every one of those bugs evaporates when you draw on the node canvas (this is exactly how ComfyUI-Olm-Histogram works). This is the template for the planned viewer family. **CRITICAL — NaN/Inf sanitization (`_sanitize_float`):** ComfyUI ships the `ui` payload over a websocket via `json.dumps` (default `allow_nan=True`), which emits bare `NaN`/`Infinity` tokens that the browser's `JSON.parse` REJECTS — corrupting the whole message. So EVERY float that may be non-finite (the raw value grid, bin edges, stats) MUST be sanitized to `None` before it enters the payload (explicit finite check, NEVER `np.nan_to_num` — that fabricates misleading finite numbers); `tests/test_nodes.py::test_array_histogram_payload_is_json_safe_with_nan` pins this with `json.dumps(payload, allow_nan=False)`. The hover value grid is nearest-downsampled (≤256 longest side, `_HOVER_GRID_MAX`) so the payload stays small while reporting real (non-interpolated) sample values. The node declares NO hidden `unique_id` input (that would make `web/run_output.js` / `web/node_timing.js` graft their widgets on); `web/array_histogram.js` gates on `nodeData.name === "Taidal_ArrayHistogram"`. To add a colormap, edit the upstream `Colormap` Literal in `sampleflux/ops/image.py`; to change the histogram math, edit `array_histogram` there — NEVER hand-roll pixels or stats in the node. Pins: `tests/test_nodes.py::test_array_histogram_*`; the `SAMPLEFLUX_ARRAY` socket is in `_SOCKET_TYPES` but NOT `TYPE_MAP` (`tests/test_bridge.py::test_array_type_is_a_wire_socket_not_a_widget`).
- **Confusion Matrix Viewer (`ConfusionMatrixViewerNode`, key `Taidal_ConfusionMatrix`) — second custom in-canvas viewer, same template:** Built to the `ArrayHistogramViewerNode` pattern above (the rendering math lives in sampleflux; the node is glue; it draws on the litegraph node canvas). It is an `OUTPUT_NODE` whose PRIMARY input is the evaluator's GENERIC **`all_metrics` `@output`** — a `STRING` (JSON) socket carrying EVERY metric (`name -> value`; the evaluator has NO confusion-matrix knowledge), `forceInput` so the STRING output wires straight in — with a fallback raw `SAMPLEFLUX_ARRAY` `matrix` input + a `class_names` STRING (JSON list / comma string, via `_parse_class_names`) for standalone use. The node **extracts EVERY confusion matrix** from the metrics via `sampleflux.ops.image.confusion_matrices_payload(metrics, class_names)` (the square-2D entries, by SHAPE not name — there can be several), which builds one `confusion_matrix_payload` per match (raw `counts` + the three `normalized.{true,pred,all}` variants precomputed so toggling never re-runs). `_build_confusion_payloads` is the thin glue that ships `{"ui": {"taidal_confusion_matrix": [payload, …]}}` (a LIST, one per matrix) to `web/confusion_matrix.js`; the FIRST matrix's counts pass through the `matrix` output so the node can sit inline. **`web/confusion_matrix.js`** draws a class-labeled grid on `onDrawForeground` (rows = true class, columns = predicted; cells coloured white→blue by value; the diagonal = correct, outlined; class names down the left + across the top, ellipsized + hidden when cells get tiny), a `view:` button (cycling **count → row % → col % → all %** — the normalized views render the precomputed variants as PERCENTAGES, DISPLAY-ONLY, no re-run), a `cm:` button (cycles between matrices when several are present), and a HOVER readout (`true=<class> pred=<class> n=<count>` + the % when a % view is active). **Two layout bugs are handled, both easy to reintroduce:** (1) `contentStartY` reserves the input-socket rows (`max(#inputs,#outputs) * NODE_SLOT_HEIGHT`), NOT just widgets — this node has only INPUT SOCKETS (no widgets), so the widget-based start used by the histogram viewer sat at the top and the grid OVERLAPPED the sockets; (2) `clippedText`'s clip rect MUST follow the text `align` — a CENTER-aligned cell label is drawn around `x`, so the clip starts at `x - maxW/2` (a left-aligned clip `[x, x+maxW]` cut off the LEFT half of every cell number — the "numbers don't display correctly" bug). Class (axis) labels use a smaller 8px font so more fit. Same invariants as the histogram viewer: JSON-safe payloads (the sampleflux helper sanitizes a 0-divisor row/col to `None`, never `NaN`; pin `::test_build_confusion_payloads_is_json_safe`), NO hidden `unique_id`, gated on `nodeData.name === "Taidal_ConfusionMatrix"`, drawn on the node canvas NOT a DOM widget, `computeSize` returns a small minimum (the grid fills the available square). This is the sanctioned way to surface non-scalar metrics — `computed_metrics` stays scalar-only; the evaluator dumps the FULL results on a GENERIC `all_metrics` output and the viewer (with sampleflux) owns "which metric is a confusion matrix", instead of one bespoke typed `@output` per metric kind. To change the extraction/normalization/colour, edit `confusion_matrices_payload` / `confusion_matrix_payload` in `sampleflux/ops/image.py` — NEVER hand-roll it in the node/JS. Pins: `tests/test_nodes.py::test_confusion_matrix_*` / `::test_parse_class_names_*`; sampleflux `tests/test_image_ops.py::test_confusion_matrix_payload_*` / `::test_confusion_matrices_payload_*`; marainer `tests/test_evaluator.py::test_evaluator_all_metrics_*`.

- **Typed Sample Extraction (derive the socket from features, never hand-render):** `SampleExtractorNode` exposes a Sample's `input`/`target` on the fixed socket set `IMAGE`/`MASK`/`STRING`/`INT`/`FLOAT`/`SAMPLEFLUX_ARRAY`/`SAMPLEFLUX_VALUE` and the user wires the one matching their viewer/consumer. Because ComfyUI sockets are statically typed at registration, the node CANNOT change a socket's type per run — so it surfaces every plausible type and derives *which is meaningful* from `Sample.describe()` (stored `__features__`/`__spec__`, else inferred). When the value isn't applicable to a socket it returns a benign placeholder (a text-rendered `IMAGE`, an empty `1×1` `MASK`, `0`/`0.0`), since ComfyUI requires every declared output be returned each run. The **`array`** (`SAMPLEFLUX_ARRAY`) output is the raw field coerced toward an ndarray (PIL→ndarray; tensor/ndarray verbatim) for the histogram viewer; the **`value`** (`SAMPLEFLUX_VALUE`) output is the raw field VERBATIM (a list of boxes stays a list, no coercion) so it wires into a nested-container param socket (`OverlayBoxes.boxes` — see the value-socket mandate). If you need a new view type, add a socket here AND back its rendering with a waivefront helper — never hand-roll pixels in the bridge/node.

- **Type-Spec Connection Filtering (socket strings stay generic):** A Sample wire ALWAYS keeps the `SAMPLEFLUX_SAMPLE` socket string — do NOT encode the SampleFlux type into finer socket strings (ComfyUI matches sockets by string equality, which can't express ranges/dtype-families/Union). Instead the richer contract is layered on top, sourced from each op/source's `ACCEPTS`/`PRODUCES` (declared in sampleflux/waivefront, never here): (1) `create_comfy_node` stashes `TAIDAL_ACCEPTS` / `TAIDAL_PRODUCES` (`SampleType.to_dict()` or `None`) on the generated node class; (2) a generated op node's `execute()` runs a **runtime accept-check** (`infer_sample_type(sample)` vs `cls.ACCEPTS`) and raises a legible error on mismatch — this is AUTHORITATIVE; (3) the `/taidal/node_specs` route + `web/connection_validator.js` reject incompatible Sample wires live on the canvas via litegraph's `onConnectInput` — this is ADVISORY (drag-drop only). The JS matcher is a faithful port of `sampleflux.typespec.compatible()` (permissive: `Any`/unknown passes); keep it in sync with the Python and cover the semantics in `sampleflux/tests/test_typespec.py`. Never hand-define type specs in FluxStudio — if a contract is wrong or missing, fix the op's `ACCEPTS`/`PRODUCES` in sampleflux/waivefront.
- **Optional Input Sockets Are Visually Marked (`web/optional_inputs.js`):** ComfyUI's `INPUT_TYPES` splits inputs into `required` / `optional`; `_node_class` emits the `optional` dict and `_build_runnable_node` routes a runnable's non-mandatory members there (the `Mandatory[...]` / no-default inputs — `model` / `train_set` — stay `required`, via `mandatory_param_names`, mirroring the confluid I/O contract `input_specs.required`). litegraph renders both alike, so this extension marks each optional SOCKET slot on a `Taidal`-category node — a ` (optional)` label suffix (on the display `label`, never the functional `name`), a dimmed unconnected-dot colour, and a hollow slot shape when the build exposes `LiteGraph.HollowCircle`. It reads `nodeData.input.optional` in `beforeRegisterNodeDef` and re-applies on `onNodeCreated` / `onConnectionsChange` / `onConfigure` (so styling survives dynamic-slot rebuilds + graph load). It deliberately SKIPS the dynamic-list slots (`op_N` / `source_N` — their own add-more UX in `op_list.js` / `source_list.js`).
