# FluxStudio Mandates

- **Reuse DataFlux + Waivefront Surfaces:** FluxStudio is the GUI layer over DataFlux pipelines — it auto-generates ComfyUI nodes from callables already exposed by DataFlux / Waivefront (and HuggingFace `datasets`). Every node it surfaces MUST come from existing passive discovery — NEVER hand-define a FluxStudio-only node, op, or visualizer. If an op or visualization is missing, add it to dataflux / waivefront, not here. RF-domain ops stay in waivefront behind the optional `[waivefront]` extra so the core install stays lean — they appear in FluxStudio only when that extra is installed.
- **ComfyUI Extension, Not a Standalone Server:** FluxStudio is a ComfyUI custom node, not its own web service. The CLI (`fluxstudio.cli:main`) clones ComfyUI to `~/.fluxstudio/ComfyUI` on first run, symlinks this package into `ComfyUI/custom_nodes/fluxstudio`, and launches `python main.py` under the active interpreter (so ComfyUI runs in the same `.venv` whose metadata discovery reads). Do NOT reintroduce a bespoke FastAPI server, React/xyflow frontend, or in-house executor — extend behaviour through ComfyUI nodes and the `web/` extension directory instead. The old FastAPI server (`/api/{ops,visualizers,graph,run,...}`), `SteppingExecutor`, Confluid-YAML graph serialization, type→visualizer registry, and React frontend were removed in the v0.2.0 refactor; any `fluxstudio/api/`, `frontend/dist/`, or `frontend/node_modules/` left on disk are orphans, not live surface.
- **Entry-Point-Driven Node Discovery:** Nodes are discovered EXCLUSIVELY via the `confluid.configurables` entry-point group. `_discover_and_register_nodes()` (`fluxstudio/__init__.py`) enumerates that group and forwards each module to `register_module_nodes` (`fluxstudio/bridge.py`); each module is scanned by `dataflux.discovery.scan_module` and wrapped into a ComfyUI node class by `create_comfy_node`, keyed by `_node_key` as `Taidal_<package>_<category>[_<group>]_<callable>` (globally unique — see the unique-key mandate below) and displayed under a `Taidal/<Package>/<Category>[/<group>]` palette path (see the palette-path mandate below). A package's ops therefore appear ONLY if its declared entry points are present in the INSTALLED `*.dist-info` metadata.
- **Entry Points Live in Installed Metadata — Reinstall After Changing Them:** Because discovery reads `importlib.metadata.entry_points(...)`, editable installs FREEZE the entry-point metadata at install time. After adding or changing a `[project.entry-points."confluid.configurables"]` declaration in ANY workspace package, you MUST reinstall that editable (`aisland setup`, or plain `uv pip install -e ./<pkg>` in dependency order) or the nodes silently vanish from FluxStudio with no error — discovery just yields fewer entries. NEVER use `--reinstall` / `--force-reinstall` to force it: that re-resolves internal deps (confluid, logflow, …) from PyPI, where they don't exist, and fails. The canonical symptom of stale metadata is an empty or near-empty `Taidal/…` palette even though the source is current; confirm with `python -c "import importlib.metadata as m; print(len(list(m.entry_points(group='confluid.configurables'))))"`.
- **Discovery Degrades Gracefully (debug, not warning):** A module that fails to import or scan during discovery MUST be skipped at `logger.debug` level so one package's missing optional dependency never empties the whole node palette. Do NOT promote these skips to `warning`/`info`.
- **Type → ComfyUI Widget Mapping:** Node inputs and outputs are derived from each callable's signature by `_map_type` in `fluxstudio/bridge.py` — int/float/str/bool (incl. `Optional`/`Union` of these, unwrapped via string scan so numerics still get real INT/FLOAT/BOOLEAN widgets rather than a STRING the constructor chokes on) map to ComfyUI scalar widgets; `dataflux.sample.Sample` maps to the `DATAFLUX_SAMPLE` socket; `datasets.Dataset` to `HF_DATASET`; path-like params (`pathlib.Path`, or names containing path/dir/root/folder) to a directory-picker widget backed by `web/directory_chooser.js` and the `/taidal/choose_directory` ComfyUI route. New supported types MUST extend `TYPE_MAP` / `_map_type` rather than special-casing individual nodes.
- **Closed `Literal[...]` → Combo Dropdown (enumerate from the annotation, never restate):** A constructor param typed as a closed `typing.Literal[...]` (the workspace's preferred way to type a fixed, short value set — see the root "Prefer Closed `Literal`s" mandate; e.g. waivefront's `Colormap`) renders as a ComfyUI **combo** whose options ARE the literal's members. `_widget_for` (via `_literal_options`, which also unwraps `Optional[Literal[...]]`) returns `(options_list, {"default": …})` — ComfyUI's enumeration form, where the *list itself* is the "type". This is resolved BEFORE the name-based PATH / scalar heuristics (an explicit enum is the stronger signal), and `_coerce_kwargs` passes a Literal value through verbatim (never the STRING list/int heuristics — a member containing `int`/`list`/`float` must not be cast/split). The default is the param default when it is a member, else the first option. The SAME annotation drives navigaitor's form-spec (pydantic renders `Literal` as a JSON-Schema `enum` automatically) — one `Literal` upstream, both GUIs get a picker. To add a choice, edit the upstream `Literal` (e.g. `waivefront.visualizers.Colormap`), NEVER hard-code a parallel option list in the bridge or a node.
- **HuggingFace Dataset-ID Field (free text + cached picker, NOT a directory):** The dataset-identifier param of a HuggingFace dataset source is a *name* (a Hub repo id like `kitofrank/RFUAV`, or optionally a local imagefolder path) — NOT a filesystem directory, even though `dataflux.sources.HuggingFaceSource` names it `path`. `_widget_for` (gated by `_is_hf_dataset_id_param`) emits it as a free-text `STRING` tagged `taidal_widget="HF_DATASET_ID"` instead of the directory picker. `web/hf_dataset_chooser.js` adds an OPTIONAL combo populated from `GET /taidal/hf_datasets` (→ `list_cached_hf_datasets()` → `huggingface_hub.scan_cache_dir()`, dataset repos only); selecting an entry fills the text field, which stays editable for any Hub id. The gate is the `HuggingFace`-class-name convention (matches `HuggingFaceSource`, sonair's `HuggingFaceClassificationDataset`, and any future `HuggingFace*`), the `repo_id`/`path` param names — NOT a per-node special-case; a plain `path` on a non-HF source still gets the directory picker. Note `taidal_widget="HF_DATASET_ID"` (a STRING-field hint) is distinct from the `HF_DATASET` socket *type* used for `datasets.Dataset` wires.
- **HuggingFace Feature-Selector Fields (free text + column picker, populated from the SELECTED dataset):** A HuggingFace source's `input_feature` / `target_feature` (which dataset *column* maps onto `Sample.input` / `.target`) are free-text `STRING`s — but typed blind they're a frequent source of zero-yield bugs, so `_widget_for` (gated by `_is_hf_feature_param`, params `_HF_FEATURE_PARAMS = {input_feature, target_feature}`) tags them `taidal_widget="HF_FEATURE"` and `web/hf_feature_chooser.js` adds an OPTIONAL "columns" combo. It is the cached-dataset picker ONE LEVEL DOWN: the columns are fetched from `GET /taidal/hf_dataset_features?path=…&name=…&split=…` (→ `list_hf_dataset_features()` → `datasets.load_dataset_builder().info.features`, falling back to streaming one example; degrades to `[]` on ANY failure — convenience over a free-text field, must never break the editor) keyed off the node's CURRENT dataset-id (`HF_DATASET_ID`) field, so the column list always reflects the chosen dataset. The combo refreshes when the dataset id / `name` / `split` widget changes — including when the cached-dataset picker fills the id field (it now fires that widget's `callback` after setting it, so dependents react to the programmatic change). Same `HuggingFace*` class-name gate as the dataset-id field — NOT a per-node special-case; a like-named param on a non-HF class is unaffected. Column order is preserved (input vs target read more naturally than alphabetical). Scope is the two scalar feature params; `metadata_features` (a list) is deliberately left as the comma-separated STRING (a multi-select / opt-in `"*"`=the-rest is a planned follow-up).
- **HuggingFace Split Field (free text + split picker; NOT the `DatasetSplit.split` Literal):** A HuggingFace source's `split` stays a free-text `STRING` — HF accepts slice syntax (`train[:90%]` / `train+test`) a closed dropdown can't express — so `_widget_for` (gated by `_is_hf_split_param`, param `_HF_SPLIT_PARAM = "split"`) tags it `taidal_widget="HF_SPLIT"` and `web/hf_split_chooser.js` adds an OPTIONAL "splits" combo fetched from `GET /taidal/hf_dataset_splits?path=…&name=…` (→ `list_hf_dataset_splits()` → `datasets.get_dataset_split_names`, metadata-only; `[]` on ANY failure) keyed off the node's current `HF_DATASET_ID` field; refreshes on dataset id / `name` change (incl. the cached-dataset pick cascade). CRUCIAL distinction: this is gated on the `HuggingFace*` class-name convention so it catches ONLY `HuggingFaceSource.split`. `DatasetSplit.split` is a DIFFERENT concept — a closed `Literal["train","val","test"]` fraction-view selector on a non-HuggingFace class — and is ALREADY a combo via `_literal_options`; the HF gate deliberately leaves it untouched. Don't merge the two.
- **HuggingFace Metadata-Columns Field (multi-select append + `*`):** A HuggingFace source's `metadata_features` is a `List[str]` (which columns ride onto `Sample.metadata`). It stays a comma-separated `STRING` (`_coerce_kwargs` splits it into the list; empty ⇒ `None` ⇒ no extra metadata) tagged `taidal_widget="HF_METADATA"` (gated by `_is_hf_metadata_param`, param `_HF_METADATA_PARAM = "metadata_features"`). ComfyUI has NO native multi-select, so `web/hf_metadata_chooser.js` adds an "add column" combo that APPENDS the picked column (pick repeatedly to build the list — the field stays editable). Options reuse the feature route (`GET /taidal/hf_dataset_features`) but EXCLUDE the current `input_feature`/`target_feature` values and prepend a `*` entry = "every column except input/target" — the `dataflux.sources.METADATA_ALL_FEATURES` sentinel the LIBRARY resolves at load (NOT here; the GUI only writes the literal `*`). Picking `*` is exclusive (already means "the rest"). Refreshes on dataset id / `name` / `split` AND input/target-feature change (the exclusion set). The "default = the rest" behaviour lives in `dataflux` (opt-in via `*`), never as GUI-only magic — keep library and GUI consistent on the one sentinel.
- **Display Names Are Verbatim; Private Callables Are Hidden:** `register_module_nodes` labels each node via `_humanize_node_name` = `name.replace("_", " ")` — NEVER `str.title()` (it lowercases CamelCase tails: `HuggingFaceSource` → `Huggingfacesource`). Capitals are preserved as written. `scan_module` returns every module-local callable, so `register_module_nodes` SKIPS names starting with `_` (internal helpers like `_to_uint8` / `_worker_task` are not user-facing nodes and would otherwise clutter the palette as generic STRING nodes).
- **Node Discovery Is a POSITIVE Category Allowlist (`_NODE_CATEGORIES = {op, source, engine}`):** `register_module_nodes` registers a discovered class as a node ONLY if `getattr(cls, "__confluid_category__", None) in _NODE_CATEGORIES`. So the palette is *exactly* the deliberately-tagged ops/sources/engines. Excluded **by construction** (no negative special-casing): the raw-callable op wrappers (`FilterOp`/`WrappedOp` — UNcategorised bare `@configurable`, see below — so they stay out even though `engine` is now allowed); task `*_dataset` classes (see *Source vs Dataset* below); uncategorised module-level helper *functions* (`sample_to_image`, `value_to_image`, …); and raw sinks (`JsonSink`/`JsonPerWindowSink`/… are uncategorised — the old `PlotSink`/`SpectrogramSink` are gone, replaced by the `ConvertToImageOp`/`RenderOverlaysOp`/`RenderSignalPlotOp` ops). `_`-private names are still skipped explicitly (belt-and-suspenders). **Consequence:** an op/source/engine that loses (or never gets) its tag silently vanishes — fix it by tagging the class in dataflux/waivefront, NEVER by special-casing the bridge. To surface another role, add its category to `_NODE_CATEGORIES` and tag the classes. **Beyond the category allowlist, `register_module_nodes` ALSO admits two interface/role classes** (see the *Runnable Nodes* + *Object Member Nodes* mandates): a class implementing the **run interface** (`_is_runnable` — a no-arg `run(self)`: trainers / evaluators / `DatasetProcessor`) and a runnable **member** class (a task `role="dataset"` → Source node; `role` ∈ `{model, loss, metric}` OR the confluid `lazy` mark `__confluid_lazy__` → OBJECT node). These are category-less or deliberately non-canvas-tagged; they're admitted by interface/role/lazy-mark, not by `_NODE_CATEGORIES`.
- **Runnable Nodes — trainers / evaluators / processors as build-only canvas nodes (members are wired sockets):** A class implementing the **run interface** (`_is_runnable`: a no-arg `run(self)`) becomes a buildable node via `_build_runnable_node`. It enumerates the runnable's FULL configurable surface from `to_pydantic(cls)` (ctor params AND `__init__`-body slots — the confluid `_post_init_field_specs` scan; `@ignore_config` members are skipped) and renders each member as: a **`DATAFLUX_SOURCE`** socket (dataset/source members — `_DATASET_MEMBER_PARAMS = {train_set, val_set, test_set, dataset}` + the `source` param), a **`DATAFLUX_OBJECT`** socket (any other non-scalar member — model / loss / optimizer / loaders / lightning / metrics — via `_is_scalar_anno`), or a **widget** (scalars: `num_classes` / `max_epochs` / `experiment_name` …, through the shared `_build_config_inputs`; ComfyUI's "convert to input" covers the rare wire). A member that is a ctor param with NO default is a REQUIRED socket (`model` / `train_set`); everything else is OPTIONAL — unwired ⇒ the runnable keeps its baked default ("true optional"). The node is **build-only**: `execute` constructs the runnable (ctor params → `__init__`, body slots via post-construction `setattr` of the wired members) and outputs it on a **`DATAFLUX_RUNNABLE`** wire (`kind="runnable"`); it does NOT run training. A scalar body slot MUST be annotated (`self.x: bool = …`) or it reads as `Any` → an OBJECT socket; real trainers annotate their slots. Member detection is by ANNOTATION/name (never per-class). Pins: `tests/test_bridge.py::test_build_runnable_node_member_sockets_and_widgets`.
- **Object Member Nodes Have TWO Outputs (`instance` + `lazy`):** A runnable's member classes become `DATAFLUX_OBJECT` producers via `_build_object_node` (`kind="object"`): config widgets → **two** `DATAFLUX_OBJECT` outputs, `instance` (the flowed, live object built right here via `confluid.flow`) and `lazy` (a deferred `LazyClass`). A runnable slot accepts either (`flow` is idempotent on a live instance): wire **`instance`** for a fully-configured standalone object; wire **`lazy`** when a value is only known at `run()` (`torch.optim.*.params` / `DataLoader.dataset`, or a model's dataset-derived `num_classes`) so the runnable flows it with the runtime kwarg. A member is detected as `role∈{model,loss,metric}` OR confluid **`lazy`** (`__confluid_lazy__`, set by `@configurable(lazy=True)` / `register(..., lazy=True)`). A `lazy` member SKIPS the runtime-injected required params (`torch.optim.*.params`, `DataLoader.dataset`) so only the configurable knobs (lr / batch_size) are widgets; because those params are missing by design, its `instance` output is `None` (logged at `debug`, NOT a warning — that's expected) and only `lazy` is usable. For a non-deferred member whose live build simply **fails** on an incomplete/invalid config (e.g. a model node left without `num_classes`), `instance` is `None` and `_build_object_node` emits an **actionable `warning`** ("could not build a live instance …") — ComfyUI tolerates the `None` socket; downstream nodes that need the instance fail legibly on use. Task `role="dataset"` classes are routed to `_build_source_node` (datasets are Sources, not objects). The select runtime members (`torch.optim.Adam`/`AdamW`/`SGD`, `DataLoader`, `pytorch_lightning.Trainer`) are `register(..., lazy=True, group=…)`-ed in **`marainer.configurables`** (entry-pointed; re-exported via `__all__`) — **deliberately with NO `category`** (only a presentation-only `group`), so they're FluxStudio object nodes via the `lazy` mark WITHOUT leaking into navigaitor's category-driven form-spec slot pickers (which would then offer the raw `params`-taking optimizer instead of navigaitor's curated infra config). Register the class upstream + mark it `lazy`, NEVER hand-build a member node here. NOTE: the second output changes saved-workflow output indices — a workflow wiring the old single object output (index 0 = the `LazyClass`) must be re-pointed (index 0 is now `instance`, index 1 is `lazy`). Pins: `tests/test_bridge.py` (object node dual output / deferred / build-warning).
- **`RunNode` Restores Autograd for `TorchRunner`s (ComfyUI runs under `inference_mode`):** The hand-written **`RunNode`** (`Taidal_Run`, in `nodes.py`) is the terminal `OUTPUT_NODE` that calls `.run()` on a wired `DATAFLUX_RUNNABLE` (the build/run split keeps the canvas cheap). ComfyUI evaluates the whole graph under `torch.inference_mode()` (`execution.py`), which is fatal for **gradient-based training**: model params (model nodes are lazy → the backbone is built *inside* `run()`), forward activations, and the loss all become inference tensors with no autograd graph, so `loss.backward()` dies with *"element 0 of tensors does not require grad and does not have a grad_fn"*. So `RunNode` re-enables normal autograd (`with torch.inference_mode(False), torch.enable_grad():`) ONLY for a runnable that declares itself a **`marainer.TorchRunner`** (duck-typed `__torch_runner__` flag — no hard `marainer` import). Inference-only runnables (`LightningEvaluator`, `DatasetProcessor`) leave the flag unset and run as-is under ComfyUI's inference mode. This is why model nodes being **lazy** matters: the backbone is constructed inside the grad-restored `run()`, not earlier in the object node's `execute` (which still runs under `inference_mode`). Pins: `tests/test_nodes.py::test_run_node_*`.
- **`RunNode` Is Interruptible (worker thread + injected `KeyboardInterrupt`):** ComfyUI only polls its interrupt flag BETWEEN nodes, but `RunNode.run()` is ONE blocking `.run()` call that can run for minutes/hours — so the interrupt button would otherwise be ignored until the sweep finished. `run()` therefore executes the runnable on a **daemon worker thread** and polls `_processing_interrupted()` (a lazy, guarded `comfy.model_management.processing_interrupted()` — `False` when comfy is absent, so fluxstudio's own tests/dev runs are unaffected) from the calling thread every 0.1 s; when the flag goes high it injects a `KeyboardInterrupt` into the worker via CPython's `PyThreadState_SetAsyncExc` (`_raise_interrupt_in_thread`) and re-raises ComfyUI's `InterruptProcessingException` for a clean stop (no traceback, UI reset). PyTorch Lightning catches `KeyboardInterrupt` for a graceful shutdown; `DatasetProcessor` / Flux iteration loops simply unwind. **Grad/inference mode is thread-local**, so the worker does NOT inherit the `torch.inference_mode()` ComfyUI wraps graph execution in — `run()` captures `torch.is_inference_mode_enabled()` on the calling thread and the worker re-establishes the correct context itself (grad-restored for `__torch_runner__`s, `inference_mode()` re-entered for inference-only runnables). The injection lands at a Python statement boundary (between batches / samples), so a single long-running C kernel is not interruptible — an accepted limitation. This keeps ALL ComfyUI/interrupt knowledge in fluxstudio; marainer/dataflux are untouched (per marainer's `TorchRunner` mandate). Pins: `tests/test_nodes.py::test_run_node_interrupt_*`, `test_run_node_grad_context_is_active_inside_worker_thread`.
- **Discovery Has Two Passes (scan_module + `__all__` re-exports):** `scan_module` returns only callables whose `__module__` IS the scanned module — which misses a package's SUBMODULE classes re-exported in its `__init__` (`sonair` re-exports `LightningClassificationTrainer` from `sonair.trainer`) AND registered third-party members (`marainer.configurables`'s `torch`/`pl` classes, `__module__` = `torch`/`pytorch_lightning`). So `register_module_nodes` runs a **second pass** over the module's `__all__`: any `@configurable` class listed there is also a candidate (gated on `__all__` so imported-for-use configurables don't leak into the palette). This is why a package whose entry point points at the package root (`sonair = "sonair"`) still surfaces its submodule classes — provided they're in `__all__`. A new runnable/member exposed from a package MUST be in that package's `__all__`.
- **Discovery Is One-Shot Per Process (double-import guard):** FluxStudio is imported under TWO module identities — editable-installed as `fluxstudio` AND symlinked into ComfyUI's `custom_nodes/` (and the package's own `from fluxstudio.bridge import …` triggers the top-level import from inside the custom-node import) — so `__init__` runs twice. `_discover_and_register_nodes` therefore **scans once** (caching the discovered mappings on the `sys` singleton, shared across identities) and, on any later call, copies the cached mappings into that identity's `NODE_CLASS_MAPPINGS` — so whichever `fluxstudio` ComfyUI reads still gets the full set while the scan + "Scanning module …" logs happen exactly once. A per-call `seen` set also dedups duplicate entry points. Don't remove the guard to "simplify"; the double-scan returns. Pins: `tests/test_init_discovery.py::test_discover_is_one_shot_per_process`.
- **Engines Are Canvas-Composable Via Wired Source/Op Sockets; Raw-Callable Wrappers Stay Uncategorised:** `category="engine"` covers the composition primitives `Flux`/`JointFlux` (and `DatasetSplit`, now a `source`). They ARE buildable on a canvas: `_build_source_node` renders their source-typed constructor params as WIRED sockets instead of STRING widgets — a single `source` → one `DATAFLUX_SOURCE` input (`_source_param`: `DatasetSplit.source`/`Flux.source`; required socket when the ctor param has no default, else optional), a source-list (`fluxes`/`sources`, `_source_list_param`) → dynamic `source_N` `DATAFLUX_SOURCE` inputs grown by `web/source_list.js` (`JointFlux.fluxes`), an op-list (`ops`/`branches`, `_op_list_param`) → dynamic `op_N` `DATAFLUX_OP` inputs grown by `web/op_list.js` (`Flux.ops`). `execute` collects the dynamic inputs (`_collect_sources`/`_collect_ops`) + the single `source` kwarg, constructs, and wraps the result in a `Flux`. Detection is by param NAME (the same convention as `_OP_LIST_PARAMS`), never per-class. This is the consuming half of "a Source/Op node already outputs ITSELF" — Source nodes output `DATAFLUX_SOURCE`, op nodes their `op` on `DATAFLUX_OP`. The raw-callable op wrappers `FilterOp(p)`/`WrappedOp(f)` are NOT engines — they are bare `@configurable` (UNcategorised), excluded because their constructor takes a raw Python callable, nothing a widget OR a `DATAFLUX_OP` socket can supply; they stay out of the palette (correct — not buildable). NOTE: `export.py` ops-export still targets linear op chains only — engine-node graphs and `source`/`source_N` links are not exportable (like `op_*` links, they'd raise `UnsupportedTopologyError`).
- **Source vs Dataset (a `source` is a canvas node; a task `dataset` is not):** A `category="source"` is a task-agnostic Sample producer (`HuggingFaceSource`, `RFUAVSource`, `RegionsJsonSource`) — the head of a DataFlux pipeline, and exactly what a canvas needs to Walk/Extract/visualize. A task `dataset` (e.g. sonair's `HuggingFaceClassificationDataset`, tagged `task="classification", role="dataset"` ⇒ `category="classification_dataset"`) is a task-scoped, model-ready dataset that fills a *trainer's* `dataset` slot — meaningful to navigaitor's config composition (which must offer only task-compatible datasets), but NOT to a per-sample canvas. So `dataset` is deliberately NOT in `_NODE_CATEGORIES`; the canvas data origin is always a `source`.
- **Palette Path Is `Taidal/<Package>/<Category>[/<group>]`:** `register_module_nodes` builds each node's ComfyUI `CATEGORY` via `_node_category` (`fluxstudio/bridge.py`): the FIRST level is the entry-point module's TOP-LEVEL package mapped through `_PACKAGE_DISPLAY_NAMES` (canonical casing — `dataflux` → `DataFlux`, `fluxstudio` → `FluxStudio`; unlisted packages fall back to `str.title()`), so every op/source of a package collects under one folder regardless of submodule. Within that it splits by `@configurable` category (`Op`/`Source`) then by the optional path-like `group` from `__confluid_group__` (`numpy` / `targets` / `fft/numpy` …). An untagged group leaves the node directly under `<Package>/<Category>`. **`group` is presentation-only** — it does NOT gate discovery (that's `category`) and is NOT part of the navigaitor `task`/`role` contract; set it in the upstream class's `@configurable(..., group="…")`, NEVER hand-build a palette path in the bridge. Add a package's canonical casing to `_PACKAGE_DISPLAY_NAMES` when `str.title()` would mangle it.
- **Registration Key Is Globally Unique (`_node_key`), NOT Just the Class Name:** ComfyUI identifies a node TYPE by its key in `NODE_CLASS_MAPPINGS` — its display `CATEGORY` folder does NOT make it unique. A plain `Taidal_<ClassName>` collides whenever two modules expose a same-named class (the canonical case: `dataflux.ops.numpy:RescaleOp` AND `dataflux.ops.torch:RescaleOp`, likewise `StandardizeOp`) — the second registration silently overwrites the first and one node disappears from the palette. `register_module_nodes` therefore keys via `_node_key` = `Taidal_<package>_<category>[_<group-segments>]_<callable>` (e.g. `Taidal_dataflux_op_numpy_RescaleOp` vs `Taidal_dataflux_op_torch_RescaleOp`). The key is built from RAW identifiers (top-level package, lowercase category, literal group) NOT the display-cased palette path, so it stays stable if `_PACKAGE_DISPLAY_NAMES` casing changes; the DISPLAY name stays the verbatim class name (so both still read "RescaleOp" in their folders). The hand-written adapter nodes in `nodes.py` keep their own literal keys (`Taidal_WalkDataset` / `Taidal_ExtractSample`). NOTE: this changes saved-workflow `class_type` strings for auto-discovered nodes — an older workflow referencing `Taidal_RescaleOp` must be re-pointed at the qualified key.
- **Widget Tooltips Come From the Docstring `Args:` (never hand-written here):** `_build_config_inputs` sets each widget's `tooltip` from the callable's docstring `Args:` block via `confluid.parse_param_docs` — the SAME per-parameter help navigaitor surfaces as pydantic `Field(description=...)` in its form-spec. Document a constructor parameter ONCE in the upstream class's `Args:` and it appears as a hover tooltip here AND in the navigaitor editor. An undocumented param simply gets no tooltip — the fix is to add the `Args:` entry in dataflux/waivefront, NEVER to hand-write a tooltip in the bridge.
- **Typed Node Classification (Source / Op / Generic):** `create_comfy_node` classifies each discovered callable so a pipeline wires by TYPE, not opaque STRING: a `Sample`-yielding source class (`__getitem__`/`__iter__` → `Sample`) becomes a `-> DATAFLUX_SOURCE` node (constructor config as widgets, output a `Flux`); a `@configurable` op class with `__call__(self, sample: Sample) -> Optional[Sample]` becomes a **dual-mode** op node (config widgets + an OPTIONAL `sample` socket → a `sample` applied-output AND an `op` `DATAFLUX_OP` output — see *Ops Are Dual-Mode* below); everything else stays a generic scalar/STRING node. `DATAFLUX_SOURCE` / `DATAFLUX_SAMPLE` / `DATAFLUX_OP` are FluxStudio socket type strings carrying the live `Flux` / `Sample` / op objects. When you add a new DataFlux/Waivefront source or op that should chain, make sure its `__getitem__`/`__iter__`/`__call__` is annotated with `Sample` so the classifier picks the right shape — do NOT add per-node special-cases to the bridge.
- **Ops Are Dual-Mode (apply via `DATAFLUX_SAMPLE` AND expose via `DATAFLUX_OP`):** `_build_op_node` builds every op node with an OPTIONAL `sample` input and TWO outputs — `sample` (the op applied to the input, for linear chaining) and `op` (the constructed op as a `DATAFLUX_OP` value). Wire `sample → sample` to chain inline (today's UX); leave `sample` unconnected and take the `op` output to use the node as an op-VALUE. `execute` constructs the op once and returns `(op(sample) if sample is not None else None, op)`. A **higher-order op** — one whose constructor has an op-list param (`_op_list_param`: `ops`/`branches`, list-annotated → `Enable`/`Parallel`/`Tee`) — does NOT render that param as a STRING widget; instead it gets dynamic `DATAFLUX_OP` inputs (`op_0`, `op_1`, … grown by `web/op_list.js`), and `execute` collects them (`_collect_ops`, index-ordered, drops empties) into the list before constructing. `Tee.branches` (list-of-lists) v1 wraps each connected op as its own 1-op branch (multi-op branches → pre-compose, deferred). Detect op-list params by the `ops`/`branches` naming + `List` annotation — NEVER per-class. NOTE this keeps `bridge.export`'s `TAIDAL_NODE_KIND`/`TAIDAL_CALLABLE_PATH` + the `sample`-link chain intact; the op-list topology is simply not yet exportable (export raises `UnsupportedTopologyError` on the `op_*` links — a future export extension).
- **Adapter Nodes Are Glue, Rendering Lives in Waivefront:** The statically-defined nodes in `fluxstudio/nodes.py` — `WalkDatasetNode` (`DATAFLUX_SOURCE` + auto-incrementing `index` via ComfyUI's `control_after_generate` → the `Sample` at `source[index]`) and `SampleExtractorNode` (a `DATAFLUX_SAMPLE` + `field` selector → typed `IMAGE`/`MASK`/`STRING`/`INT`/`FLOAT` sockets) — are ComfyUI orchestration/adapter glue, NOT DataFlux data ops, so they may live here. `SampleExtractorNode` is deliberately NOT an `OUTPUT_NODE`: it extracts/unpacks a Sample field onto typed sockets and lets NATIVE ComfyUI nodes (Preview Image, text/number displays) do the viewing — do not re-add a bespoke in-canvas viewer (the removed `SampleViewerNode`). The relevant socket is chosen from the sample's features via `Sample.describe()` (ComfyUI can't retype a socket per run, so all plausible types are surfaced — see *Typed Sample extraction* below). The actual image-rendering logic MUST stay in waivefront (`waivefront.visualizers.value_to_image`, with `sample_to_image` a thin wrapper); the node only bridges its `(H,W,3) uint8` output to ComfyUI's `IMAGE` tensor protocol (`[1,H,W,3]` float) and a 2-D field to the `MASK` protocol (`[1,H,W]` float). This is the one sanctioned exception to "no FluxStudio-only nodes": adapters that translate ComfyUI's execution model are allowed; data ops and visualizers are not.
- **Typed Sample Extraction (derive the socket from features, never hand-render):** `SampleExtractorNode` exposes a Sample's `input`/`target` on the fixed socket set `IMAGE`/`MASK`/`STRING`/`INT`/`FLOAT` and the user wires the one matching their viewer. Because ComfyUI sockets are statically typed at registration, the node CANNOT change a socket's type per run — so it surfaces every plausible type and derives *which is meaningful* from `Sample.describe()` (stored `__features__`/`__spec__`, else inferred). When the value isn't applicable to a socket it returns a benign placeholder (a text-rendered `IMAGE`, an empty `1×1` `MASK`, `0`/`0.0`), since ComfyUI requires every declared output be returned each run. If you need a new view type, add a socket here AND back its rendering with a waivefront helper — never hand-roll pixels in the bridge/node.
- **Type-Spec Connection Filtering (socket strings stay generic):** A Sample wire ALWAYS keeps the `DATAFLUX_SAMPLE` socket string — do NOT encode the DataFlux type into finer socket strings (ComfyUI matches sockets by string equality, which can't express ranges/dtype-families/Union). Instead the richer contract is layered on top, sourced from each op/source's `ACCEPTS`/`PRODUCES` (declared in dataflux/waivefront, never here): (1) `create_comfy_node` stashes `TAIDAL_ACCEPTS` / `TAIDAL_PRODUCES` (`SampleType.to_dict()` or `None`) on the generated node class; (2) a generated op node's `execute()` runs a **runtime accept-check** (`infer_sample_type(sample)` vs `cls.ACCEPTS`) and raises a legible error on mismatch — this is AUTHORITATIVE; (3) the `/taidal/node_specs` route + `web/connection_validator.js` reject incompatible Sample wires live on the canvas via litegraph's `onConnectInput` — this is ADVISORY (drag-drop only). The JS matcher is a faithful port of `dataflux.typespec.compatible()` (permissive: `Any`/unknown passes); keep it in sync with the Python and cover the semantics in `dataflux/tests/test_typespec.py`. Never hand-define type specs in FluxStudio — if a contract is wrong or missing, fix the op's `ACCEPTS`/`PRODUCES` in dataflux/waivefront.
- **Ops Export Is a Faithful Translator, Not an Optimizer (`fluxstudio/export.py`):** A canvas graph's OPS (dropping the source + Walk/Extract adapters) compile to a Confluid `{ops: [!class:…()]}` YAML — the inverse of how the canvas builds a pipeline — consumed by `Flux.from_ops_yaml` / `confluid.materialize(confluid.load(path)["ops"])`. The SINGLE compiler `export.export_ops_yaml(prompt, NODE_CLASS_MAPPINGS)` is shared by BOTH the `/taidal/export_ops` POST route (canvas button `web/export_ops.js`) and the `fluxstudio export <graph.json>` CLI — never fork it. Input is the ComfyUI **prompt / API-format** graph (`{node_id: {class_type, inputs}}`), NOT the UI `workflow.json`. The compiler relies on two class attrs stamped by `bridge._node_class`: `TAIDAL_NODE_KIND` (`"op"` / `"source"` / `"generic"`) picks out the op nodes, and `TAIDAL_CALLABLE_PATH` (importable `module:qualname`) recovers each op's class to re-emit as a `!class:` marker — these join the existing `TAIDAL_ACCEPTS`/`TAIDAL_PRODUCES`; preserve them on any new node builder. **Scope (v1):** linear chains + **fan-out** (one op output → ≥2 op nodes) → `dataflux.ops.tee.Tee` (each branch a nested op-list — `Tee.branches` is recursive). It does NOT auto-insert `Copy`/`Stash` for branch isolation — the user wires those op nodes explicitly. Fan-in (multi-input merge), multiple disconnected chains, cycles, an unresolvable op, and a widget input driven by a link all raise `UnsupportedTopologyError` (HTTP 400 from the route). **Consumer caveat:** `confluid.load` leaves `!class:` markers nested under a mapping key deferred, and `Flux` rejects deferred markers at iteration by design — so the op-list MUST be run through `confluid.materialize` (which `Flux.from_ops_yaml` does) before attaching; a bare `load(...)["ops"]` is not enough.
- **Whole-Graph YAML ↔ workflow.json Is a Faithful Translator Too (`fluxstudio/graphio.py`):** `graphio` is the WHOLE-config sibling of `export.py` (a SEPARATE compiler for a different artifact — the full UI `workflow.json`, not the ops-only op-list; both are shared by their own route+CLI, neither forks the other). `yaml_to_workflow` / `workflow_to_yaml` convert a Confluid YAML (sources / ops / object members / the runnable + wiring) ↔ a ComfyUI workflow. The **Fluid graph is the shared IR**: confluid owns YAML↔Fluid (`resolve`/`dump`/`load`), graphio owns Fluid↔`workflow.json` — it works WITHOUT a running ComfyUI (reads only `NODE_CLASS_MAPPINGS`). **Import** broadcast-resolves with `confluid.resolve` (un-instantiated markers — uniform `Class`/`Instance`/`Lazy` with `.target`+`.kwargs`, `!ref:` shared by identity ⇒ fan-out = one node + many out-links); `instantiate=True` walks live-but-inert objects from `confluid.load(..., solidify=False)` instead (same `_target_and_kwargs` abstraction; `solidify=False` suppresses the expensive finalize like a model backbone). It reuses the bridge primitives verbatim (`TAIDAL_CALLABLE_PATH`→`resolve_callable` reverse index, `_coerce_kwargs`, `_SOCKET_TYPES`, `_collect_ops`/`_collect_sources`, `_OP_LIST_PARAMS`/`_SOURCE_LIST_PARAMS`) — preserve those stamps on any new node builder. **Export** is the hoisted-`!ref:` shape (matches navigaitor / the hand-written reference configs): every node → a top-level key named by the socket it feeds (path-prefixed on collision; a runnable root by its `__confluid_role__` — `trainer`/`evaluator`), a wire → a `confluid.Reference` (`!ref:`), shared scalar dims (`num_classes`/`image_size`) hoisted; ONLY non-default widget values are kept (import fills every widget position; a default-valued one wasn't explicitly set — this also discards bridge-unrepresentable params like tuple defaults). The **wired output slot is authoritative** for an object node's eager/lazy-ness: consumed via `lazy` (slot 1) → `!lazy:`, via `instance` (slot 0) → `!class:` — so a `!lazy:` model wires off the object node's lazy output and round-trips. A `collate_fn`-style callable param round-trips as `!ref:dotted.path` (`_REF_FIELDS`). Round-trip is **semantic** (topology+kwargs+kinds), not byte-exact — positions are re-derived by a deterministic layered layout. The FOUR canvas commands live under the **Taidal** menu (`web/import_yaml.js` "Import Taidal YAML → Graph/Subgraph/Group", `web/export_workflow.js` "Export Graph → Taidal YAML") + routes `/taidal/import_yaml` · `/taidal/export_workflow` + CLI `fluxstudio import` / `export-workflow` — all share the graphio functions, never fork. **Subgraphs/groups:** `as_="group"` wraps nodes in one `groups[]` box (presentation-only, dropped on export); `as_="subgraph"` packages them as a `definitions.subgraphs[]` blueprint — boundary inference per the approved convention (an unresolved `!ref:NAME` → an INPUT socket named `NAME` wired from `inputNode` id `-10`; a pipeline root → an OUTPUT socket to `outputNode` id `-20`); export inlines a saved subgraph back into the flat YAML (standalone `include:` files are a follow-up). **v1 limits (documented in README, not silent):** a config member with NO FluxStudio node (e.g. torchmetrics `MetricCollection`) is dropped-with-warning on import (the runnable keeps its default — surface it by tagging/registering upstream, as the loggers + base `LightningTrainer`/`LightningEvaluator` are in `marainer.configurables`); a `List`-valued member (`logger:`) wires only its first element (single-socket list-gap → dynamic `logger_N` is a follow-up).
