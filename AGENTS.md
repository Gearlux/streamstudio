# FluxStudio Mandates

- **Reuse DataFlux + Waivefront Surfaces:** FluxStudio is the GUI layer over DataFlux pipelines — it auto-generates ComfyUI nodes from callables already exposed by DataFlux / Waivefront (and HuggingFace `datasets`). Every node it surfaces MUST come from existing passive discovery — NEVER hand-define a FluxStudio-only node, op, or visualizer. If an op or visualization is missing, add it to dataflux / waivefront, not here. RF-domain ops stay in waivefront behind the optional `[waivefront]` extra so the core install stays lean — they appear in FluxStudio only when that extra is installed.
- **ComfyUI Extension, Not a Standalone Server:** FluxStudio is a ComfyUI custom node, not its own web service. The CLI (`fluxstudio.cli:main`) clones ComfyUI to `~/.fluxstudio/ComfyUI` on first run, symlinks this package into `ComfyUI/custom_nodes/fluxstudio`, and launches `python main.py` under the active interpreter (so ComfyUI runs in the same `.venv` whose metadata discovery reads). Do NOT reintroduce a bespoke FastAPI server, React/xyflow frontend, or in-house executor — extend behaviour through ComfyUI nodes and the `web/` extension directory instead. The old FastAPI server (`/api/{ops,visualizers,graph,run,...}`), `SteppingExecutor`, Confluid-YAML graph serialization, type→visualizer registry, and React frontend were removed in the v0.2.0 refactor; any `fluxstudio/api/`, `frontend/dist/`, or `frontend/node_modules/` left on disk are orphans, not live surface.
- **Launcher Seeds Custom Nodes (entry-point-declared incl. bundled ComfyUI-Manager; extras via flag/env; idempotent; never blocks launch):** On EVERY `run` (not just the first clone), `cli._install_custom_nodes` clones custom-node repos into `ComfyUI/custom_nodes/` and pip-installs each repo's `requirements.txt` into the ACTIVE interpreter (the same env ComfyUI runs in). URLs come from THREE tiers, deduped in order **declared → env → flags**: (1) the **`fluxstudio.custom_nodes` entry-point group** (`cli.CUSTOM_NODES_ENTRY_POINT_GROUP`, read by `_declared_custom_nodes`) — ANY installed package declares "generally available" nodes by pointing an entry point at a git-URL `str` or iterable of them; **fluxstudio's own declaration is `fluxstudio/custom_nodes.py:CUSTOM_NODE_URLS`** (wired in `pyproject.toml`), which bundles **ComfyUI-Manager** (`COMFYUI_MANAGER_URL`, canonical `Comfy-Org/ComfyUI-Manager`, re-exported by `cli`). To bundle another node with fluxstudio, append to that tuple — tuple edits need NO reinstall (loaded at launch), but adding/renaming an entry point DOES (installed `*.dist-info` metadata — same staleness gotcha as `confluid.configurables`; pinned by `test_fluxstudio_declares_manager_via_entry_point`, which fails on a stale editable). A broken declaration (load error / wrong type / non-str item) logs an actionable `warning` and is skipped. `--no-declared-nodes` skips the whole tier; `--no-manager` filters ONLY the manager URL and ONLY from the declared tier (an explicit env/flag request for it is the stronger signal and still installs). (2) the `FLUXSTUDIO_CUSTOM_NODES` env var (comma-separated git URLs, blanks dropped via `_env_custom_nodes`); (3) the repeatable `--custom-node <git-url>` flag. ComfyUI-Manager is the sanctioned in-GUI way to install/update/remove further nodes, which is why the launcher only SEEDS: a repo whose target directory (`custom_nodes/<url-basename-minus-.git>`, via `_custom_node_dir_name`) already exists is SKIPPED (`debug` log) — never re-cloned, never `git pull`-ed (updates are ComfyUI-Manager's job; don't add auto-update logic here). A clone or pip failure of ONE node logs an actionable `warning` and CONTINUES (both the loop and the launch) — a broken/unreachable custom node must never block the studio; only the ComfyUI clone itself stays fatal (`check=True` uncaught). Keep these semantics when touching `_run`: the install runs AFTER the clone-or-reuse step and BEFORE the fluxstudio symlink, and `--manager`/`--declared-nodes`/`--custom-node` follow the established launcher-flag pattern (top-level argparse flags, like `--default-nodes`). Tests pin the tier hermetically: an autouse fixture fakes `cli.entry_points` to fluxstudio's own declaration so ambient venv packages can't leak into call-count assertions. Pins: `tests/test_cli.py` custom-node + entry-point blocks (`test_main_installs_comfyui_manager_by_default`, `test_custom_node_flag_and_env_combine`, `test_fluxstudio_declares_manager_via_entry_point`, `test_declared_custom_nodes_*`, `test_main_no_declared_nodes_skips_package_declared_tier`, `test_no_manager_filters_declared_tier_only`, dedup / skip / clone-failure / pip-failure tests).
- **Console Coloring Defaults OFF:** `fluxstudio/__init__.py` calls `logflow.force_no_color()` near the TOP — after `import logflow` but before `from logflow import get_logger` and the `fluxstudio.*` submodule imports that transitively pull logflow in — because FluxStudio's logs land in ComfyUI's own console/log capture where ANSI escapes are noise. Inheriting/copying the env var is NOT enough: once logflow's console sink exists its colorize is baked, so if any earlier ComfyUI import already configured logflow the env change is ignored — `force_no_color()` sets the standard `NO_COLOR=1` AND reloads logflow if it was already configured. It MUST precede those logflow-pulling imports (so the not-yet-configured path also picks it up), which means they legitimately follow a statement; `setup.cfg` carries a `per-file-ignores: fluxstudio/__init__.py: E402` for exactly this (don't "fix" the E402 by moving the call below the imports — that defeats it). `NO_COLOR` is the only color env var (no bespoke `LOGFLOW_COLORIZE`); to re-allow colors pre-set `NO_COLOR=` (empty). Pin: `tests/test_logflow_colorize_default.py` (asserts colorless even when logflow was pre-configured WITH colors).
- **Entry-Point-Driven Node Discovery:** Nodes are discovered EXCLUSIVELY via the `confluid.configurables` entry-point group. `_discover_and_register_nodes()` (`fluxstudio/__init__.py`) enumerates that group and forwards each module to `register_module_nodes` (`fluxstudio/bridge.py`); each module is scanned by `dataflux.discovery.scan_module` and wrapped into a ComfyUI node class by `create_comfy_node`, keyed by `_node_key` as `Taidal_<package>_<category>[_<group>]_<callable>` (globally unique — see the unique-key mandate below) and displayed under a `Taidal/<Package>/<Category>[/<group>]` palette path (see the palette-path mandate below). A package's ops therefore appear ONLY if its declared entry points are present in the INSTALLED `*.dist-info` metadata.
- **Entry Points Live in Installed Metadata — Reinstall After Changing Them:** Because discovery reads `importlib.metadata.entry_points(...)`, editable installs FREEZE the entry-point metadata at install time. After adding or changing a `[project.entry-points."confluid.configurables"]` declaration in ANY workspace package, you MUST reinstall that editable (`aisland setup`, or plain `uv pip install -e ./<pkg>` in dependency order) or the nodes silently vanish from FluxStudio with no error — discovery just yields fewer entries. NEVER use `--reinstall` / `--force-reinstall` to force it: that re-resolves internal deps (confluid, logflow, …) from PyPI, where they don't exist, and fails. The canonical symptom of stale metadata is an empty or near-empty `Taidal/…` palette even though the source is current; confirm with `python -c "import importlib.metadata as m; print(len(list(m.entry_points(group='confluid.configurables'))))"`.
- **Discovery Degrades Gracefully (debug, not warning):** A module that fails to import or scan during discovery MUST be skipped at `logger.debug` level so one package's missing optional dependency never empties the whole node palette. Do NOT promote these skips to `warning`/`info`.
- **Type → ComfyUI Widget Mapping:** Node inputs and outputs are derived from each callable's signature by `_map_type` in `fluxstudio/bridge.py` — int/float/str/bool (incl. `Optional`/`Union` of these, unwrapped via string scan so numerics still get real INT/FLOAT/BOOLEAN widgets rather than a STRING the constructor chokes on) map to ComfyUI scalar widgets; `dataflux.sample.Sample` maps to the `DATAFLUX_SAMPLE` socket; `datasets.Dataset` to `HF_DATASET`; path-like params (`pathlib.Path`, or names containing path/dir/root/folder) to a directory-picker widget backed by `web/directory_chooser.js` and the `/taidal/choose_directory` ComfyUI route. New supported types MUST extend `TYPE_MAP` / `_map_type` rather than special-casing individual nodes.
- **`Optional[X] = None` Params Must Coerce to the CONSTRUCTOR Default, Never a Forced Widget Value (the "FluxStudio Trainer ≠ the YAML Trainer" footgun):** ComfyUI widgets can't be `None`, so a param that defaults to `None` (the library resolves it to ITS own default — Lightning's `precision`→32-bit, `enable_progress_bar`/`enable_checkpointing`→True) MUST render a "blank = use default" widget that `_coerce_kwargs` turns into omit/None — NOT a forced concrete widget value that silently overrides the constructor. The widget per type: a nullable **numeric** (`Optional[int/float]=None`) → blank `STRING` (`""`→None, filled→cast); a nullable **bool** (`Optional[bool]=None`) → a 3-state combo `["", "true", "false"]` defaulting blank (`""`→None, `true`/`false`→bool — NOT a checkbox forced to `False`); a nullable **`Literal`** (`Optional[Literal[...]]=None`) → the Literal combo with a leading blank entry (see the Literal mandate below); a nullable **str** → `STRING` `""`→None. The bridge already does this for numerics/Literals/str; bool was the gap (a `False` checkbox disabled the progress bar / checkpointing on an imported eval). A param with a **concrete** default keeps it (a real `bool=False` stays a checkbox; `int=1000` keeps 1000). The symptom of getting this wrong: the same config runs under `marainer` (flow omits the param → library default) but fails or behaves differently in FluxStudio (the widget injected a wrong value — e.g. `precision=64`→float64-on-MPS crash, or `enable_progress_bar=False`). Pins: `tests/test_bridge.py::test_optional_bool_none_default_is_tristate_combo` / `::test_real_lightning_trainer_enable_flags_default_blank` / `::test_optional_literal_none_default_offers_blank_use_default`.
- **Closed `Literal[...]` → Combo Dropdown (enumerate from the annotation, never restate):** A constructor param typed as a closed `typing.Literal[...]` (the workspace's preferred way to type a fixed, short value set — see the root "Prefer Closed `Literal`s" mandate; e.g. waivefront's `Colormap`) renders as a ComfyUI **combo** whose options ARE the literal's members. `_widget_for` (via `_literal_options`, which also unwraps `Optional[Literal[...]]`) returns `(options_list, {"default": …})` — ComfyUI's enumeration form, where the *list itself* is the "type". This is resolved BEFORE the name-based PATH / scalar heuristics (an explicit enum is the stronger signal), and `_coerce_kwargs` passes a Literal value through verbatim (never the STRING list/int heuristics — a member containing `int`/`list`/`float` must not be cast/split). The default is the param default when it is a member, else the first option. **EXCEPTION — an `Optional[Literal[...]]` that defaults to `None`** (e.g. `pytorch_lightning.Trainer.precision`, `Optional[Literal[64,32,16]…]=None`): the combo can't BE `None`, so `_widget_for` does NOT force the first member — it prepends a blank `""` "(use default)" entry and selects it, and `_coerce_kwargs` OMITS a blank-valued Optional Literal so the constructor's own default applies. Without this, the combo would silently inject the first member (`precision=64` → the model is cast to **float64**, which crashes on MPS: "Cannot convert a MPS Tensor to float64") instead of letting Lightning pick its 32-bit default — the canonical "FluxStudio Trainer differs from the YAML/flow Trainer" footgun. (A param with a concrete in-set default keeps that default; a required Literal with no default still uses the first member.) Pins: `tests/test_bridge.py::test_optional_literal_none_default_offers_blank_use_default` / `::test_real_lightning_trainer_precision_defaults_to_blank`. The SAME annotation drives navigaitor's form-spec (pydantic renders `Literal` as a JSON-Schema `enum` automatically) — one `Literal` upstream, both GUIs get a picker. To add a choice, edit the upstream `Literal` (e.g. `waivefront.visualizers.Colormap`), NEVER hard-code a parallel option list in the bridge or a node.
- **HuggingFace Dataset-ID Field (free text + cached picker, NOT a directory):** The dataset-identifier param of a HuggingFace dataset source is a *name* (a Hub repo id like `kitofrank/RFUAV`, or optionally a local imagefolder path) — NOT a filesystem directory, even though `dataflux.sources.HuggingFaceSource` names it `path`. `_widget_for` (gated by `_is_hf_dataset_id_param`) emits it as a free-text `STRING` tagged `taidal_widget="HF_DATASET_ID"` instead of the directory picker. `web/hf_dataset_chooser.js` adds an OPTIONAL combo populated from `GET /taidal/hf_datasets` (→ `list_cached_hf_datasets()` → `huggingface_hub.scan_cache_dir()`, dataset repos only); selecting an entry fills the text field, which stays editable for any Hub id. The gate is the `HuggingFace`-class-name convention (matches `HuggingFaceSource`, sonair's `HuggingFaceClassificationDataset`, and any future `HuggingFace*`), the `repo_id`/`path` param names — NOT a per-node special-case; a plain `path` on a non-HF source still gets the directory picker. Note `taidal_widget="HF_DATASET_ID"` (a STRING-field hint) is distinct from the `HF_DATASET` socket *type* used for `datasets.Dataset` wires.
- **HuggingFace Feature-Selector Fields (free text + column picker, populated from the SELECTED dataset):** A HuggingFace source's `input_feature` / `target_feature` (which dataset *column* maps onto `Sample.input` / `.target`) are free-text `STRING`s — but typed blind they're a frequent source of zero-yield bugs, so `_widget_for` (gated by `_is_hf_feature_param`, params `_HF_FEATURE_PARAMS = {input_feature, target_feature}`) tags them `taidal_widget="HF_FEATURE"` and `web/hf_feature_chooser.js` adds an OPTIONAL "columns" combo. It is the cached-dataset picker ONE LEVEL DOWN: the columns are fetched from `GET /taidal/hf_dataset_features?path=…&name=…&split=…` (→ `list_hf_dataset_features()` → `datasets.load_dataset_builder().info.features`, falling back to streaming one example; degrades to `[]` on ANY failure — convenience over a free-text field, must never break the editor) keyed off the node's CURRENT dataset-id (`HF_DATASET_ID`) field, so the column list always reflects the chosen dataset. The combo refreshes when the dataset id / `name` / `split` widget changes — including when the cached-dataset picker fills the id field (it now fires that widget's `callback` after setting it, so dependents react to the programmatic change). Same `HuggingFace*` class-name gate as the dataset-id field — NOT a per-node special-case; a like-named param on a non-HF class is unaffected. Column order is preserved (input vs target read more naturally than alphabetical). Scope is the two scalar feature params; `metadata_features` (a list) is deliberately left as the comma-separated STRING (a multi-select / opt-in `"*"`=the-rest is a planned follow-up).
- **HuggingFace Split Field (free text + split picker; NOT the `DatasetSplit.split` Literal):** A HuggingFace source's `split` stays a free-text `STRING` — HF accepts slice syntax (`train[:90%]` / `train+test`) a closed dropdown can't express — so `_widget_for` (gated by `_is_hf_split_param`, param `_HF_SPLIT_PARAM = "split"`) tags it `taidal_widget="HF_SPLIT"` and `web/hf_split_chooser.js` adds an OPTIONAL "splits" combo fetched from `GET /taidal/hf_dataset_splits?path=…&name=…` (→ `list_hf_dataset_splits()` → `datasets.get_dataset_split_names`, metadata-only; `[]` on ANY failure) keyed off the node's current `HF_DATASET_ID` field; refreshes on dataset id / `name` change (incl. the cached-dataset pick cascade). CRUCIAL distinction: this is gated on the `HuggingFace*` class-name convention so it catches ONLY `HuggingFaceSource.split`. `DatasetSplit.split` is a DIFFERENT concept — a closed `Literal["train","val","test"]` fraction-view selector on a non-HuggingFace class — and is ALREADY a combo via `_literal_options`; the HF gate deliberately leaves it untouched. Don't merge the two.
- **HuggingFace Metadata-Columns Field (multi-select append + `*`):** A HuggingFace source's `metadata_features` is a `List[str]` (which columns ride onto `Sample.metadata`). It stays a comma-separated `STRING` (`_coerce_kwargs` splits it into the list; empty ⇒ `None` ⇒ no extra metadata) tagged `taidal_widget="HF_METADATA"` (gated by `_is_hf_metadata_param`, param `_HF_METADATA_PARAM = "metadata_features"`). ComfyUI has NO native multi-select, so `web/hf_metadata_chooser.js` adds an "add column" combo that APPENDS the picked column (pick repeatedly to build the list — the field stays editable). Options reuse the feature route (`GET /taidal/hf_dataset_features`) but EXCLUDE the current `input_feature`/`target_feature` values and prepend a `*` entry = "every column except input/target" — the `dataflux.sources.METADATA_ALL_FEATURES` sentinel the LIBRARY resolves at load (NOT here; the GUI only writes the literal `*`). Picking `*` is exclusive (already means "the rest"). Refreshes on dataset id / `name` / `split` AND input/target-feature change (the exclusion set). The "default = the rest" behaviour lives in `dataflux` (opt-in via `*`), never as GUI-only magic — keep library and GUI consistent on the one sentinel.
- **Display Names Are Verbatim; Private Callables Are Hidden:** `register_module_nodes` labels each node via `_humanize_node_name` = `name.replace("_", " ")` — NEVER `str.title()` (it lowercases CamelCase tails: `HuggingFaceSource` → `Huggingfacesource`). Capitals are preserved as written. `scan_module` returns every module-local callable, so `register_module_nodes` SKIPS names starting with `_` (internal helpers like `_to_uint8` / `_worker_task` are not user-facing nodes and would otherwise clutter the palette as generic STRING nodes).
- **Node Discovery Is a POSITIVE Category Allowlist (`_NODE_CATEGORIES = {op, source, engine}`):** `register_module_nodes` registers a discovered class as a node ONLY if `getattr(cls, "__confluid_category__", None) in _NODE_CATEGORIES`. So the palette is *exactly* the deliberately-tagged ops/sources/engines. Excluded **by construction** (no negative special-casing): the raw-callable op wrappers (`FilterOp`/`WrappedOp` — UNcategorised bare `@configurable`, see below — so they stay out even though `engine` is now allowed); task `*_dataset` classes (see *Source vs Dataset* below); uncategorised module-level helper *functions* (`sample_to_image`, `value_to_image`, …); and raw sinks (`JsonSink`/`JsonPerWindowSink`/… are uncategorised — the old `PlotSink`/`SpectrogramSink` are gone, replaced by the `ConvertToImageOp`/`RenderOverlaysOp`/`RenderSignalPlotOp` ops). `_`-private names are still skipped explicitly (belt-and-suspenders). **Consequence:** an op/source/engine that loses (or never gets) its tag silently vanishes — fix it by tagging the class in dataflux/waivefront, NEVER by special-casing the bridge. To surface another role, add its category to `_NODE_CATEGORIES` and tag the classes. **Beyond the category allowlist, `register_module_nodes` ALSO admits two interface/role classes** (see the *Runnable Nodes* + *Object Member Nodes* mandates): a class implementing the **run interface** (`_is_runnable` — a no-arg `run(self)`: trainers / evaluators / `DatasetProcessor`) and a runnable **member** class (a task `role="dataset"` → Source node; `role` ∈ `{model, loss, metric}` OR the confluid `lazy` mark `__confluid_lazy__` → OBJECT node). These are category-less or deliberately non-canvas-tagged; they're admitted by interface/role/lazy-mark, not by `_NODE_CATEGORIES`.
- **Runnable Nodes — trainers / evaluators / processors RUN on execute (members are wired sockets):** A class implementing the **run interface** (`_is_runnable`: a no-arg `run(self)`) becomes a node via `_build_runnable_node`. It enumerates the runnable's FULL configurable surface from `to_pydantic(cls)` (ctor params AND `__init__`-body slots — the confluid `_post_init_field_specs` scan; `@ignore_config` members are skipped) and renders each member as: a **`DATAFLUX_SOURCE`** socket (dataset/source members — `_DATASET_MEMBER_PARAMS = {train_set, val_set, test_set, dataset}` + the `source` param), a **`DATAFLUX_OBJECT`** socket (any other non-scalar member — model / loss / optimizer / loaders / lightning / metrics — via `_is_scalar_anno`; a model/loss/metric member is ROLE-QUALIFIED & TASK-AGNOSTIC per the role-socket mandate below — ANY trainer's `model` slot is `DATAFLUX_OBJECT:model`), or a **widget** (scalars: `num_classes` / `max_epochs` / `experiment_name` …, through the shared `_build_config_inputs`; ComfyUI's "convert to input" covers the rare wire). A member that is a ctor param with NO default is a REQUIRED socket (`model` / `train_set`); everything else is OPTIONAL — unwired ⇒ the runnable keeps its baked default ("true optional"). **The node RUNS on execute — it IS the terminal `OUTPUT_NODE` (there is NO separate Run node; the build/run split was collapsed).** `execute` builds the runnable (ctor params → `__init__`, body slots via post-construction `setattr` of the wired members), then calls `fluxstudio.nodes.run_runnable` (lazy-imported to dodge the `bridge`↔`nodes` import cycle — it restores autograd, handles interrupts, live-streams stdout) and returns `{"ui": {"text": [log]}, "result": (runnable, *live_outputs)}`. OUTPUTS: slot 0 is the (post-run) runnable on a **`DATAFLUX_RUNNABLE`** wire (`kind="runnable"`), then EVERY declared `@output` as a typed socket carrying its LIVE value (see the all-outputs mandate below). A scalar body slot MUST be annotated (`self.x: bool = …`) or it reads as `Any` → an OBJECT socket; real trainers annotate their slots. Member detection is by ANNOTATION/name (never per-class). Pins: `tests/test_bridge.py::test_build_runnable_node_member_sockets_and_widgets` / `::test_runnable_node_execute_builds_post_sets_and_runs`.
- **Object Member Nodes Have TWO Outputs (`instance` + `class`):** A runnable's member classes become `DATAFLUX_OBJECT` producers via `_build_object_node` (`kind="object"`): config widgets → **two** `DATAFLUX_OBJECT` outputs, `instance` (the flowed, live object built right here via `confluid.flow`) and **`class`** (the configured-but-deferred class — a `LazyClass` value; the port is named `class` as the user-facing "the configured class, not yet built", NOT `lazy`). A runnable slot accepts either (`flow` is idempotent on a live instance): wire **`instance`** for a fully-configured standalone object; wire **`class`** when a value is only known at `run()` (`torch.optim.*.params` / `DataLoader.dataset`, or a model's dataset-derived `num_classes`) so the runnable flows it with the runtime kwarg. (graphio's whole-graph export keys eager `!class:Foo()` / deferred `!lazy:Foo` off the WIRED output slot — `instance`=slot 0, `class`=slot 1 — NOT the port label.) A member is detected as `role∈{model,loss,metric,logger}` OR confluid **`lazy`** (`__confluid_lazy__`, set by `@configurable(lazy=True)` / `register(..., lazy=True)`). A `lazy` member SKIPS the runtime-injected required params (`torch.optim.*.params`, `DataLoader.dataset`) so only the configurable knobs (lr / batch_size) are widgets; because those params are missing by design, its `instance` output is `None` (logged at `debug`, NOT a warning — that's expected) and only `class` is usable. For a non-deferred member whose live build simply **fails** on an incomplete/invalid config (e.g. a model node left without `num_classes`), `instance` is `None` and `_build_object_node` emits an **actionable `warning`** ("could not build a live instance …") — ComfyUI tolerates the `None` socket; downstream nodes that need the instance fail legibly on use. Task `role="dataset"` classes are routed to `_build_source_node` (datasets are Sources, not objects). The select runtime members (`torch.optim.Adam`/`AdamW`/`SGD`, `DataLoader`, `pytorch_lightning.Trainer`) are `register(..., lazy=True, group=…)`-ed in **`marainer.configurables`** (entry-pointed; re-exported via `__all__`) — **deliberately with NO `category`** (only a presentation-only `group`), so they're FluxStudio object nodes via the `lazy` mark WITHOUT leaking into navigaitor's category-driven form-spec slot pickers (which would then offer the raw `params`-taking optimizer instead of navigaitor's curated infra config). Register the class upstream + mark it `lazy`, NEVER hand-build a member node here. **A member target may be a CLASS or a plain builder/factory FUNCTION** — the gate is "callable + marked", NOT "class + marked" (`_is_object_member_class` checks `callable(obj)`, never `inspect.isclass`; the `register_module_nodes` second pass likewise admits a re-exported registered *function*). Canonical case: `raidar.configurables` `register`s torchvision's detection builder FUNCTIONS (`fasterrcnn_*` / `retinanet_*` / `fcos_*` / `ssd*`) with `task="detection", role="model", lazy=True`, so each becomes a `DATAFLUX_OBJECT:model` object node whose widgets are introspected from the FUNCTION's own signature (`num_classes` / `weights_backbone` / …) — wiring straight into a detection trainer's `model` slot with no Retag. `_build_object_node` already uses `inspect.signature(cls)` + `LazyClass(cls, …)` + `flow`, all callable-safe; the `class` output is a `LazyClass(builder, …)`. (Relies on confluid's callable-aware `to_pydantic` / `flow` / `resolve_class` — confluid AGENTS "A Target May Be ANY Callable".) NOTE: object nodes have TWO outputs — index 0 is `instance`, index 1 is `class` (the `LazyClass`). Both outputs carry the ROLE-QUALIFIED & TASK-AGNOSTIC socket (`_object_socket_for_class(cls)` → `DATAFLUX_OBJECT:model`) per the role-socket mandate below. Pins: `tests/test_bridge.py` (object node dual output / deferred / build-warning; `::test_object_member_predicate_accepts_marked_function` / `::test_object_node_from_builder_function`).
- **Object Sockets Are ROLE-QUALIFIED & TASK-AGNOSTIC; the Retag Node Is the Escape Hatch:** ComfyUI connects sockets only on string EQUALITY, so object-member sockets are **role-qualified** — `DATAFLUX_OBJECT:<role>` (`bridge._object_socket`), where `<role>` ∈ `{model, loss, metric}` (the value-set `bridge._QUALIFIED_OBJECT_ROLES`). **TASK is deliberately NOT on the socket** — a classification model and a segmentation model both produce `DATAFLUX_OBJECT:model` and dock into ANY trainer's `model` slot. Task survives only as GUIDANCE (navigaitor slot ranking + the palette folder/label). The role still guards KIND: a loss (`DATAFLUX_OBJECT:loss`) can't dock into a model slot. An object node's output role comes from `bridge._object_socket_for_class` = the explicit `@configurable(role=…)` tag, ELSE inferred from the Python type (`_role_for_class` — a duck-typed MRO scan: `Metric→metric`, `Optimizer→optimizer`, `DataLoader→loader`, `Logger→logger`; model vs loss are BOTH `nn.Module` so only the tag disambiguates them). A runnable's object SLOT role comes from `bridge._STRICT_SLOT_ROLES` (`model→model` / `loss_fn→loss` / `*metrics→metric`, mirroring navigaitor's `PARAM_NAME_TO_ROLE` — fluxstudio MUST NOT import navigaitor; the convention is small and replicated) and a trainer `@output` (`trained_model`) via the keyword-scanning `_infer_member_role`. The object-NODE output side and the runnable-SLOT input side MUST agree on which roles qualify (both gated on `_QUALIFIED_OBJECT_ROLES`) — a one-sided qualifier silently refuses an otherwise-valid wire (the original "can't connect a logger" footgun). **Scope:** model/loss/metric object members. Datasets stay generic `DATAFLUX_SOURCE`. **Role-less members (optimizer / loader / lightning / logger) stay bare `DATAFLUX_OBJECT`** — no kind to enforce; they interchange among themselves (acceptable). The **Retag node** (`nodes.py:RetagObjectNode`, `Taidal_Retag`) is the deliberate, visible bypass: a wildcard (`AnyType("*")`) input accepts any object; the `target_role` combo (from the registry's `list_roles()`) re-stamps `__confluid_role__` PER-INSTANCE (never the class) and `web/retag.js` retypes the OUTPUT socket to the chosen `DATAFLUX_OBJECT:<role>` (or `*` for `(keep)`); `target_task` re-stamps only the guidance tag (no socket effect). graphio whole-graph export does NOT round-trip Retag nodes (no `TAIDAL_CALLABLE_PATH`, like the other canvas-only adapters — skipped-with-comment per the export-skip mandate; ops-export still raises `UnsupportedTopologyError` on them); it's a canvas convenience, hand-written YAML controls types directly. `_is_socket_type`/`_base_socket_type` (base-aware) keep graphio's socket-vs-widget split working under the qualified strings. Pins: `tests/test_bridge.py::test_object_node_output_socket_is_role_qualified` / `::test_strict_sockets_reject_cross_role` / `::test_role_for_class_*`, `tests/test_nodes.py::test_retag_*`.
- **Object Nodes Wire Object-Typed Ctor Params as INPUT Sockets (the `logger`/`callbacks` fix):** An object node's constructor param that accepts an OBJECT — a non-scalar **class** arm with **no `str`/`int`/`float` config arm** (a `bool` toggle arm or `None` does NOT disqualify) — renders as a wired **`DATAFLUX_OBJECT`** INPUT socket instead of a widget, so a producer node docks into it. Detection is by annotation SHAPE (`bridge._is_wireable_object_param`, applied in `_build_object_node`), NEVER a per-class list: on a `pytorch_lightning.Trainer` it sockets `logger` / `callbacks` / `plugins` while leaving `accelerator` / `strategy` / `devices` / `precision` / `profiler` as STRING/INT widgets (they have a `str`/`int` config arm you TYPE). This fixes the bug where `logger: Union[Logger, Iterable[Logger], bool]` collapsed to a **BOOLEAN widget** (`_map_type` string-scans and hits `"bool"`) so a logger node couldn't connect. The socket is **bare `OBJECT_TYPE`** (role-less, matching the logger/callback producer nodes' bare `DATAFLUX_OBJECT` output). **A param that also admits a LIST of objects (`_admits_object_list` — a `list`/`Iterable`/`Sequence` arm of an object class, e.g. `logger: Union[Logger, Iterable[Logger], bool]` / `callbacks: Union[List[Callback], Callback, None]`) gets a DYNAMIC `<name>_N` socket FAMILY** (seed `<name>_0`; `web/object_list.js` grows `<name>_1`, `<name>_2`, … as you wire — the object analogue of `op_N`/`source_N`), collected index-ordered into a list by `bridge._collect_indexed` in `execute` (empty ⇒ omitted ⇒ ctor default). A single-object param (no list arm) gets ONE socket — required when the param has no default, else optional. `execute` splits wired object kwargs (passed through as-is, `flow()`-ed first if still a `Fluid` so the producer's `instance` OR `class` output both work) from widget kwargs (still `_coerce_kwargs`-ed). Wire the producer's `instance` output. `web/optional_inputs.js`'s `(optional)` marker skips ANY `<name>_<digit>` slot (the list families have their own add-more UX). This is the INPUT-side complement to the role-qualified OUTPUT mandate above. - **`run_runnable` Restores Autograd for `TorchRunner`s (ComfyUI runs under `inference_mode`):** `fluxstudio.nodes.run_runnable(runnable, unique_id)` is the shared runner each generated runnable node's `execute` calls (the node IS the `OUTPUT_NODE`). ComfyUI evaluates the whole graph under `torch.inference_mode()` (`execution.py`), which is fatal for **gradient-based training**: model params (model nodes are lazy → the backbone is built *inside* `run()`), forward activations, and the loss all become inference tensors with no autograd graph, so `loss.backward()` dies with *"element 0 of tensors does not require grad and does not have a grad_fn"*. So `run_runnable` re-enables normal autograd (`with torch.inference_mode(False), torch.enable_grad():`) ONLY for a runnable that declares itself a **`marainer.TorchRunner`** (duck-typed `__torch_runner__` flag — no hard `marainer` import). Inference-only runnables (`LightningEvaluator`, `DatasetProcessor`) leave the flag unset and run as-is under ComfyUI's inference mode. This is why model nodes being **lazy** matters: the backbone is constructed inside the grad-restored `run()`, not earlier in the object node's `execute` (which still runs under `inference_mode`). Pins: `tests/test_nodes.py::test_run_runnable_*`.
- **`run_runnable` Is Interruptible (worker thread + injected `KeyboardInterrupt`):** ComfyUI only polls its interrupt flag BETWEEN nodes, but `run_runnable` wraps ONE blocking `.run()` call that can run for minutes/hours — so the interrupt button would otherwise be ignored until the sweep finished. It therefore executes the runnable on a **daemon worker thread** and polls `_processing_interrupted()` (a lazy, guarded `comfy.model_management.processing_interrupted()` — `False` when comfy is absent, so fluxstudio's own tests/dev runs are unaffected) from the calling thread every 0.1 s; when the flag goes high it injects a `KeyboardInterrupt` into the worker via CPython's `PyThreadState_SetAsyncExc` (`_raise_interrupt_in_thread`) and re-raises ComfyUI's `InterruptProcessingException` for a clean stop (no traceback, UI reset). PyTorch Lightning catches `KeyboardInterrupt` for a graceful shutdown; `DatasetProcessor` / Flux iteration loops simply unwind. **Grad/inference mode is thread-local**, so the worker does NOT inherit the `torch.inference_mode()` ComfyUI wraps graph execution in — `run()` captures `torch.is_inference_mode_enabled()` on the calling thread and the worker re-establishes the correct context itself (grad-restored for `__torch_runner__`s, `inference_mode()` re-entered for inference-only runnables). The injection lands at a Python statement boundary (between batches / samples), so a single long-running C kernel is not interruptible — an accepted limitation. This keeps ALL ComfyUI/interrupt knowledge in fluxstudio; marainer/dataflux are untouched (per marainer's `TorchRunner` mandate). Pins: `tests/test_nodes.py::test_run_runnable_interrupt_*`, `test_run_runnable_grad_context_is_active_inside_worker_thread`.
- **A Runnable Node's Output Is LIVE-Streamed Into a Collapsible Widget (`web/run_output.js`):** The runner's stdout/stderr (training progress, metrics, logflow lines) is captured by `_TeeStream` (mirrored to the live console; delegates `isatty`/`fileno`/`encoding` so a real tqdm/Lightning bar still renders there) and shown in a read-only, **collapsible** multiline widget on the node. It streams **DURING** the run: the worker-join poll loop (the same 0.1 s loop that checks the interrupt flag) pushes the latest `_collapse_carriage_returns`-collapsed, `_strip_ansi`-cleaned, `_MAX_OUTPUT_CHARS`-tail-capped snapshot — but only when it CHANGED — via `_send_run_output` → ComfyUI's `server.PromptServer.instance.send_sync("taidal.run_output", {node, text})` websocket event. **ANSI stripping (`_strip_ansi`, `_snapshot` only):** a Rich/Lightning bar emits CSI control codes — color, dim/underline (`\x1b[2m`/`\x1b[2;4m`), erase-line (`\x1b[2K`), cursor moves — that a plain text widget can't render and that show up as literal `[2K`/`[0m` garbage (NO_COLOR strips *color* SGR but not dim/underline/erase). `_snapshot` strips the lot for the WIDGET copy ONLY; the `_TeeStream` console mirror keeps them so the bar still animates in the terminal. Strip the WIDGET side, never the tee. `web/run_output.js` attaches the log widget to **every runnable node** (NOT a single class) — it identifies one structurally by `nodeData.input?.hidden?.unique_id` (only runnable nodes declare the hidden `unique_id`; ComfyUI exposes the full `INPUT_TYPES` incl. `hidden` as `nodeData.input`), stamps `nodeType.prototype._isTaidalRunnable = true`, and the live-event handler updates a node when `node._isTaidalRunnable`. The node id reaches `run_runnable` via that `hidden: {unique_id: "UNIQUE_ID"}` INPUT (the bridge folds it in). `_send_run_output` is lazy + guarded like `_processing_interrupted` (no `unique_id` / no ComfyUI `server` ⇒ silent no-op), so fluxstudio's own tests/dev never break. The final text is ALSO returned as `{"ui": {"text": [...]}}` (restored by `onExecuted` on re-open); the structured `@output` VALUES ride their own typed sockets (the all-outputs mandate below), NOT this log. Captured logs are runtime output so `web/run_output.js` sets `serializeValue = () => ""` (never persisted into `workflow.json`). The collapse toggle (a button widget, default **expanded** so progress shows immediately) folds the text area by hiding `inputEl` + zeroing the widget's `computeSize`. **Out of scope:** ComfyUI's NATIVE green progress bar (`comfy.utils.ProgressBar`) — a generic runnable exposes no total step count to drive it; the streamed tqdm/Lightning bar IS the progress display. Pins: `tests/test_nodes.py::test_run_runnable_streams_output_live`, `test_send_run_output_is_a_safe_noop_without_comfyui`, `test_strip_ansi_removes_csi_sequences`, `test_run_runnable_strips_ansi_progress_codes`.
- **EVERY Declared `@output` Is a Live, STATIC, Wireable Socket (no dynamic outputs, no results panel):** Because the runnable node RUNS on execute, its `@output` sockets carry LIVE post-run values — so `_build_runnable_node` appends a socket for EVERY `confluid.output_specs(cls)` entry (no filtering). The socket TYPE comes from `_output_socket_type` (per-class STATIC — ComfyUI v0.22 has no dynamic outputs, and the node is generated per class so it doesn't need them): a **container** output (`Dict`/`List`/`Set`/`Tuple` — `computed_metrics` a `Dict[str,float]`, `label_names` a `List[str]`) → a **`STRING`** socket (the execute JSON-encodes the value via `_coerce_output_value`, so you wire it into ComfyUI's native *Show Text*); a **role-bearing object** (`trained_model`) → `DATAFLUX_OBJECT:<role>` (into a downstream evaluator's `model`); a dataset name → `DATAFLUX_SOURCE`; a scalar → its `_map_type` widget type. The container branch is BEFORE the role inference ON PURPOSE — it stops `computed_metrics` mis-mapping to a bogus `DATAFLUX_OBJECT:metric` via the `"metric"` substring in `_infer_member_role`. `execute` reads each `@output` post-run (`getattr`, live) and `_coerce_output_value`s it to its socket. There is NO bespoke results panel and NO `taidal.run_outputs` event (deleted) — structured outputs are sockets, not a hand-rolled viewer (consistent with the *Adapter Nodes Are Glue* mandate: expose typed sockets, let native nodes display). Pins: `tests/test_bridge.py::test_runnable_node_is_output_node_with_all_outputs` / `::test_output_socket_type_maps_containers_to_string` / `::test_runnable_node_runs_and_emits_live_outputs` / `::test_runnable_node_emits_container_outputs_as_json_strings`.
- **Discovery Has Two Passes (scan_module + `__all__` re-exports):** `scan_module` returns only callables whose `__module__` IS the scanned module — which misses a package's SUBMODULE classes re-exported in its `__init__` (`sonair` re-exports `LightningClassificationTrainer` from `sonair.trainer`) AND registered third-party members (`marainer.configurables`'s `torch`/`pl` classes, `__module__` = `torch`/`pytorch_lightning`). So `register_module_nodes` runs a **second pass** over the module's `__all__`: any `@configurable` callable listed there is also a candidate — a CLASS **or a registered builder FUNCTION** (the pass-2 gate is `callable(member) and getattr(member, "__confluid_configurable__", …)`, NOT `inspect.isclass`; this is what surfaces `raidar.configurables`'s torchvision detection builder functions). Gated on `__all__` so imported-for-use configurables don't leak into the palette. This is why a package whose entry point points at the package root (`sonair = "sonair"`) still surfaces its submodule classes — provided they're in `__all__`. A new runnable/member exposed from a package MUST be in that package's `__all__`.
- **Discovery Is One-Shot Per Process (double-import guard):** FluxStudio is imported under TWO module identities — editable-installed as `fluxstudio` AND symlinked into ComfyUI's `custom_nodes/` (and the package's own `from fluxstudio.bridge import …` triggers the top-level import from inside the custom-node import) — so `__init__` runs twice. `_discover_and_register_nodes` therefore **scans once** (caching the discovered mappings on the `sys` singleton, shared across identities) and, on any later call, copies the cached mappings into that identity's `NODE_CLASS_MAPPINGS` — so whichever `fluxstudio` ComfyUI reads still gets the full set while the scan + "Scanning module …" logs happen exactly once. A per-call `seen` set also dedups duplicate entry points. Don't remove the guard to "simplify"; the double-scan returns. Pins: `tests/test_init_discovery.py::test_discover_is_one_shot_per_process`.
- **Engines Are Canvas-Composable Via Wired Source/Op Sockets; Raw-Callable Wrappers Stay Uncategorised:** `category="engine"` covers the composition primitives `Flux`/`JointFlux` (and `DatasetSplit`, now a `source`). They ARE buildable on a canvas: `_build_source_node` renders their source-typed constructor params as WIRED sockets instead of STRING widgets — a single `source` → one `DATAFLUX_SOURCE` input (`_source_param`: `DatasetSplit.source`/`Flux.source`; required socket when the ctor param has no default, else optional), a source-list (`fluxes`/`sources`, `_source_list_param`) → dynamic `source_N` `DATAFLUX_SOURCE` inputs grown by `web/source_list.js` (`JointFlux.fluxes`), an op-list (`ops`/`branches`, `_op_list_param`) → dynamic `op_N` `DATAFLUX_OP` inputs grown by `web/op_list.js` (`Flux.ops`). `execute` collects the dynamic inputs (`_collect_sources`/`_collect_ops`) + the single `source` kwarg, constructs, and wraps the result in a `Flux`. Detection is by param NAME (the same convention as `_OP_LIST_PARAMS`), never per-class. This is the consuming half of "a Source/Op node already outputs ITSELF" — Source nodes output `DATAFLUX_SOURCE`, op nodes their `op` on `DATAFLUX_OP`. The raw-callable op wrappers `FilterOp(p)`/`WrappedOp(f)` are NOT engines — they are bare `@configurable` (UNcategorised), excluded because their constructor takes a raw Python callable, nothing a widget OR a `DATAFLUX_OP` socket can supply; they stay out of the palette (correct — not buildable). NOTE: `export.py` ops-export still targets linear op chains only (several disconnected chains export fine — one doc per chain) — engine-node graphs and `source`/`source_N` links are not exportable (like `op_*` links, they'd raise `UnsupportedTopologyError`).
- **Source vs Dataset (a `source` is a canvas node; a task `dataset` is not):** A `category="source"` is a task-agnostic Sample producer (`HuggingFaceSource`, `RFUAVSource`, `RegionsJsonSource`) — the head of a DataFlux pipeline, and exactly what a canvas needs to Walk/Extract/visualize. A task `dataset` (e.g. sonair's `HuggingFaceClassificationDataset`, tagged `task="classification", role="dataset"` ⇒ `category="classification_dataset"`) is a task-scoped, model-ready dataset that fills a *trainer's* `dataset` slot — meaningful to navigaitor's config composition (which must offer only task-compatible datasets), but NOT to a per-sample canvas. So `dataset` is deliberately NOT in `_NODE_CATEGORIES`; the canvas data origin is always a `source`.
- **Palette Path Groups by ROLE/TASK or CATEGORY (NOT package); Package Is a `[PKG]` Label Tag:** `register_module_nodes` builds each node's ComfyUI `CATEGORY` via `_node_category` (`fluxstudio/bridge.py`) by REUSING the discovery taxonomy, never the package: a ROLE-bearing class (model/loss/metric/trainer/evaluator/dataset/logger) nests `<root>/<Role>[/<Task>]` — ROLE-first then the optional task — so every model of every task collects under `Taidal/Model/` (`Taidal/Model/Classification`, `Taidal/Trainer/Detection`, `Taidal/Logger` = task-agnostic so no task level); a task-agnostic class (op/source/engine + role-less lazy infra) nests `<root>/<Category>[/<group>]` (`Taidal/Op/numpy`, `Taidal/Source`). The PRODUCING PACKAGE moves to the node LABEL as an uppercased `[PKG]` tag via `_package_tag` (derived from `ep.dist.name` — the distribution name passed through `__init__` → `register_module_nodes` → `_package_tag` → `.upper()` → `[SONAIR]`, `[WAIVEFRONT-HELIOS]`), prepended to the verbatim `_humanize_node_name` (e.g. `[SONAIR] TimmModel`). Companion namespace packages (e.g. `waivefront-helios`, `waivefront-torchsig`) therefore produce distinct tags automatically — no hardcoded registry needed. **`group` is presentation-only** (op/source nesting), NOT a discovery filter (that's `category`) and NOT the navigaitor `task`/`role` contract; set it in the upstream `@configurable(..., group="…")`, NEVER hand-build a palette path. An empty `root` (`--no-default-nodes`) drops the leading `Taidal/`. The registration KEY (`_node_key`) is UNCHANGED — still package+category+group-qualified (globally unique), independent of the display grouping.
- **`--no-default-nodes` Hides ComfyUI's Built-ins and Roots the Palette (one CLI flag, one env var):** The `fluxstudio` CLI's `--default-nodes` / `--no-default-nodes` flag (`argparse.BooleanOptionalAction`, default = shown) controls whether ComfyUI's own nodes appear next to the Taidal nodes. The CLI is a launcher for a ComfyUI *subprocess*, so the choice crosses the process boundary via the env var **`FLUXSTUDIO_HIDE_DEFAULT_NODES`** (`_run` sets it explicitly to `"0"`/`"1"` so the flag wins over any ambient shell export). Inside ComfyUI, `fluxstudio.bridge.hide_default_comfy_nodes()` reads that var and drives TWO behaviours: (1) **prune** — `_prune_default_comfy_nodes()` (`fluxstudio/__init__.py`, called from the `import server` block) deletes ComfyUI's built-in nodes from the GLOBAL `nodes.NODE_CLASS_MAPPINGS`. It runs at *our* import time, which (per ComfyUI's load order: built-ins + `comfy_extras` + `comfy_api_nodes` load BEFORE `custom_nodes/`, and our own nodes merge in AFTER this import returns) is exactly the window where the global registry holds *only* the defaults. A default node is told from a custom one by `RELATIVE_PYTHON_MODULE` (ComfyUI stamps it on every loaded class; `server.py` defaults a missing attr to `"nodes"`) — top-level module in `{nodes, comfy_extras, comfy_api_nodes}` ⇒ pruned, `custom_nodes.*` ⇒ kept (so other third-party extensions survive). Idempotent across the two fluxstudio module identities. (2) **root** — `node_root()` returns `""` (vs `"Taidal"`) so the palette path drops the leading `Taidal/` folder (`DataFlux/Op` not `/DataFlux/Op` — `_node_category` filters the empty segment) and the hand-written adapter nodes' `_FLUXSTUDIO_CATEGORY` becomes `FluxStudio`. CONSEQUENCE: hiding the defaults also removes ComfyUI's native viewers (Preview Image, …) that **Extract from Sample** feeds — so it's opt-in, never the default. Don't read the env var ad-hoc — go through `hide_default_comfy_nodes()` / `node_root()` (the single source of truth, also the default for `register_module_nodes`'s `root`).
- **Empty Canvas Instead of ComfyUI's SD Sample (`web/empty_default_graph.js`):** ComfyUI ships a built-in `defaultGraph` (CheckpointLoader → CLIP → KSampler → VAE → Save Image) that it loads as the initial canvas AND re-loads whenever the LAST workflow tab is closed (frontend `workflowService.closeWorkflow` → `loadDefaultWorkflow` → `app.loadGraphData(defaultGraph)`). Those Stable-Diffusion nodes are unrelated to FluxStudio's Taidal pipeline nodes, so this web extension substitutes ComfyUI's own `blankGraph` (an empty canvas). The frontend exposes both on `window.comfyAPI.defaultGraph` (a self-described *internal* shim — so the extension is defensive: optional chaining, a hardcoded blank-graph fallback, idempotency guards). TWO complementary hooks (internals aren't a stable public API): (1) wrap `app.loadGraphData` to swap the default-graph object for a fresh blank one at call time — catches first-launch AND the all-tabs-closed reload with no timing race; (2) blank the shared `defaultGraph` object IN PLACE (poll until its possibly-lazy chunk is present, ~5s cap) — `loadDefaultWorkflow` captured that exact object reference at module-eval time, so emptying its contents neutralizes the reload even if (1)'s `app` ref isn't the one the workflow service calls. Substitution is gated on object IDENTITY (`graphData === defaultGraph`), so a real user workflow loads untouched. JS web extensions aren't in CI; verified by `node --check` + a node harness simulating `window.comfyAPI.defaultGraph` + a fake `app` (immediate, lazy-chunk, and untouched-user-workflow paths). This is GUI/launch UX (the one sanctioned class of canvas-only adapter glue), not a node/op.
- **Registration Key Is Globally Unique (`_node_key`), NOT Just the Class Name:** ComfyUI identifies a node TYPE by its key in `NODE_CLASS_MAPPINGS` — its display `CATEGORY` folder does NOT make it unique. A plain `Taidal_<ClassName>` collides whenever two modules expose a same-named class (the canonical case: `dataflux.ops.numpy:RescaleOp` AND `dataflux.ops.torch:RescaleOp`, likewise `StandardizeOp`) — the second registration silently overwrites the first and one node disappears from the palette. `register_module_nodes` therefore keys via `_node_key` = `Taidal_<package>_<category>[_<group-segments>]_<callable>` (e.g. `Taidal_dataflux_op_numpy_RescaleOp` vs `Taidal_dataflux_op_torch_RescaleOp`). The key is built from RAW identifiers (top-level package, lowercase category, literal group) NOT the display-cased `[PKG]` tag, so it stays stable regardless of how the tag is derived; the DISPLAY name stays the verbatim class name (so both still read "RescaleOp" in their folders). The hand-written adapter nodes in `nodes.py` keep their own literal keys (`Taidal_WalkDataset` / `Taidal_ExtractSample`). NOTE: this changes saved-workflow `class_type` strings for auto-discovered nodes — an older workflow referencing `Taidal_RescaleOp` must be re-pointed at the qualified key.
- **Widget Tooltips Come From the Docstring `Args:` (never hand-written here):** `_build_config_inputs` sets each widget's `tooltip` from the callable's docstring `Args:` block via `confluid.parse_param_docs` — the SAME per-parameter help navigaitor surfaces as pydantic `Field(description=...)` in its form-spec. Document a constructor parameter ONCE in the upstream class's `Args:` and it appears as a hover tooltip here AND in the navigaitor editor. An undocumented param simply gets no tooltip — the fix is to add the `Args:` entry in dataflux/waivefront, NEVER to hand-write a tooltip in the bridge.
- **Typed Node Classification (Source / Op / Generic):** `create_comfy_node` classifies each discovered callable so a pipeline wires by TYPE, not opaque STRING: a `Sample`-yielding source class (`__getitem__`/`__iter__` → `Sample`) becomes a `-> DATAFLUX_SOURCE` node (constructor config as widgets, output a `Flux`); a `@configurable` op class with `__call__(self, sample: Sample) -> Optional[Sample]` becomes a **dual-mode** op node (config widgets + an OPTIONAL `sample` socket → a `sample` applied-output AND an `op` `DATAFLUX_OP` output — see *Ops Are Dual-Mode* below); everything else stays a generic scalar/STRING node. `DATAFLUX_SOURCE` / `DATAFLUX_SAMPLE` / `DATAFLUX_OP` are FluxStudio socket type strings carrying the live `Flux` / `Sample` / op objects. When you add a new DataFlux/Waivefront source or op that should chain, make sure its `__getitem__`/`__iter__`/`__call__` is annotated with `Sample` so the classifier picks the right shape — do NOT add per-node special-cases to the bridge.
- **Ops Are Dual-Mode (apply via `DATAFLUX_SAMPLE` AND expose via `DATAFLUX_OP`):** `_build_op_node` builds every op node with an OPTIONAL `sample` input and TWO outputs — `sample` (the op applied to the input, for linear chaining) and `op` (the constructed op as a `DATAFLUX_OP` value). Wire `sample → sample` to chain inline (today's UX); leave `sample` unconnected and take the `op` output to use the node as an op-VALUE. `execute` constructs the op once and returns `(op(sample) if sample is not None else None, op)`. A **higher-order op** — one whose constructor has an op-list param (`_op_list_param`: `ops`/`branches`, list-annotated → `Enable`/`Parallel`/`Tee`) — does NOT render that param as a STRING widget; instead it gets dynamic `DATAFLUX_OP` inputs (`op_0`, `op_1`, … grown by `web/op_list.js`), and `execute` collects them (`_collect_ops`, index-ordered, drops empties) into the list before constructing. `Tee.branches` (list-of-lists) v1 wraps each connected op as its own 1-op branch (multi-op branches → pre-compose, deferred). Detect op-list params by the `ops`/`branches` naming + `List` annotation — NEVER per-class. NOTE this keeps `bridge.export`'s `TAIDAL_NODE_KIND`/`TAIDAL_CALLABLE_PATH` + the `sample`-link chain intact; the op-list topology is simply not yet exportable (export raises `UnsupportedTopologyError` on the `op_*` links — a future export extension).
- **Adapter Nodes Are Glue, Rendering Lives in Waivefront:** The statically-defined nodes in `fluxstudio/nodes.py` — `WalkDatasetNode` (`DATAFLUX_SOURCE` + auto-incrementing `index` via ComfyUI's `control_after_generate` → the `Sample` at `source[index]`) and `SampleExtractorNode` (a `DATAFLUX_SAMPLE` + `field` selector → typed `IMAGE`/`MASK`/`STRING`/`INT`/`FLOAT` sockets) — are ComfyUI orchestration/adapter glue, NOT DataFlux data ops, so they may live here. `SampleExtractorNode` is deliberately NOT an `OUTPUT_NODE`: it extracts/unpacks a Sample field onto typed sockets and lets NATIVE ComfyUI nodes (Preview Image, text/number displays) do the viewing — do not re-add a bespoke in-canvas viewer (the removed `SampleViewerNode`). The relevant socket is chosen from the sample's features via `Sample.describe()` (ComfyUI can't retype a socket per run, so all plausible types are surfaced — see *Typed Sample extraction* below). The actual image-rendering logic MUST stay in waivefront (`waivefront.visualizers.value_to_image`, with `sample_to_image` a thin wrapper); the node only bridges its `(H,W,3) uint8` output to ComfyUI's `IMAGE` tensor protocol (`[1,H,W,3]` float) and a 2-D field to the `MASK` protocol (`[1,H,W]` float). This is the one sanctioned exception to "no FluxStudio-only nodes": adapters that translate ComfyUI's execution model are allowed; data ops and visualizers are not.
- **Typed Sample Extraction (derive the socket from features, never hand-render):** `SampleExtractorNode` exposes a Sample's `input`/`target` on the fixed socket set `IMAGE`/`MASK`/`STRING`/`INT`/`FLOAT` and the user wires the one matching their viewer. Because ComfyUI sockets are statically typed at registration, the node CANNOT change a socket's type per run — so it surfaces every plausible type and derives *which is meaningful* from `Sample.describe()` (stored `__features__`/`__spec__`, else inferred). When the value isn't applicable to a socket it returns a benign placeholder (a text-rendered `IMAGE`, an empty `1×1` `MASK`, `0`/`0.0`), since ComfyUI requires every declared output be returned each run. If you need a new view type, add a socket here AND back its rendering with a waivefront helper — never hand-roll pixels in the bridge/node.
- **Type-Spec Connection Filtering (socket strings stay generic):** A Sample wire ALWAYS keeps the `DATAFLUX_SAMPLE` socket string — do NOT encode the DataFlux type into finer socket strings (ComfyUI matches sockets by string equality, which can't express ranges/dtype-families/Union). Instead the richer contract is layered on top, sourced from each op/source's `ACCEPTS`/`PRODUCES` (declared in dataflux/waivefront, never here): (1) `create_comfy_node` stashes `TAIDAL_ACCEPTS` / `TAIDAL_PRODUCES` (`SampleType.to_dict()` or `None`) on the generated node class; (2) a generated op node's `execute()` runs a **runtime accept-check** (`infer_sample_type(sample)` vs `cls.ACCEPTS`) and raises a legible error on mismatch — this is AUTHORITATIVE; (3) the `/taidal/node_specs` route + `web/connection_validator.js` reject incompatible Sample wires live on the canvas via litegraph's `onConnectInput` — this is ADVISORY (drag-drop only). The JS matcher is a faithful port of `dataflux.typespec.compatible()` (permissive: `Any`/unknown passes); keep it in sync with the Python and cover the semantics in `dataflux/tests/test_typespec.py`. Never hand-define type specs in FluxStudio — if a contract is wrong or missing, fix the op's `ACCEPTS`/`PRODUCES` in dataflux/waivefront.
- **Optional Input Sockets Are Visually Marked (`web/optional_inputs.js`):** ComfyUI's `INPUT_TYPES` splits inputs into `required` / `optional`; `_node_class` emits the `optional` dict and `_build_runnable_node` routes a runnable's non-mandatory members there (the `Mandatory[...]` / no-default inputs — `model` / `train_set` — stay `required`, via `mandatory_param_names`, mirroring the confluid I/O contract `input_specs.required`). litegraph renders both alike, so this extension marks each optional SOCKET slot on a `Taidal`-category node — a ` (optional)` label suffix (on the display `label`, never the functional `name`), a dimmed unconnected-dot colour, and a hollow slot shape when the build exposes `LiteGraph.HollowCircle`. It reads `nodeData.input.optional` in `beforeRegisterNodeDef` and re-applies on `onNodeCreated` / `onConnectionsChange` / `onConfigure` (so styling survives dynamic-slot rebuilds + graph load). It deliberately SKIPS the dynamic-list slots (`op_N` / `source_N` — their own add-more UX in `op_list.js` / `source_list.js`). Purely COSMETIC — the execution semantics (an unconnected required socket blocks the run; an unconnected optional one passes `None`, which `execute` treats as "keep the baked default") are owned by ComfyUI + `bridge.py`, NOT this extension. To change which inputs are optional, change the `required`/`optional` split in `bridge.py` (or the upstream `Mandatory[...]` markers), never hand-edit this JS.
- **Ops Export Is a Faithful Translator, Not an Optimizer (`fluxstudio/export.py`):** A canvas graph's OPS (dropping the source + Walk/Extract adapters) compile to a Confluid `{ops: [!class:…()]}` YAML — the inverse of how the canvas builds a pipeline — consumed by `Flux.from_ops_yaml` / `confluid.materialize(confluid.load(path)["ops"])`. The SINGLE compiler `export.export_ops_yamls(prompt, NODE_CLASS_MAPPINGS)` (one YAML doc per independent op chain) is shared by BOTH the `/taidal/export_ops` POST route (canvas button `web/export_ops.js` — downloads `ops.yaml`, or `ops_1.yaml`…`ops_N.yaml` for several chains) and the `fluxstudio export <graph.json>` CLI (`-o ops.yaml` fans out to `ops_1.yaml`…; stdout gets a `---`-separated document stream) — never fork it; the shared `export.chain_output_paths` owns the per-chain file-naming policy for both. Input is the ComfyUI **prompt / API-format** graph (`{node_id: {class_type, inputs}}`), NOT the UI `workflow.json`. The compiler relies on two class attrs stamped by `bridge._node_class`: `TAIDAL_NODE_KIND` (`"op"` / `"source"` / `"generic"`) picks out the op nodes, and `TAIDAL_CALLABLE_PATH` (importable `module:qualname`) recovers each op's class to re-emit as a `!class:` marker — these join the existing `TAIDAL_ACCEPTS`/`TAIDAL_PRODUCES`; preserve them on any new node builder. **Scope (v1):** linear chains + **fan-out** (one op output → ≥2 op nodes) → `dataflux.ops.tee.Tee` (each branch a nested op-list — `Tee.branches` is recursive) + **multiple disconnected chains** → one complete, individually-loadable `{ops: [...]}` document per chain (`compile_op_chains` / `export_ops_yamls`, deterministic head-node-id order; the strict single-chain `compile_ops` / `export_ops_yaml` remain and still raise on a multi-chain graph). It does NOT auto-insert `Copy`/`Stash` for branch isolation — the user wires those op nodes explicitly. Fan-in (multi-input merge), cycles, an unresolvable op, and a widget input driven by a link all raise `UnsupportedTopologyError` (HTTP 400 from the route). **Consumer caveat:** `confluid.load` leaves `!class:` markers nested under a mapping key deferred, and `Flux` rejects deferred markers at iteration by design — so the op-list MUST be run through `confluid.materialize` (which `Flux.from_ops_yaml` does) before attaching; a bare `load(...)["ops"]` is not enough.
- **Whole-Graph YAML ↔ workflow.json Is a Faithful Translator Too (`fluxstudio/graphio.py`):** `graphio` is the WHOLE-config sibling of `export.py` (a SEPARATE compiler for a different artifact — the full UI `workflow.json`, not the ops-only op-list; both are shared by their own route+CLI, neither forks the other). `yaml_to_workflow` / `workflow_to_yaml` convert a Confluid YAML (sources / ops / object members / the runnable + wiring) ↔ a ComfyUI workflow. The **Fluid graph is the shared IR**: confluid owns YAML↔Fluid (`resolve`/`dump`/`load`), graphio owns Fluid↔`workflow.json` — it works WITHOUT a running ComfyUI (reads only `NODE_CLASS_MAPPINGS`). **Import** broadcast-resolves with `confluid.resolve` (un-instantiated markers — uniform `Class`/`Instance`/`Lazy` with `.target`+`.kwargs`, `!ref:` shared by identity ⇒ fan-out = one node + many out-links); `instantiate=True` walks live-but-inert objects from `confluid.load(..., solidify=False)` instead (same `_target_and_kwargs` abstraction; `solidify=False` suppresses the expensive finalize like a model backbone). It reuses the bridge primitives verbatim (`TAIDAL_CALLABLE_PATH`→`resolve_callable` reverse index, `_coerce_kwargs`, `_SOCKET_TYPES`, `_collect_ops`/`_collect_sources`, `_OP_LIST_PARAMS`/`_SOURCE_LIST_PARAMS`) — preserve those stamps on any new node builder. The reverse index (`_node_index` / `_node_key_for_class`) and `_target_and_kwargs` key by **any callable**, not only classes (`if callable(target)`, return type `Callable[..., Any]`), so a graph node whose target is a registered builder FUNCTION (`raidar.configurables`'s `fasterrcnn_*`) round-trips like a class — `_coerce_kwargs` / `getattr(cls, "__confluid_lazy__", …)` / `cls.__module__`+`__qualname__` are all function-safe. **The importer/exporter respect how the NODE handles lists:** a config member whose node declares a `<name>_0` seed socket (the bridge's `_admits_object_list` object-list family — `logger` / `callbacks`) is wired into `<name>_0`, `<name>_1`, … on **import** (the same dynamic-socket treatment as `op_N`/`source_N`, keyed off the node's actual `socket_names`, NOT a single by-name socket), and `_strip_index` collapses `<name>_<digit>` back into one `<name>:` list member on **export** (`op_N`→`ops` / `source_N`→`fluxes` keep their special prefix→param mapping; a generic `<name>_<digit>` strips the trailing index). Pins: `tests/test_graphio.py::test_strip_index_maps_list_sockets_to_param` / `::test_object_list_member_round_trips_as_logger_n`. **Export** is the hoisted-`!ref:` shape (matches navigaitor / the hand-written reference configs): every node → a top-level key named by the socket it feeds (path-prefixed on collision; a runnable root by its `__confluid_role__` — `trainer`/`evaluator`), a wire → a `confluid.Reference` (`!ref:`), shared scalar dims (`num_classes`/`image_size`) hoisted; ONLY non-default widget values are kept (import fills every widget position; a default-valued one wasn't explicitly set — this also discards bridge-unrepresentable params like tuple defaults). The **wired output slot is authoritative** for an object node's eager/lazy-ness: consumed via `lazy` (slot 1) → `!lazy:`, via `instance` (slot 0) → `!class:` — so a `!lazy:` model wires off the object node's lazy output and round-trips. A `collate_fn`-style callable param round-trips as `!ref:dotted.path` (`_REF_FIELDS`). Round-trip is **semantic** (topology+kwargs+kinds), not byte-exact — positions are re-derived by a deterministic layered layout. The FOUR canvas commands live under the **Taidal** menu (`web/import_yaml.js` "Import Taidal YAML → Graph/Subgraph/Group", `web/export_workflow.js` "Export Graph → Taidal YAML") + routes `/taidal/import_yaml` · `/taidal/export_workflow` + CLI `fluxstudio import` / `export-workflow` — all share the graphio functions, never fork. **Subgraphs/groups:** `as_="group"` wraps nodes in one `groups[]` box (presentation-only, dropped on export); `as_="subgraph"` packages them as a `definitions.subgraphs[]` blueprint — boundary inference per the approved convention (an unresolved `!ref:NAME` → an INPUT socket named `NAME` wired from `inputNode` id `-10`; a pipeline root → an OUTPUT socket to `outputNode` id `-20`); export inlines a saved subgraph back into the flat YAML (standalone `include:` files are a follow-up). **The export-side inliner (`_inline_subgraphs` → per-level `_inline_subgraphs_once`) handles REAL ComfyUI saves**, not just graphio's own output: a definition's inner links are normalized via `_link_six` (current ComfyUI writes them as DICTS `{id, origin_id, …}` — positional `link[1]` indexing was the `KeyError: 1` that aborted every subgraph-bearing export as "Export failed: 1"); boundary wires are RE-STITCHED (outer link into instance input k → the inner node(s) the definition's `-10` slot k feeds, fan-out included; outer link from instance output k → the inner producer feeding `-20` slot k — also into widget-backed inner inputs, e.g. a PrimitiveNode driving `spectrogram_type`); the links array is REBUILT with fresh sequential ids and every node's `inputs[].link`/`outputs[].links` refs rewritten (inner ids are only unique per definition — verbatim copies collide across two instances of the same subgraph AND with top-level ids, cross-talking `_normalize_ui_workflow`'s id-keyed `link_src`); nesting flattens by repeating the single-level pass (depth cap 16 + warning for a self-referential definition). Pins: `tests/test_graphio.py::test_inline_subgraphs_*` / `::test_export_inlines_subgraph_instances_end_to_end`. **Export skips non-Taidal nodes (never fails on them):** a node with no Confluid form — native ComfyUI nodes (viewers/primitives, `class_type` not in `NODE_CLASS_MAPPINGS`), the canvas-only adapters (Walk/Extract/Retag/Compose/Mix/YamlDump/Math — no `TAIDAL_CALLABLE_PATH`), or a Taidal node whose `_build_fluid` RAISES (isolated per node, logged at `warning`) — is SKIPPED and listed with its reason in a leading `#` comment block (`_skipped_comment_block`; empty when nothing skipped, so all-Taidal exports stay byte-identical); a wire from a skipped node into an exported config member is dropped-with-comment (the member keeps its default), and the op-chaining `sample` socket is treated as DATA-FLOW, not config — it never becomes a kwarg (`sample: !ref:…` would crash the reloaded ctor) and never names a node (`_assign_ref_names` skips it; sample-chained ops export as standalone `_snake`-named entries — the chain itself is the ops-export artifact). Ref NAMES come only from EXPORTED config consumers: `_assign_ref_names` ignores wires whose consumer is itself skipped (a YamlDump `object`, a PreviewAny `source`, a Math `a` are UI plumbing and produced junk keys like `object:`/`source_2:`); a node no exported consumer feeds falls back to its `_snake` class name. **v1 limits (documented in README, not silent):** a config member with NO FluxStudio node (e.g. torchmetrics `MetricCollection`) is dropped-with-warning on import (the runnable keeps its default — surface it by tagging/registering upstream, as the loggers + base `LightningTrainer`/`LightningEvaluator` are in `marainer.configurables`); a `List`-valued member on a node WITHOUT a `<name>_0` seed (a runnable's own single `logger` slot) still wires only its first element (the single-socket list-gap) — but object **nodes** that declare the `<name>_N` family (a `pytorch_lightning.Trainer`'s `logger`/`callbacks`) now round-trip the FULL list (see the importer/exporter note above).
